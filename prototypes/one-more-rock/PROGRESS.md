# One More Rock 開發進度

## 2026-11-28｜master｜首批可玩原型

這份紀錄對應採石、搬運與工坊的首批實作。遊戲來源是同一筆提交中的 `prototypes/one-more-rock/`，提交識別碼以 `git log -1 -- prototypes/one-more-rock` 查閱。主入口是採石場，工作台可獨立試玩 V0.1。 [執行方式](README.md#執行與匯出) · [實作方案與里程碑](../../docs/incremental/One-more-rock/IMPLEMENTATION.md#六個里程碑與工期)

### 已完成

- **V0.1 工作台**有五擊開石、逐步裂紋、槌面接觸與碎屑、普通敲擊加品相、金色時窗與亮面驚喜。敲開後可點一下收走，持續按住會多等一拍再補石，結算時有金幣音效與滾動金額。首次礦物或成就會出現通知，已收錄的礦物可在工坊展示架查看。
- **V0.2 採石場**支援第一人稱走跑跳、桌機滑鼠與手機橫向雙指。十字鎬可揮空及長按連挖，命中點決定石屑位置和局部 Voronoi 裂面。岩層失去支撐會先鬆動再落地碎裂；挖口會移除舊岩皮並更新碰撞。普通揮鎬和電鑽基礎掉落 1 顆，礦震基礎掉落 2 顆、冷卻 8 秒。
- **第二階段採礦**會在新挖口露出方解石或紫水晶。只有直接命中礦片才會疊播 `impactMining` 和 `crystal hit`。採下的原石需手動拾取，加工時保留對應礦物與硬度。普通採石、工作台和砂礫腳步各有獨立音效。
- **搬運循環**有背包、手推車、容量升級、普通原石靠近拾取、拾取先浮起再落入容器。木屋旁的料斗可自動卸貨與部分入庫，石堆使用剛體、中層表現與遠層模型。走進木屋切進工作台加工，清空料斗有提示。
- **V0.3 自動化切片**已有八路天賦樹、分級槌、鋼鎬、可持續鑽掘的電鑽，以及出礦、拾取和體能升級。拾運機器人搬普通原石，固定式破石機可獨立開關、分三級加工。滿倉和在途保留位有回歸覆蓋。
- **開發與素材**已有可編輯的 Godot 場景、Polyfork 道具、Kenney Adventure 工坊 UI，以及共用的 `godot-dev-panel`。在編輯器試玩時按 F1 可調參數、試音與做石堆壓測，正式 Web 匯出排除開發面板。 [共用開發面板](../godot-dev-panel/README.md) · [採礦手感研究](../../docs/incremental/One-more-rock/DRG-MINING-RESEARCH.md)

### 接下來

| 優先 | 待做 | 驗收重點 |
|---|---|---|
| M1–M2 | 真人與手機橫向試玩 | 鎬尖位置和揮擊重量、露出礦片是否看得懂、地形是否仍有擋住準星的薄面、原石落地與拾取、採一袋送回工坊的往返耗時。覆蓋低處、斜面、連挖與礦震，量手機上音量和場景幀時間。 |
| M3 | 經濟與存檔 | 定價、預選掉落、保底、留樣與出售選擇。保存岩體進度、原石的來源與已知礦物、庫存、升級和圖鑑。重開或讀檔驗證原石結果與收入守恆。 |
| M4 | 大量自動化與產線 | 接中央固定步長結算、採集機、運輸與分類販售。做滿倉阻塞、吞吐、清空回饋和放大處理單位的壓測。 |
| M5–M6 | 新區域、收藏與離線結算 | 做紫晶洞窟、完整收藏與換區，驗證舊區產線及離線重返。最後在原生與網頁真機各跑完整循環。 |

使用者尚未另行延期功能。本批先把首個採石場與工坊切片交付，完整販售、存檔、離線收益與第二張地圖仍在規格的後續里程碑。

### 驗證與交接

- **L2 功能回歸，沿用 2026-11-28 實作驗證**。Godot 4.7 從原型目錄執行 `godot --headless --script tests/<名稱>.gd`，下列六項皆通過。

  | 腳本 | 已驗證 |
  |---|---|
  | `bench_loop` | 快速連敲、品相、收料、入帳與圖鑑 |
  | `excavation_loop` | 多條射線能穿過挖口、挖空後舊殼與碰撞同步移除、支撐與坍落 |
  | `mineral_loop` | 方解石及紫水晶露出、礦片專屬命中聲、方解石從拾取到工坊 |
  | `dev_tools_and_mining` | F1、揮擊過程轉向、鎬尖命中、普通外岩的音效 |
  | `mining_tools_loop` | 礦震冷卻和出礦量、電鑽持續切削及放開停止 |
  | `quarry_loop` | 走跑跳、觸控、拾取、搬運、天賦路線、破石與清空石堆 |

- **場景與 Web，沿用同一輪證據**。Godot headless 匯入與 `--export-release Web build/web/index.html` 成功。本機靜態伺服器對最終 `index.pck` 回傳 HTTP 200，大小 4,293,644 bytes。另以 Godot 渲染確認礦片嵌在挖口內。手機原生及 Safari／Chrome 真機的聲音、觸感和長時間效能仍待量測。
- **提交前新驗證**。用 `git checkout-index` 匯出暫存區的原型，再執行 `godot --headless --editor --import`。首次啟動先記錄主題字型尚未匯入，匯入完成後 `tests/mineral_loop.gd`、`tests/bench_loop.gd` 都通過。共用面板的 `bash prototypes/godot-dev-panel/sync.sh --check one-more-rock` 通過。
- **關鍵檔案**。岩體、礦片與拾取在 [rock_volume.gd](rock_volume.gd)、[rock_skin.gd](rock_skin.gd)、[embedded_mineral.tscn](scenes/embedded_mineral.tscn)、[quarry.gd](quarry.gd)。倉庫、加工與設備在 [quarry_inventory.gd](quarry_inventory.gd)、[workbench.gd](workbench.gd)、[quarry_automation.gd](quarry_automation.gd)。
- **工作區**。`build/` 與 `.godot/` 屬本機產物。提交範圍是 One More Rock、增量規格、共用開發面板原始碼及本專案紀錄。

### 專案調校心得

- 同一擊可移除多格岩材，玩家真正帶走的顆數獨立決定。維持普通採掘 1 顆、礦震 2 顆、坍落批次上限，避免地面和背包堵塞。大量待處理的視覺量留給料斗及後續自動化。
- 礦片要從原挖掘視角可見，且貼住保留的岩材。震動、成品音與礦片命中聲各有時機，普通岩壁和工坊各用自己的音色，水晶提示留給玩家直接命中的礦片。
- 手動拾取、輸送與加工要保留同一份原石識別及已知礦物。方解石需要鍛鋼槌，紫水晶需要鑽尖槌。自動破石依對應硬度判斷及依原礦基價結算。
- 開發版調參、匯出與真機試玩分開驗收。可重用的地形、音訊與測試經驗集中在 [原型 LESSONS](../LESSONS.md)。
