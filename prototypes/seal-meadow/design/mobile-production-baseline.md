# 蓬蓬草原：手機製作基準

日期：2026-10-26。適用範圍：`prototypes/seal-meadow` 後續規劃、素材規格、實作與驗收。

## 已確認的使用者要求

- 製作時以**手機執行**為前提，同時考慮觸控、小螢幕、效能、記憶體與長時間遊玩。
- **固定鏡頭方向與俯角**，不製作可旋轉鏡頭。鏡頭可跟隨角色平移；固定方向不等於鏡頭停在世界中的同一位置。
- **不製作短連招**。本製作基準也不安排 A/S/D 鍵序、雙鍵、節奏窗或長連招系統；普攻可輪播揮擊動畫，玩家不需追加節奏輸入。
- 希望 Online 的詳細分析保留為參考，參考遊戲的功能不自動成為本遊戲需求。

這些是使用者確認的範圍。以下操作、方向與預算為製作提案，後續可依真機結果調整。此文件記錄目標，並不表示目前程式已完成手機適配。

完整研究：[希望 Online 客戶端證據與 Godot 拆解](../../../docs/research/seal-online-deep-dive-2026-10-26/README.md)。原作封裝、shader 與音訊統計保留在研究目錄，無需為本次方向變更重新產生。

## 要保留的遊戲體驗

Q 版角色、手繪感草原與城鎮、搞笑且容易辨識的怪物、點怪練功、清楚的命中回饋、升級換裝、寵物養成與回城整理。任務、精煉、交易與多人社交依階段規劃，不因手機方向而刪除，也不代表第一版必須全數完成。

```text
點地移動／點怪 → 自動追到射程 → 自動普攻／點技能
                                      ↓
                         掉落、經驗、任務進度
                                      ↓
                       換裝／餵寵物／回城整理
```

戰鬥參與感來自目標選擇、技能時機、距離與走位。攻擊動畫、火花、跳字與聲音要對齊接觸點；不以快速連按增加操作負擔。

## 鏡頭與場景

- yaw、pitch 與基準距離／FOV 存在 scene 或 export 欄位，由作者調整；執行時不將單指、雙指或滑鼠右鍵接到旋轉。
- 首輪採固定基準縮放，不要求捏合縮放。必要的長寬比／安全區構圖調整屬整體適配，不能覆蓋作者設定的 UI 位置與間距。
- 角色置於可看清行進前方的構圖位置，跟隨平移平滑但不拖到操作困難；傳送或重生時直接重設跟隨狀態。
- 道路、入口、NPC、寶箱與怪物不可必須轉鏡頭才找得到。以固定視角檢查樹冠、建築、坡度與前後遮擋；可用前景淡化或局部剪影維持玩家可見。
- 小地圖固定北向；縮小版顯示玩家、任務與關鍵入口，詳細地圖另開面板。
- 地圖可用完整 3D；角色先沿用現有 2.5D 管線。固定相機後，角色仍會朝不同方向移動與攻擊，不能把所有動作縮成單一方向。

## 角色與素材製作

- 首輪使用現有 8 方向玩家與分層裝備規格；怪物方向數沿用既有規格。固定鏡頭不自動授權重做所有 atlas 或刪除方向。
- 先做一套角色、武器與頭髮的待機／走路／攻擊／受擊／死亡，驗證腳底錨點、描邊、比例與層級遮擋，再擴充裝備。
- 地圖角色尺寸、貼圖壓縮、mipmaps 與 atlas 留白以真機畫面判斷；減少空白像素、同時載入的裝備與透明 overdraw。
- 模型渲染 sprite 仍可使用 Blender 作製作工具；Godot 執行時使用已保存的資源。需要完整 3D 角色時，以大量換裝維護成本、動畫需求與記憶體實測作決策。
- AI 素材生成仍遵守專案規則：先描述批次，待使用者選直接生成或 opt image 提示詞。本次不生成素材。

## 觸控操作提案

| 動作 | 首輪設計 | 邊界處理 |
|---|---|---|
| 移動 | 點地面設定目的地 | 可達性檢查；UI 點擊不穿透 |
| 攻擊 | 點怪選取，追到射程後自動普攻 | 名牌／選取圈確認目標；怪物死亡即解除 |
| 停止追擊 | 點地移動或使用明確取消操作 | 新移動指令優先；不瞬間又拉回原目標 |
| 技能 | 右下少量大按鈕，首輪以 2～3 個測試 | 顯示冷卻、AP、射程與不可用原因 |
| 密集目標 | 放大可點範圍，搭配最近可見目標規則 | 不誤選被 UI 蓋住或隔牆的怪；必要時補切目標按鈕 |
| 撿取 | 有效距離內點物品，另測一鍵附近拾取 | 不假設自動全撿已定案；驗證滿包、權限與重複請求 |
| 背包／裝備 | 面板內點選物品顯示詳情，再按裝備／使用 | 拖曳不是唯一入口；操作結果清楚可見 |
| 寵物餵食／精煉 | 選物品與材料後顯示結果預覽再執行 | 保留數量、成本與消耗確認，避免誤觸 |
| 聊天 | 收合訊息區；點開輸入 | 軟鍵盤彈出時保留輸入框與送出；不觸發角色操作 |

實作使用 touch index 區分每根手指；滑動、點按與長按若同時存在，需明確分辨。首輪不強制虛擬搖桿；若點地在真機難用，再評估 kit 的 `floating_stick.gd`。桌面滑鼠／鍵盤可作測試入口，主要功能必須能純觸控完成。

## 手機 UI 與可讀性

- **暫以橫向布局驗證**，這是提案，使用者尚未指定橫向／直向。未確認前不大量製作只適用某一方向的素材與畫面。
- HUD 保留生命／AP、目標、少量技能與功能入口；聊天、完整任務、寵物詳細數值、背包與裝備用可收合面板。
- 優先讓拇指操作區清楚，避開瀏海、挖孔、圓角與系統手勢區；safe area 必須在實機取得並驗證。
- 按鈕用實際手機上的可點尺寸與誤觸率驗收，不把桌面像素當作 dp／pt。小字與次要裝飾可減，生命、技能冷卻與道具數量需保留對比。
- 名牌、飄字與特效設定同屏上限；重要目標優先，普通怪可依距離減量。狀態不能只靠顏色或聲音辨識。
- 所有主要 UI 與重複物件使用保存的 `.tscn`，anchors、Containers、Theme 與樣式資源可在編輯器調整；不在每幀重寫 UI 位置與大小。

## 效能、記憶體與平台

手機執行是已確認要求；**原生 Android／iOS 或手機瀏覽器尚未指定**，本文件不擅自選定發佈平台。先以現有 Godot 4.7 Compatibility 原型驗證，平台確定後再決定 renderer 與匯出設定。

| 項目 | 首輪目標／策略 | 如何記錄 |
|---|---|---|
| 更新率 | 低階目標機先求穩定 30 FPS；較好裝置再評估 60 FPS | 機型、OS、解析度、renderer；frame time P50/P95/P99 |
| 熱與電量 | 連續遊玩 20～30 分鐘觀察降頻、卡頓與耗電 | 前後 FPS／frame time、溫度資訊可取得時記錄 |
| 記憶體 | 先量常駐、切圖尖峰、裝備預覽與重開窗口 | RAM／GPU 可取得的資訊、載入前後與回收狀態 |
| 繪製 | 分區 MultiMesh、限制透明粒子與名牌；先簡化 shader | draw calls、透明覆蓋、GPU／CPU 瓶頸 |
| 內容載入 | 區域與角色外觀按需載入，避免所有 atlas 常駐 | 冷啟動、首次顯示、切圖時間與尖峰 |
| 背景切換 | 切到背景時停掉單機非必要更新／聲音 | 返回後輸入、動畫、存檔、音訊狀態 |
| 多人斷線 | 以服務端時間處理戰鬥與結算，前景恢復後同步 | 重連與重送不複製道具、獎勵或精煉 |

以上是待驗證目標，沒有指定目標機型前不宣稱已達標。30 FPS 約 33.3 ms／幀，60 FPS 約 16.7 ms／幀；需要留出系統與尖峰餘裕。桌面 headless 測試無法取代手機 GPU、觸控與熱降頻驗證。

Compatibility 的刀光用預製弧形 mesh／flipbook／自建 ribbon 等適用方案；不能把僅 Forward+／Mobile 支援的內建 particle trails 視為已有能力。未指定原生／Web 前，網路層先保留平台邊界，不能預設瀏覽器可直連 ENet UDP。

## 開發順序與驗收

```text
固定鏡頭／手機構圖＋觸控輸入
              ↓
點怪追打＋自動普攻＋少量技能＋命中回饋
              ↓
背包／換裝／任務／掉落＋一段完整練功循環
              ↓
寵物／精煉／存檔＋真機持續遊玩
              ↓
依需求加入多人、交易、更多內容與營運功能
```

1. 全程觸控完成移動、選怪、攻擊、技能、撿物、換裝與關窗，不依賴鍵盤、滑鼠右鍵或鏡頭旋轉。
2. 攻擊與命中可讀；不出現連招輸入要求或連招條。技能按鈕不因移動手指而誤觸，關窗不觸發地面行走。
3. 固定視角下每條必要路線與互動物可辨識；樹、牆與地形不長時間遮住玩家。
4. 驗證兩種不同長寬比與有安全區的裝置；軟鍵盤、背景切換與恢復正常。
5. 目標機持續遊玩 20～30 分鐘，記錄 frame time、記憶體、載入尖峰與降頻情況；未有真機證據即標未驗證。
6. 在編輯器修改 UI 靜態文字／間距後執行仍保留；來源 scene 不被角色執行狀態污染。

## 目前程式與整合提醒

這次只更新規劃文件。現有 `scripts/camera_rig.gd` 的右鍵旋轉、滾輪縮放與 README 桌面操作是**目前原型實況**，後續實作需改為本基準；不得只改操作說明就宣稱旋轉功能已移除。

kit 的 `combo_input.gd` 保留給其他原型，本遊戲不接入；`pet_care.gd`、`refine_ladder.gd` 可依手機面板與數值規則另行整合。先查 `godot-kit/README.md`，需要時只同步指定專案，不直接改副本。

待決定但不阻擋文件記錄：橫向／直向、原生／Web、最低目標手機、技能具體組合、長期 3D／2.5D 換裝策略。這些不改變已確認的固定鏡頭與不做連招範圍。
