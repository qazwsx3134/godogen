# 手機版製作 Roadmap

2026-10-26；狀態：**規劃草案**。依據：[手機基準](../design/mobile-production-baseline.md)、[game brief](../design/game-brief.md)、[40 系統索引](../design/gdd/systems-index.md)。本次只交付文件；所有里程碑均未以本文件宣稱完成。

採「可驗收成果＋相依順序」，不給未經容量與團隊校準的日期。系統首版與後續擴充分開：S12 在 M0 有最小交易原語，並不代表 M0 完整背包、商店與多人經濟都完成。

## 路線總覽

```text
M0 手機／資料／scene 基礎
         ↓
M1 手機可打怪原型
         ↓
M2 城鎮與完整成長循環 ─→ 多人技術風險試驗（不算 MMO 完成）
         ↓
M3 寵物／精煉完整切片＋真機長測
         ↓
M4 權威多人／社交／交易（啟用多人時）
         ↓
M5 內容與條件分支（公會、副本、休閒、PvP、活動、商城）
         ↓
M6 依實際發佈範圍硬化與交付
```

MVP 首版責任 20 系統（M0 先做其中 6 個的薄切片，其餘在 M1 補），完整切片新增 7 系統（M2 5＋M3 2），多人新增 3 系統，後期條件新增 10 系統。數量是責任邊界，不是相同工作量。S20 UI、S22 美術、S25 保存、S27 測試與 S40 數值工具每階段持續擴充。

單機產品若成立，可由 M3 進 M6；若採多人則先走 M4。M5 不要求十個分支全做完才能發佈，必須先明列本次要包含哪些分支。

## M0：現有原型上手機 Web

**目標**：把已能玩的原型（`scripts/player.gd` 近戰自動普攻、怪物、HUD）原樣搬到使用者手機的瀏覽器，純觸控能打怪，並量到第一組真機數字。不先建新框架；只做讓手機可玩與可量測所需的最小改動。

決策依據：D01 橫向、D02 手機 Web（itch.io）、D03 使用者手機為代表機、D07 近戰＋範圍揮砍（技能本身在 M1）。

首版系統（薄切片）：S03 觸控、S04 固定鏡頭、S02 最小結算入口、S25 最小保存、S20 HUD 觸控按鈕、S27 Web 匯出與量測。S01、S05、S12、S22、S40 延到 M1 依需要補。

| 工作包 | 交付 | 約束 | 驗收證據 |
|---|---|---|---|
| M0-01 Web 匯出 | `export_presets.cfg` Web preset、匯出腳本、pck 按副檔名的大小表 | 照 `godot-prototype-to-itch` skill；先量再縮 | headless Chromium 開得起來、無 console error；大小表 |
| M0-02 觸控操作 | 點地移動、點怪鎖定追打、HUD 按鈕不穿透到地面 | 保留桌面 WASD／滑鼠；不加搖桿 | playwright 觸控事件測試；AC-S04-01 拖曳／雙指不轉鏡頭 |
| M0-03 最小結算入口 | 傷害與經驗只經一個入口；可注入時鐘與 seed；背景時暫停 | 不做冪等快取或網路 adapter（D08 前） | AC-S02-01、AC-S02-02、AC-S02-03 的 headless 測試 |
| M0-04 最小保存 | 等級、經驗、位置存 `user://`（瀏覽器 IndexedDB），回城／升級時存 | 版本欄位＋寫暫存檔再改名；不做完整背包 | 重新整理頁面後狀態還在；寫一半中斷不損壞 |
| M0-05 真機量測 | 代表機上的載入時間、平均／1% low FPS、10 分鐘後 FPS、下載大小 | 低階機以 Chromium CPU 節流模擬並標示 | `production/qa/m0-baseline.md` 記機型、瀏覽器、數字 |

**進度（2026-10-27）**：M0-01～M0-04 完成並有測試（`tests/test_m0.gd`、kit `tests/test_m0_modules.gd`）；M0-05 只有模擬器數字，見 `production/qa/m0-baseline.md`。使用者決定（2026-10-27）：開發期以電腦版 Godot 能開能玩為準，iPhone 17 真機測試等一個階段完成後再一起做。M0-03 的「傷害與經驗只經一個入口」與固定 seed 移到 M1 S08 一起做。

**出口**：使用者用自己手機打開 itch.io 草稿頁（或本機 LAN），只用觸控能走、打怪、升級；重新整理後等級保留；有一份真機基準。沒真機數字時 M0 標「桌面完成、手機未驗證」。

## M1：手機核心戰鬥原型

**目標**：驗證「選怪→追打→技能→死亡／掉落→經驗→保存」在手機上是否順手。

新增首版：S06 移動／選取、S07 生存、S08 普攻、S09 技能、S10 怪物、S11 掉落、S14 最小成長、S23 回饋、S24 音訊。擴充 S12 背包、S20 HUD、S25 保存與 S27 smoke。

| 工作包 | 交付 | 順序 | 驗收證據 |
|---|---|---|---|
| M1-01 追擊與取消 | Idle/Move/Chase/Attack 轉接、目標 id | 先移動／目標，再接攻擊 | 射程邊緣不抖、移動可中斷、目標卸載安全 |
| M1-02 戰鬥權威 | HP、普攻接觸、死亡／重生、拒絕碼 | 先生命與一次結算，再碰動畫 | 低 FPS／重複事件／死亡取消測試 |
| M1-03 一種怪 | 被動反擊、回家、重生、出生點 | AI 發命令，不直接發獎 | 拉怪／不可達／重生新 id |
| M1-04 一個技能 | AP、CD、施法／取消、觸控按鈕 | 確認 D07；不加連招條 | 超距／AP 不足／快點不雙扣 |
| M1-05 獎勵薄切片 | 一掉表、地上物、最小背包、EXP／升級 | 必須用 S12 交易原語 | 滿包不吞物、唯一拾取、跨級／保存 |
| M1-06 聲畫整合 | 普攻、命中、暴擊、死亡、升級事件 | 先固定時序，再調力度 | 命中／跳字／聲音同步；靜音仍可讀 |

**內容上限提案**：1 角色、1 怪、1 地圖、1 主動技能、少量可堆疊掉落與一個裝備樣本。先不做全職業、裝備海或完整首領。

**所需文件**：戰鬥時序、傷害公式與算例、AI FSM、技能卡、掉表、拾取規則、成長曲線初稿、回饋事件表、最小 HUD UX、10 分鐘循環測試腳本。

**進度（2026-10-27）**：第一批完成——`scripts/combat.gd` 單一結算入口（固定 seed 可重播、死目標不再受擊、擊殺經驗只發一次）、範圍揮砍（AP／冷卻／前搖移動取消、拒絕原因）、HUD AP 條與技能鈕；測試 `tests/test_m1.gd`。第二批完成——掉落表與地上物（`scripts/items.gd`、`scenes/loot_drop.tscn`）、12 格背包全有或全無（`scripts/inventory.gd`）、點選撿取不重複、存檔 v2 遷移、怪物重生換 `spawn_id`、音效（`scripts/sfx.gd`，合成佔位音）、揮砍光圈與暴擊停頓；測試 `tests/test_m1_loot.gd`。之後加入社群仇恨（`pack_radius`）、果凍 5／5／4 三群與 5 秒重生、經驗曲線 `100 × L^1.8`。核心指標改成清群時間：揮砍清 5 隻快 1.53 倍（目標 1.40）；詳見 `design/core-loop.md`。

**出口**：玩家不用鍵盤、旋轉與連招能完成多次擊殺並升級；追擊／技能／關窗不互相誤觸；一次攻擊／拾取不重複結算；退出／重開回到可理解狀態。有手機 frame time 與短試玩記錄後才進一步擴內容。

## M2：回城、換裝與任務完整循環

**目標**：驗證「出城練功→拿裝備→回城賣雜物／補給→接交任務→再出城」的方向感與動機。

新增首版：S13 裝備／紙娃娃、S15 任務／對話、S16 商店／銀行、S21 地圖／跨區、S26 教學／文字。擴充一職業曲線、2～3 技能與 3 種怪。

| 工作包 | 交付 | 前置 | 驗收證據 |
|---|---|---|---|
| M2-01 換裝管線 | 2 武器、1 服裝、比較與裝備操作 | S12＋S07＋S22 | 全方向動作、屬性不重加、滿包互換、atlas 記憶體 |
| M2-02 小城鎮與跨區 | NPC、商店、銀行、入口、小地圖 | S05＋S21＋S25 | 固定視角可達、切區清理、載入失敗恢復 |
| M2-03 任務與教學 | 3 個任務串接選怪／換裝／回城 | S12＋S14＋S15 | 不可重領、滿包提交、可跳教學、軟鍵盤不擋返回 |
| M2-04 成長與經濟 | 一職業曲線、售價／補給、掉落用途 | 各來源都能查表 | TTK／回城頻率／金幣收支／裝備提升試算 |
| M2-05 內容檢查 | ID 引用、任務可達、字形與資產來源 | S01＋S22＋S26＋S40 | 不靠手工逐頁找漏字／漏圖 |
| M2-06 多人技術試驗 | mock／測試服務端雙 client 移動＋一次攻擊／拾取 | M0 權威邊界；平台／網路方向可用時 | 命令／結果 trace、延遲／重送、可複用／需重設介面報告 |

多人試驗只驗風險，不包含帳號營運、完整 AOI、交易、公會或任何同屏容量承諾。若多人產品方向未定，試驗可限縮為 transport／authority adapter 可替換測試，保留未驗證的網路部分。

**所需文件**：裝備欄／限制、紙娃娃遮擋矩陣、城鎮 layout、NPC 服務、3 任務卡／對話、商店價格、銀行容量、跨區／小地圖投影、首次遊玩 journey、雙 client 試驗 ADR 草案。

**進度（2026-10-27）**：M2-01～M2-05 完成，M2-06 多人試驗依 D08 延後。
- M2-01 換裝：鐵劍、布衣用 Blender 程序化建模（`tools/blender/make_test_chibi.py`）渲染成紙娃娃圖層，穿上後外觀即時改變；兩個裝備欄、屬性不重複疊加、滿包不能卸下。
- M2-02 村莊與跨區：`scenes/town.tscn`（村長、廣場、傳送回草原），草原 `ToTown` 傳送圈；淡出切換、存檔記住所在區域；左側圓形小地圖。ponytail：兩區放在同一個 scene 相距 300 m，傳送即移動；地圖變大再改成串流載入。
- M2-03 任務與教學：3 段任務串、5 步新手提示（依實際操作前進、可跳過、存檔）。
- M2-04 經濟：商店、一鍵賣材料、蘋果補血；收支初測見 `design/core-loop.md`（目前偏寬鬆，等 M3 消耗再調）。
- M2-05 內容檢查：`tests/test_content.gd` 檢查 ID 引用、任務可完成、裝備圖存在、字型缺字（已抓到並修正「獠」字缺字）。
- 兩裝備呈現成本：每個圖層一張 3840×1920 atlas，未壓縮 28 MB（與身體同大，劍只佔很少像素）。量產 2.5D 換裝前要裁切每層的空白或降 `cell_px`，記在 D05。
- 測試：`test_m0`／`test_m1`／`test_m1_loot`／`test_m2`／`test_content` 全過；godot-kit `test_kit` 現在遇到 SCRIPT ERROR 會判定失敗。

**出口**：一名新玩家可在觸控裝置理解並完成上述循環；拿到的裝備能換上、存讀後仍保留；任務與商店不產生資產複製；城鎮／草原不卡死。完成兩裝備呈現成本比較，再決定是否量產 2.5D 換裝。

## M3：寵物、精煉與可持續遊玩的切片

**目標**：形成一段可以反覆遊玩、保存且在手機長時間運作的完整內容。

新增首版：S17 寵物照護／進化、S18 精煉／製作。前置要完成 D09/D10，不能默認採用原作寵物死亡或精煉裝備消失。

| 工作包 | 交付 | 驗收重點 |
|---|---|---|
| M3-01 寵物一分支 | 一寵、餵食、一進化配方、外觀與加成 | 食物只扣一次、城鎮／背景／卸裝政策、進化存讀 |
| M3-02 一精煉階梯 | 材料／成功率／失敗結果表與確認 UI | 同 request 不重抽、失敗全量一致、結果保存 |
| M3-03 養成經濟 | 掉落→賣物／餵寵／精煉的資源分流 | 資源來源／消耗對帳、期望成本與可預期進度 |
| M3-04 手機完整 UI | 餵食、精煉、設定、教學提示與安全區 | 誤觸、字級、兩 aspect、背景／軟鍵盤 |
| M3-05 硬化與長測 | 20～30 分鐘真機、強制終止／恢復、冷啟動 | frame time、記憶體、熱降頻、聲音與保存證據 |

**所需文件**：寵物照護規格、精煉失敗矩陣、經濟 workbook、保存 migration、效能報告、完整切片 QA 與 playtest 問題清單。

**出口**：戰鬥、任務、掉落、換裝、商店、寵物、精煉、保存可串完整循環；使用選定手機持續執行的數據支持當前內容量；重大誤觸、資料遺失與不可達問題有解決或明確限制。這才是完整切片，並非只因所有窗口存在就通過。

## M4：多人、社交與安全經濟（條件里程碑）

**啟動條件**：決定多人產品範圍、平台、伺服器與資料持久化方向；M2 試驗的介面問題已處理。未啟動多人時，後續線上功能保持條件規劃。

新增：S28 帳號／權威／AOI／重連、S29 隊伍／聊天／好友、S30 交易／擺攤。

順序：可信登入／角色與 DB → 權威地圖移動／戰鬥／拾取 → AOI／重連／跨圖 → 隊伍／聊天／分配 → 雙人原子交易 → 有限在線擺攤。

**所需文件**：後端架構 ADR、版本化協定、權威清單、DB schema／migration、重送／鎖／idempotency 策略、AOI／server tick／流量量測、社交權限矩陣、交易狀態機、恢復 runbook。

**出口**：至少兩 client 下同一物品只存在一份；重送、斷線、server 重啟不產生半邊交易；偽造傷害／價格／速度被拒絕；隊伍與聊天權限一致；記錄已壓測的人數、怪物、技能負載與硬體。沒有數據就不宣稱 MMO 容量。

## M5：後期內容與產品分支

以下是獨立範圍；先選要做的分支，再補 GDD／UX／TDD 與測試。首版切片不被這些功能阻塞。

| 分支／系統 | 最小交付 | 前置／啟動條件 | 再擴充前的證據 |
|---|---|---|---|
| S19 聲望／收藏 | 一聲望線與少量收藏 | 成長事件與獎勵契約 | 解鎖可查、獎勵去重、舊存檔政策 |
| S31 公會 | 建會、成員、公告 | M4 社交／權威 | 權限與職級改變生效；銀行另驗 |
| S32 情侶／表情 | 一表情、一雙人休息 | 角色動作與多人同意 | 取消／離線可恢復操作 |
| S33 釣魚 | 一釣點、一餌、一掉表 | 物品／時鐘／背景政策 | 餌與獎勵對帳、不用本機時間刷獎 |
| S34 戰鬥寵／守護者 | 一跟隨或乘坐 | 角色／技能／照護邊界 | 不重疊加成、切區清理；戰鬥 AI 另擴 |
| S35 時裝／光環 | 一外觀覆寫、一光環 | 紙娃娃／效能 | 預覽不改數值、低特效仍可讀 |
| S36 副本／首領 | 一短副本、一首領 | M4 隊伍／權威＋戰鬥 | 團滅重置、領獎去重、固定鏡頭預警 |
| S37 PvP／決鬥 | 一次 1v1 同意對戰 | M4＋獨立 PvP ruleset | 不誤套 PvE 懲罰、延遲下結算一致 |
| S38 每日／活動 | 一每日、一限時活動 | 服務端時間／獎勵去重 | reset 邊界、內容修訂、補領與對帳 |
| S39 商城／支付 | 先 mock／sandbox | 商業模式與發佈平台已定 | 收據去重、背景恢復、退款與權益一致 |

S40 在每個分支提供數值、事件與稽核支持；S27 每次擴內容都重新檢查代表性手機成本。真實付款與對外發佈是獨立動作，本 roadmap 不代表已授權執行。

## M6：發佈範圍硬化

先寫此次發佈清單：支援平台、語言、裝置、內容、是否多人、哪些 M5 分支、存檔／帳號相容性。依範圍完成以下工作：

- 資料／scene／腳本匯入與可重現匯出；純邏輯、整合、UI、真機與持續遊玩證據。
- 內容引用、缺字、任務可達、經濟異常、保存／重連、裝置限制與音訊背景行為。
- 素材來源／授權、外部套件版本與匯出限制；實際平台提交要求於提交前查核。
- 發佈說明、已知限制、升級／migration、回滾／恢復、客服與營運方式（如有後端／付費）。

**出口**：所有此版 AC 有證據；未支援項目明確標示；產出具版本與 hash 的 candidate package。真實上架、部署或收費按當時授權處理。

## 設計順序與實作順序的差別

平台／權威／物品／時間與保存要早定**契約**；不用等完整後端寫好才做手機原型。UI 與美術也從 M0 就有最小可驗版本，不拖到核心全寫完再處理。每階段先補對應規格與資料，再拆 story，避免以「功能很多」取代可玩證據。

下一步是實作 M0-01～M0-05：先讓現有原型在手機瀏覽器可觸控遊玩並量到基準，再擴 M1。注意現有 `scripts/camera_rig.gd` 仍有右鍵拖曳旋轉，M0-02 要移除。

## 估算與排期規則

系統包的 S/M/L/XL 是相對風險和介面複雜度；XL（多人、原子交易、副本、付款）不能直接乘同一人日。正式日期排程需先有：人數與每週工時、可用手機、美術來源、平台決策、M0/M1 實際完成速度，以及 M2 多人／換裝試驗結果。

每次 milestone review 更新「本階段已驗證、未驗證、剩餘決策、內容量、下一階段範圍」，只在工作量／團隊有變化時重估；不要以文檔產生數或原型部分程式當作完成百分比。
