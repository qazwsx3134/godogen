# 紙娃娃版素材遷移盤點

盤點日期：2026-09-09

本文件只盤點現有素材與紙娃娃設計需要的素材遷移，不改程式、不產圖、不刪檔。依 [PAPER-DOLL-SPEC.md](./PAPER-DOLL-SPEC.md) 已確認的方向，固定三名主角不再是最終的玩家外觀；玩家需要可自訂的主角基底、模組化髮型／衣物，並能把多件被動道具以獨立層展示在角色身上。

版面以 [BATTLE-LAYOUT.md](./BATTLE-LAYOUT.md) 的 Slay the Spire 2 參考與版面規格為準；本文件只提供素材接點。戰鬥顯示契約明列如下：玩家與每一名敵人的生命條、格擋值都要貼近各自角色；意圖與狀態也要在該角色附近可讀，不能只放在遠端總 HUD。這不代表本文件已決定排版尺寸、圖示數量或最終 UI 元件數量。

## 讀法與數量界線

- **沿用**：可直接作為目前用途或新系統的暫時／正式素材。
- **修改**：保留構圖、風格或動作參考，需重新裁切、拆層、重配色或重做輸出。
- **重製**：現有檔案把身份、服裝或功能烘焙在一起，不能直接滿足新設計，需要新的原畫／圖層。
- **新增**：目前沒有相應檔案或引用，需要建立新的素材與索引。
- P0 是紙娃娃與戰鬥可讀性的前置；P1 是首個完整內容批次需要；P2 是內容池、分享或 polish 依決策補齊。

下文的檔案數量是 2026-09-09 工作樹的盤點結果，不是新需求數量。素材總數尚未定案；任何新髮型、服裝、道具、敵人、卡牌或 UI 狀態的數目均待內容設計與實作前決定。

## 建議的遷移交付順序

1. **P0：建立紙娃娃素材契約。** 先定義基底畫布、腳底／root、圖層排序、遮罩、動作錨點和 runtime manifest；把現有三名角色圖降級為參考／預設素材，不把新內容建立在固定身份路徑上。
2. **P0：建立角色附近 HUD 圖示契約。** 生命條、格擋、意圖、狀態全部能靠近玩家或每名敵人，圖示與角色 PNG 分離；位置與響應式排列依 [BATTLE-LAYOUT.md](./BATTLE-LAYOUT.md)。
3. **P1：遷移區域背景與敵人。** 保留現有背景與 enemy 圖作 style／fallback，產出區域畫風一致、普通／菁英／首領可辨認的透明圖層與錨點。
4. **P1：建立 card art／item icon 索引。** 先使卡牌、被動道具、消耗品在獎勵、商店、戰鬥、解鎖與紀錄可辨認，再決定哪些道具具備紙娃娃展示層。
5. **P1／P2：補流程 UI 圖像。** 地圖、解鎖池、廣告、續命先做已確認流程的狀態資產；紀錄／分享等未定欄位收斂後再製作完整摘要圖。

## 開放決策與風險

- 主角基底的身形、臉部抽象程度、髮型／髮色／膚色的選項邊界，以及現有三名角色是否只保留為預設外觀，尚未由內容設計定案。
- 每種模組是否需要完整 idle／attack／hurt 或更多動作、道具層如何處理手部遮罩與武器碰撞、錨點 manifest 的正式 schema 尚未定案。
- 區域與宇宙的關係、後續宇宙候選數與是否重複仍是 SPEC 未定事項；因此不能先把目前三套背景當成最終區域總數。
- 普通／菁英／首領的正式 enemy roster、每個首領的階段與是否需要專用攻擊動作尚未定案；現有 enemy ID 僅是 prototype 證據。
- HP／格擋／意圖／狀態要用 PNG atlas、SVG、CSS／DOM 或混合方案尚未定；本盤點要求視覺契約，不替實作選型。
- 卡牌插圖、道具 icon、可穿戴層與消耗品 icon 的覆蓋範圍、命名和 fallback 尚未定；不以現有 `data.js` 項目數推導新素材總數。
- 解鎖池組成、廣告平台與額度、續命頁的還原預覽、紀錄分享形式與額外欄位仍待決；在決策前只建立可重用的狀態框架，不鎖死內容數量。
- 現有檔名混用連字號與底線（例如 `enemy-raider`、`hero-shadow_ninja`）。本次不改名、不改引用；新增 manifest 應先確立穩定 ID 與檔名規則，避免紙娃娃層再產生歧義。
