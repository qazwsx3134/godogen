# 全畫面戰鬥與浮動手牌

2026-09-14。使用者指定遊戲全畫面、卡牌浮在畫面上出牌，以圖形按鈕搭配簡潔文字。本文是本輪實作與驗收規格，延續 [核心設計](PAPER-DOLL-SPEC.md)與角色附近血條要求。

## 畫面與資訊

- 遊戲外框填滿瀏覽器可視範圍，使用動態視窗高度與安全邊界。戰鬥不捲動整頁；主選單與其他內容頁維持全畫面外框，長清單在內容區內捲動。
- 戰場背景鋪滿戰鬥畫面，主角在左、敵人在右。HUD、操作與手牌覆在同一戰場上，避免將戰場和手牌分成上下文件區塊。
- 頂部僅呈現區域、回合、金幣與少量入口。能量靠近手牌，結束回合固定右下。牌堆、消耗品、共鳴、選單與戰報用可辨識圖示及短標籤；圖示保留可及名稱與鍵盤焦點。
- 主角與各敵人的生命進度條、目前／最大生命、盾牌數值、狀態在角色附近。意圖在敵人上方。HUD 與手牌預留空間，不能遮蔽選敵和主要生存資訊。
- 手機生命、格擋、意圖與可閱讀卡牌效果採至少 12px 字級；主要操作保留約 44px 觸控範圍。資訊不足以容納時簡化常駐文字並用預覽補充，不以持續縮小字體解決。
- 長篇規則、戰報、構築與完整牌堆放入可關閉的浮層；僅最上層接收操作，Escape／關閉回到原入口。
- 全畫面先指填滿瀏覽器視窗；若提供隱藏瀏覽器介面的全螢幕功能，須由玩家點擊啟動，支援失敗時仍可正常遊玩。

## 手牌操作

- 底部中央為浮動手牌，可輕微重疊排列。卡面以插圖、名稱、能量與短效果為主，流派等次要資訊不長期佔據操作區。
- 桌面 hover 或鍵盤 focus 抬起並放大卡牌，內容不被容器裁掉；離開恢復排列。每張牌都須有可操作區，十張牌時可採局部橫向瀏覽。
- 桌面維持點牌施放；指定目標牌點牌後再點敵人。hover 本身不出牌、不花能量。
- 手機沒有 hover：第一次點牌選取並放大預覽。指定目標牌再點敵人施放；無指定目標牌使用清楚的「出牌」按鈕確認。提供取消選牌，不能因瀏覽手牌而意外出牌。
- 無足夠能量時清楚顯示不可施放；取消、開關浮層、旋轉螢幕都不應花費能量或改變手牌。選牌、出牌、敵方行動與存檔仍由現有遊戲狀態管理。

## 本輪範圍

接入現有瀏覽器原型的外框、戰鬥視覺與手牌互動。保留遊戲規則與存檔語意；紙娃娃、三區冒險與廣告系統仍依核心設計另行實作。使用既有美術及可縮放介面元件；要新增 AI 圖片時，先讓使用者選擇直接生成，或提供 prompt 讓使用者使用 opt image 生成。

## 驗收

1. 1440×900、1366×768、390×844、844×390 戰鬥頁沒有整頁水平或垂直捲動；結束回合、能量、主角及每名敵人血條在視窗內且能操作。
2. 一至三名敵人、首領、五張／十張手牌可辨識；浮動卡牌不遮住不可取代的血條／格擋與目標操作區。
3. hover／focus 放大卡牌且不出牌；桌面指定目標、格擋牌、共鳴、消耗品、牌堆和回合流程保持可用。
4. 真正觸控情境下點牌先預覽，取消不消耗，確認或點目標只施放一次。
5. 浮層可關閉、焦點可返回，不能點穿操作戰場；無瀏覽器錯誤，重新整理可續玩相同存檔。
6. 保存實際桌面與手機截圖、檢查結果，人工檢視可讀性與遮擋。完成後在此記錄證據與實際限制。

```bash
node prototypes/anime-card-roguelite/battle-layout-check.mjs \
  --playwright /path/to/node_modules/@playwright/test \
  --url http://127.0.0.1:5182 \
  --out /tmp/rift-fullscreen-qa
```

瀏覽器驗收使用 headless Chromium，手機情境啟用 `hasTouch` 與 `isMobile`，並實際送出觸控事件；尚未以實體手機或 Safari 驗證。截圖使用既有原型美術，本輪沒有生成 AI 圖片。全畫面目前填滿瀏覽器可視範圍；作業系統全螢幕切換與正式美術、紙娃娃等後續系統不在本輪實作內，差距見 [設計與實作狀態](DESIGN-STATUS.md)。
