## 要驗證的假設

> 純抽象的幾何演出，能不能撐起柏青哥的期待感。

這是一個試作，成功的定義是**回答這個問題**，不是產出可維護的程式碼。假設被推翻也是成功——那會省掉一整個專案。

判定方式是[前傾測試](README.md#驗收)，分序列測試與場次測試兩種（[ADR 0009](docs/adr/0009-lean-in-test-is-two-tests.md)）。只有人能判，模擬腳本判不了。

執行順序是**最早碰到真正的風險**。這個試作的風險不在盤面物理——那是已知做得出來的工程；風險在兩件事：抽象演出撐不撐得起期待感，以及它撐不撐得住 iPhone Safari。所以第一個里程碑就要同時碰到這兩件事，而數字正確與釘微調往後排。

**這個順序回本了。** M1 一跑就撞出四件只有實機才看得到的事：ASCII 豆腐字、`--headless` 下 `--write-movie` 會 crash、`web_nothreads` 模板、以及 secure context 不等於 COOP/COEP。如果先做完 shader 才發現，那批工全白做。

## M1 一段會動的 SP，跑在 iPhone 上 — 技術過，內容沒過

不做整台機器。做**一段可以重播的演出，在目標裝置上跑起來並且有聲音**。

- [x] Godot 4.7 專案、直式 9:16、2:3 機台置中、上下 HUD 帶
- [x] **技術基準線**：Compatibility renderer、Web 匯出關閉 thread support
- [x] 軌道連珠的視覺語彙：三天體、軌道、鎖定態、目標位幽靈標記、吸附、偏離（零生成美術）
- [x] 四條可重播的強制序列，不經過抽選
- [x] 黑洞接管越出液晶邊界接管全螢幕
- [x] 音效：程序合成的最小集合，含高潮前 0.5 秒靜默
- [x] 固定標準盤：釘子寫死、不隨機、不校準
- [x] 發射操作兩版：按住連發 vs 點一下開始／停止

**技術出場條件**：

| 檢查項 | 目標 | 結果 |
| --- | --- | --- |
| 黑洞接管期間幀數 | ≥ 30 fps | **60/60/60**，穩態下三個成本變體都滿幀（[ADR 0010](docs/adr/0010-reconsidering-ios-native.md)） |
| 音訊 gesture 解鎖 | 觸控後正常，第一個播的不是リーチ音 | 待回報 |
| Sample 播放模式時序 | 斜坡連續、靜默真的安靜 | 待回報 |
| 發射操作 | 兩版都試過，定案寫回 README | 待回報 |

**內容出場條件沒過。** M1 交付的那段 SP 演出被否決了：接管中段的天體跳來跳去、環繞不像在運行、沒有「差一點」的感覺。原因是那 11 秒是用 `sin()` 疊 drift 做的**動畫曲線而不是軌道運動**——天體沒有速度這個量，所以沒有近日點加速、沒有遠日點拖慢。詳見 [README 的〈結論〉](README.md#結論)。

照 ADR 0009，這只否定這一版演出，不否定抽象幾何。修的是運動模型，不是美術，所以工作回到 M3。

## M2 數字與狀態機 — 主體完成

讓整台機器在數學上成立。

- [x] 盤面物理：`RigidBody2D` 的球、固定釘子陣列、始動口、電チュー、大入賞口
- [x] 發射：0.4 秒／發，左打／右打兩檔
- [x] 抽選（落入始動口即定案）、演出路徑在抽選時選定（四個互斥終點）、保留上限 4
- [x] 持ち玉 收支、始動口賞球 3 顆（保留滿也給）
- [x] 通常／確變／大當中 三狀態、確變ループ（突入率 65%）、出玉振り分け
- [x] **終局結算**：持ち玉 歸零後把飛行球與保留全部結算完（[ADR 0007](docs/adr/0007-zero-balls-settles-the-queue.md)）
- [x] HUD：持ち玉、狀態、轉數、保留（含滿的警示）、連莊與累計出玉、回轉率按鈕、右打提示
- [x] 模擬腳本 `sim.gd`，純 RNG／場次／物理三類分開跑

**出場條件**：[README 的驗收統計表](README.md#驗收)全綠 — **達成**。純 RNG 類十項、場次類（600 場）全過；物理類左打 12.31 発/轉（CI [11.66, 13.04]），右打 3.58。

釘子校準花掉 M2 大半時間，而且**沒有捷徑**——它是全機唯一無法用數學推導的數字。過程中發現真正的旋鈕是誘導釘 V 底的開口而不是釘子密度，細節寫在 [TODO.md](TODO.md)。

## M3 節奏與完整演出

把兩邊接起來，然後調到玩家願意等。這是整個試作真正要驗的部分。

- [ ] **重做接管中段的運動模型**（M1 留下來的債，是這一階段的第一件事）
- [ ] 確變高速變動、連莊累積回饋（軌道加環、BGM 加泛音）
- [ ] 依[秒節奏表](README.md#節奏)調校，並驗保留互動：通常與確變的溢出率都 < 3%
- [ ] 載入時預熱 SP 的 shader（實機編譯 68 ms 是會被感覺到的一次性 stall）
- [ ] 完整混音：通常時只有機械聲，リーチ 進來聲音才長出來
- [ ] 真正的接管做完之後重跑壓力測試

**出場條件**：兩種前傾測試都通過（[ADR 0009](docs/adr/0009-lean-in-test-is-two-tests.md)）。

序列測試用開發旋鈕迭代；場次測試必須切設計值、固定標準台、玩到第 3 次 SP。開發旋鈕驗不了等待值不值得（[ADR 0005](docs/adr/0005-sp-reliability-is-set-by-the-test-not-the-genre.md)）。

**這一階段有真正的失敗可能**，而且已經先嘗到一次（M1 的接管）。失敗的結論是「**這一版演出不成立**」——節奏、可讀性、回饋強度三個變因都調過仍失敗，才輪到談具象元素（[ADR 0003](docs/adr/0003-no-generated-art.md)）。

## M4 釘調整與交付

- [ ] 釘調整：每場開始時隨機微調（[ADR 0006](docs/adr/0006-nails-are-reset-each-session.md)）。
      旋鈕已經找到了——誘導釘 V 底開口 90–102 對應入賞率 10–16，校準工具也在手上
- [ ] `sim.gd` 驗 20 組配置的分布，全數落在 9.5–16.5、無離群
- [ ] 若效能有餘裕，評估開 thread support（要 COOP/COEP header，itch.io 有設定）
- [ ] itch.io 上架（`butler push`，`itch-publish` skill）

**出場條件**：把連結傳給一個沒看過這台機器的人，他用手機打開就能玩完一場，不需要任何說明。

> `.claude/rules/prototype-code.md` 寫「Prototypes must not be deployed or shipped」。這裡是**刻意偏離**：目標裝置是 iPhone，上架 itch.io 是讓沒看過這台機器的人也能玩到的唯一方法（[ADR 0004](docs/adr/0004-web-only-delivery.md)）。上架是為了測，不是為了發行——頁面保持 Draft 或不公開列出。
>
> 平時的實機測試不需要上架：`tools/serve.sh` 匯出後用 Caddy 在 LAN 上開 **HTTPS** server（Godot Web 需要 secure context，純 http 只有 localhost 算數）。除錯用 **Safari Web Inspector**——Mac 與 iPhone 用 USB 相接，iPhone 設定 > Safari > 進階 > 網頁檢閱器，然後 Mac 的 Safari > 開發 > 你的 iPhone。

## M5 之後

**前傾測試通過才談**，沒通過就不該有 M5。而且這些是**升級成正式專案之後**的題目，**不在這個試作上實作**——照 `prototype-code.md`，試作驗證成功後是重寫，不是在原目錄上長。

- 台選び：開場給幾台，試打 100 發看回轉率再決定坐哪台
- 通常大當之後的時短
- 確變中的專屬演出層（第一版確變只有高速變動，沒有 SP）
- 保留變化（保留球變色預告）
- SPSPリーチ、復活演出
- 角色演出（抽象版驗證成功後的加法，不是補救）
- 店內換台、跨台持ち玉

## 已知風險

| 風險 | 影響 | 現在的狀態 |
| --- | --- | --- |
| 抽象演出撐不起期待感 | M3 失敗，整個試作的假設被推翻 | **已經失敗過一次**（M1 的接管中段）。失敗只否定這一版演出，不推論「需要角色」（[ADR 0009](docs/adr/0009-lean-in-test-is-two-tests.md)）。下一版動運動模型 |
| 確變中沒有高張力演出層 | 連莊平均 48 秒都是同一段高速變動，緊接在第一次大當的情緒高點之後 | 未驗。這一版的取捨：連莊的張力全押在累積回饋。若場次測試顯示注意力在連莊段落流失，第一個要動的是這裡，不是 SP |
| iPhone Safari 上 shader 撐不住 | 交付不了 | **已排除。** 穩態下三個成本變體都 60 fps，80 顆球也一樣 |
| 冷啟動的前置成本 | 玩家點開連結的第一分鐘卡頓，而那可能正好撞上第一次演出 | 已量化。shader 快取＋WASM tier-up＋時脈爬升要數秒。節奏本來就在保護我們（SP 每 80 轉才一次），唯一會撞上的是序列測試——它已經先跑暖機 |
| Web 音訊限制打壞靜默原則 | 整套混音設計要重來 | 實機探測畫面已就緒，**判讀待回報**。不過就切 `audio/general/default_playback_type.web=0` |
| 五分之一的場次天生看不到 3 次 SP | 場次測試判不了，卻看起來像演出失敗 | 已量化：`sim.gd` 實測 P(≥3 SP) = 0.83。樣本不足的場次直接重跑，不列入判定 |
| 始動口入賞率校準不到目標值 | M2 卡住 | **已解決。** 12.31 発/轉。旋鈕是誘導釘 V 底開口，不是釘子密度 |
| 物理類模擬跑太久 | 回饋迴圈變慢 | 已解決：球不和球碰撞，所以入賞率與發射速度無關，1.4 萬顆 27 秒 |
| 場次類模擬跑太久 | 2000 場要跑十幾分鐘 | 已知代價。平時用 `--sessions=600`（約 3 分鐘），改動經濟時才跑滿 |
| 試作長大成正式專案 | 拋棄式的前提失效 | 先讓它拋棄式。前傾測試通過再談要不要升級 |
