## P0：下一輪，先驗證手機與爽感

### T-001 手機 HTTPS 試玩入口

- [ ] 整理現有 Web 包與試玩說明，選定測試用 HTTPS 主機。
- [ ] 建立可由實際手機開啟的試玩連結；確認載入、開始手勢與聲音。
- [ ] 記錄版本、建置日期與對應驗證證據，避免試到舊包。

驗收：一台實際手機從連結開始、選卡、跑完 90 秒並重試。本機 `localhost:8793` 是目前電腦的入口，外部手機入口尚未建立。

### T-002 真機輸入、生命週期與安全區

依賴：T-001。優先使用手邊手機；Android Chrome 與 iPhone Safari 的覆蓋狀態分別記錄。

- [ ] 測試拖曳、放手、選卡後再次拖曳、暫停／繼續與連續重試。
- [ ] 在移動中、選卡中切到背景，再切回；確認不偷跑計時或留下移動向量。
- [ ] 檢查來電／通知、瀏海、底部手勢區、瀏覽器工具列與不同長寬比。
- [ ] 依實測加入需要的 Safe Area 處理，保留 scene 的版面調整。

驗收：附裝置、系統、瀏覽器版本與實機錄影；只驗證過的組合標成通過。

### T-003 第一段打擊與聽感調整

- [ ] 錄下前 15 秒與後期成長，逐項比較拳擊、金屬命中、重拳、致命揍飛。
- [ ] 檢查打中位置、揮拳方向、擊退距離、飛出速度與畫面停頓是否一致。
- [ ] 在手機喇叭／耳機上調整音量與音效層次；避免連打蓋住機車預警。
- [ ] 依使用者試玩反饋調整，不把「自動測試通過」當成「夠爽」。

驗收：普通命中與致命一擊能靠畫面和聲音辨認；機車預警可聽見、看清楚，關閉震屏後仍能辨認命中。

### T-004 真機效能基線

- [ ] 量測前期、後期與高密度揍飛時的幀時間、載入時間與長局記憶體。
- [ ] 測試目前的上限：22 個存活敵人、12 道衝擊波、24 個特效。
- [ ] 連續重試至少五局，檢查敵人、煙霧、投射物與音效是否持續累積。
- [ ] 按量測結果處理瓶頸；需要時才加入物件池、低特效模式或批次更新。

驗收：留下具體裝置與量測結果，再確定支援裝置及效能預算。軟體 WebGL 的速度不當作真機結果。

## P1：素材、成長與可讀性

### T-101 第一批 opt image 素材

- [ ] 使用者生成主角、抽菸者、機車、汽車與街區背景，見 [提示詞](docs/opt-image-prompts.md)。
- [ ] 檢查畫風、斜俯視角度、透明底、輪廓與背景中央的可玩空間。
- [ ] 原圖放 `assets/source/`，遊戲用圖放 `assets/art/`，記錄來源與版本。

依賴：素材由使用者提供。現有選擇是提供提示詞，不直接調用 AI 生成。

### T-102 素材接入與角色動作

依賴：T-101；可先逐張接入，不必等整批到齊。

- [ ] 用 Art node 替換幾何佔位，校正腳底／車輪、陰影、尺寸與視覺遮擋。
- [ ] 換圖後驗證碰撞、拳擊範圍與預警仍對得上。
- [ ] 決定需要補哪些方向與待機／行走／出拳圖，再提供第二批 opt image 提示詞。

驗收：角色與交通工具可辨識，動作讀得出出拳／受傷／飛出，主要 scene 仍可直接編輯。

### T-103 三條成長路線調整

- [ ] 分別以衝擊波、回旋踢、橫掃拳開局，記錄首次升級時間、後期等級、擊殺與受擊。
- [ ] 固定敵人種子並記錄選卡路線，檢查是否有明顯弱卡、必選卡或無感強化。
- [ ] 調整 EXP、招式觸發、傷害、範圍與層數上限，更新 Resource 與卡片描述。
- [ ] 視需要加入少量協同效果；新增前先寫清觸發與傷害判定。

驗收：三種開局都能形成可辨識的打法；一次試玩的 Lv.8／57 擊殺不是固定平衡目標。

### T-104 後期 HUD 與提示

- [ ] 用多張／多層升級檢查招式摘要、等級、經驗與連殺資訊。
- [ ] 檢查窄螢幕、較大文字與長卡片說明；避免資訊遮住敵人與交通預警。
- [ ] 補足玩家需要的操作提示，收斂首次進入、選卡與重試的文字。

### T-105 音樂與替換音效

- [ ] 確定音樂方向與來源，使用已接入的 Music 服務設定音量與淡入淡出。
- [ ] 需要時替換程序音效，保持事件檔名與播放節流。
- [ ] 記錄外部音樂／音效的作者、來源與授權，測試 Web 匯出仍包含音檔。
