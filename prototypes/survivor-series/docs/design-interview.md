# 倖存者系列：設計訪談

狀態：四輪回答已記錄；使用者於 2026-10-07 明確回覆「可以 開始實作」，整體規格已接受並進行實作。未接受的建議不視為決策。

## 已知要求

- 使用 Godot 製作倖存者遊戲系列。
- 可重用 sugarcane-tanks 與 godot-kit。
- 先建立骨架，再透過 grill-with-docs 逐輪釐清。
- 主要畫面與物件保留可編輯 scene；本輪使用幾何佔位。

## 決策樹

```text
系列
├─ Q1 作品關係：獨立發行／同款多主題／玩法實驗
│  └─ 核心共享方式、作品資料、版本與存檔隔離
├─ Q2 首要平台與畫面方向
│  └─ 輸入、HUD、安全區、效能與匯出
├─ Q3 第一款戰鬥主軸
│  └─ 攻擊策略、武器成長、刷怪與勝敗條件
└─ Q4 第一款特色與玩家幻想
   └─ 角色、敵人、美術、內容與試玩驗收
```

第一輪結果：先做第一款；系列發行關係待定，不阻擋第一款。平台方向為手機直式，攻擊為邊走邊自動攻擊。主角為行人，敵人包含抽菸行人、騎車者與駕車者。核心特色是爽快打擊特效、音效、把敵人揍出螢幕外。

第一輪的開放項目以下列逐輪紀錄為準；手機瀏覽器已在第三輪確認。

## 第一輪

1. 「系列」指多款各自發行、同一款內換主題／角色，或先做不同玩法實驗？建議：若主要換題材，先以一款驗證，再決定發行與共用邊界。
2. 第一款最先照顧桌面橫式、手機直式，或其他平台／方向？建議：先選一種主要操作與畫面，其他平台後續驗證。
3. 戰鬥是邊走邊自動攻擊、停下才攻擊並清房，或手動瞄準射擊？建議：若目標是典型倖存者，選邊走邊自動攻擊；它與 sugarcane-tanks 的現有規則不同。
4. 玩家操控什麼、對抗什麼，最吸引人的動作或效果是什麼？可給一句具體場景；未定也可明說，下一輪共同收斂。

## 第二輪決策樹

```text
第一款：手機直式、行人、移動中自動攻擊、揍飛爽感
├─ Q5 手機瀏覽器／原生 App
│  └─ 發行、輸入細節、真機與音訊驗證
├─ Q6 出畫面的敵人：擊殺演出／直接淘汰／仍在場外
│  └─ 傷害、邊界、掉落、敵人計數與 Boss 規則
├─ Q7 攻擊形式：近身拳腳／拳風遠程／兩者混合
│  └─ 目標選擇、射程、命中、打擊分層與成長
├─ Q8 場地：封閉街區／持續移動的街道／其他
│  └─ 相機、出畫面定義、刷怪與交通路線
└─ Q9 敵人具體威脅與車種
   └─ 預警、碰撞、速度、反擊窗口與密度
```

## 第二輪

5. 手機直式第一版要在手機瀏覽器直接玩，還是安裝原生 App？建議先以手機瀏覽器試玩，原生發行另行確認；不將網頁震動支援視為已驗證。
6. 「揍出螢幕外」是血量歸零的擊殺演出、一擊出界就淘汰，還是敵人有血量且可能回來？建議一般命中擊退，致命命中才誇張揍飛；避免相機移動改變擊殺規則。
7. 自動攻擊要近身拳腳、可打到遠處的拳風，還是兩者混合？建議先以近身拳腳驗證命中爽感，成長再擴大範圍。
8. 第一個場地要封閉街區，還是主角沿街持續前進？建議先用單一封閉街區驗證打擊與交通敵人，再決定單局長度與完整關卡結構。
9. 抽菸者／騎車者／駕車者分別怎麼威脅玩家？騎車指機車或腳踏車，駕車指汽車或也含其他車種？建議抽菸者釋放煙霧危險區、機車沿預警路線衝刺、汽車慢速但佔位大；這是提案，非已接受設定。

## 第二輪回答紀錄

- Q5：「手機」。已確認裝置，但尚未區分瀏覽器與原生 App。
- Q6：普通命中擊退，最後一下才誇張揍飛；採用血量歸零後的擊殺演出。
- Q7：再次確認普通擊退與致命擊飛，也允許其他攻擊模式；尚未指定第一招是拳腳或遠程。
- Q8：封閉街區，優先做好命中、擊飛與交通衝刺。
- Q9：抽菸者留下煙霧危險區、機車亮出路線後衝過來、汽車體積大且難推動。尚未決定煙霧的傷害／減速，以及汽車的具體移動模式；上一輪建議的汽車慢速尚未被明確接受。

## 第三輪決策樹

```text
已確認的打擊與交通敵人
├─ Q5a 手機發行管道（前題補充）
├─ Q10 起始攻擊 → 射程、選敵、攻擊動畫
├─ Q11 觀看角度 → 場景尺度、預警與遮擋
├─ Q12 移動操作 → 搖桿接入、觸控與安全區
└─ Q13 第一個可玩版本目標 → 單局節奏與成長範圍
```

## 第三輪

5a. 第一版在手機瀏覽器開連結，還是安裝 App？建議手機瀏覽器；尚未視為同意。
10. 起始招式是自動揮拳打附近敵人、遠距離拳風，還是環身踢擊？建議自動朝最近的射程內敵人揮拳，其他模式透過後續成長加入；選敵規則也是提案。
11. 畫面是從上方俯視街區、斜俯視可看到人物正面，還是側面橫向？建議 2D 斜俯視，保留交通路線辨識與人物受擊表情。
12. 移動採單指浮動搖桿，還是固定在左下的搖桿？建議單指浮動搖桿，攻擊全自動，重用 kit 現有模組。
13. 第一個可玩版本是短時間的打擊測試場，還是已有升級與勝敗的一局？建議先用 90 秒打擊測試場驗證三類敵人、音效與致命擊飛，再做完整成長；不自行選定正式單局時間。

## 第三輪回答紀錄

- Q5a：手機瀏覽器。
- Q10：先自動朝附近敵人揮拳，其他模式之後透過升級加入。
- Q11：2D 斜俯視。
- Q12：浮動搖桿、單指移動、全自動攻擊，使用 godot-kit 現有模組。
- Q13：90 秒打擊測試場，包含三類敵人、交通預警、普通擊退、致命揍飛與音效；優先驗證爽感。

## 第一個可玩版本範圍

手機瀏覽器直式、2D 斜俯視封閉街區、浮動搖桿移動、自動近身拳擊、抽菸者／機車／汽車、預警、擊退、致命擊飛、打擊特效與音效、90 秒計時及重試。

升級與其他攻擊模式屬於後續版本；系列發行關係、正式單局成長、局外成長、Boss、存檔另行設計，不作本次測試場的實作前提。

## 第四輪決策樹

```text
90 秒打擊測試場
├─ Q14 煙霧：傷害／減速／兩者 → 危險區回饋
├─ Q15 汽車如何接近玩家 → 移動、預警與出拳窗口
```

## 第四輪

14. 煙霧是持續傷害、減速，或兩者都有？建議只有持續傷害，讓手機上的移動與揮拳保持爽快。
15. 汽車慢速追近玩家，還是沿預警車道快速衝過？建議慢速追近、體積大且擊退小，與機車的直線衝刺形成不同打法；尚未接受。
16. 玩家血量歸零時結束重試，還是測試場中不死、只記錄受擊次數？建議這一版不死且記錄受擊，讓玩家完整測試 90 秒；正常勝敗留待正式單局設計。
17. 第一批視覺素材需要行人主角、抽菸者、機車、汽車及封閉街區；建議誇張漫畫風，打擊用程式粒子與動畫，音效先重用程序合成。選擇直接生成這批 AI 圖、提供 opt image 提示詞，或先用幾何佔位？任何生成或編輯都等待使用者選擇；本輪尚未生成。

## 第四輪回答紀錄

- Q14：煙霧只持續造成傷害，不減速。
- Q15：汽車慢速追近、體積大且難推動，與機車的高速衝刺區分。
- Q16：本版玩家不死，記錄受擊次數，完整測試 90 秒。
- Q17：提供可直接使用的提示詞，由使用者以 opt image 生成；沒有授權代理直接生成或編輯圖片。
