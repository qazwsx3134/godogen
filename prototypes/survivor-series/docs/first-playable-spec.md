# 第一個可玩版本：90 秒行人打擊測試場

狀態：2026-10-07 使用者整體確認，開始實作。以下區分已確認的產品決策與可調整的實作細節。

本文件記錄最初可玩版本；試玩後加入的經驗、升級與新招式見 [第二輪規格](progression-spec.md)。90 秒、不死計次與三類敵人的基準繼續沿用。

## 已確認的體驗

手機瀏覽器直式、2D 斜俯視封閉街區。單指浮動搖桿移動，移動中也自動朝附近敵人揮拳。普通命中扣敵人血量並擊退，最後一下誇張揍飛出畫面；打擊特效與音效是核心驗收重點。

抽菸者留下只傷害、不減速的煙霧；機車顯示路線預警後高速衝刺；汽車慢速追近、體積大、難推動。玩家在測試場不死，完整玩 90 秒並記錄受擊次數。其他攻擊模式後續透過升級加入。

## 流程提案

```text
入口 → 手指按開始（啟動音訊）→ 90 秒測試場 → 結算 → 重試
                                │
                                ├─ 自動拳擊／三類敵人
                                └─ 擊殺數、受擊次數、剩餘時間
```

計時使用遊戲時間；頁面切到背景時暫停，回來顯示繼續按鈕，避免切回時突然被車撞。hit stop 不消耗整段真實停頓的測試時間。重試清空敵人、煙霧、演出與統計，不重寫原始場景。

## 場景與重用邊界提案

- 主要入口、戰場、HUD、結算、主角、三類敵人、煙霧、拳擊與擊飛特效做成可編輯 `.tscn`；代表性物件在編輯器內可見。
- 行為由根腳本控制，位置與版面保留在 scene。敵人與特效依資料 instantiate 小場景，不在 `_ready` 建整個畫面。
- 使用 kit 的 FloatingStick、TimeControl、SfxBank、Synth、CameraShake、Music、SceneBuilder、TestKit。場景產生器只作一次性製作工具。
- sugarcane-tanks 的房間／停下攻擊流程不直接搬入；可借用經盤點的敵人預警、受擊、特效與數值分離概念。共用 kit 副本不直接修改。
- 第一版畫面提案為 540×960；HUD 留上方安全區，觸控區避開按鈕。相機固定觀看整個街區，致命擊飛沿攻擊方向越過可見邊緣。

## 戰鬥細節提案

自動拳擊選射程內最近的存活敵人，每次揮拳在命中時刻判定一次；沒有目標便不空揮。目標不因受擊短暫無法被選中，避免爽快的連擊中斷。

普通擊退區分重量，汽車最小；敵人仍留在街區邊界內。致命命中立即計入一次擊殺，退出攻擊／受傷／選敵判定，再播放擊飛演出。飛出去的物件不再撞玩家，不等待出畫面才判斷死亡。機車與汽車連同騎士／駕駛一起飛走；本版沒有致命擊飛例外。

煙霧有可見範圍與有限壽命，週期造成受傷事件。機車預警時固定路線，衝刺途中不追蹤拐彎；離開場地後回收。汽車慢速追近並產生接觸受傷事件。玩家受傷有短暫間隔，避免重疊煙霧或車體每幀都計一次；受擊次數只在有效事件發生時增加。

敵人逐步刷出，設存活數上限；死亡演出另設數量上限並及時回收。精確數值經第一輪試玩調整，暫不使用物理布娃娃或大量剛體來做擊飛。

## 打擊與音效提案

普通命中有短促拳聲、接觸閃光、敵人形變與小幅擊退；致命命中疊加低頻重擊、速度線／粒子與誇張旋轉位移。TimeControl 管理短促 hit stop；震屏使用 CameraShake，設強度與關閉選項。高密度命中節流，避免持續停頓或音效失真。

音效先由 Synth 與 SfxBank 產生可替換的佔位音，分拳擊、行人命中、金屬命中、致命揍飛、玩家受傷與交通預警事件。致命揍飛需要明顯區分普通命中，不能只有音量變大。手機瀏覽器從開始按鈕的實際手勢啟動音訊；震動不作必要驗收條件。

## 素材交接

使用者選擇 opt image，自行生成。代理提供五份提示詞，不直接調用圖片生成／編輯。第一批是靜態角色與背景，揮拳、受擊與擊飛先由場景動畫／粒子完成；額外動作圖另開批次。

素材尚未到位時，場景保留幾何佔位以便繼續實作與測試；貼圖替換不改變戰鬥碰撞。生成結果的透明背景、視角、留白與人物辨識需要人工檢查，不能因檔案存在就宣稱可用。

## 驗收

1. 手機直式瀏覽器能開始、完整遊玩 90 秒、結算並重試；切換背景後能安全繼續。
2. 真正觸控操作能移動，移動中仍自動揮拳；浮動搖桿不搶 HUD 按鈕事件。
3. 三類敵人行為可辨識：煙霧持續傷害而不減速、機車先預警再衝刺、汽車慢速且普通擊退明顯更小。
4. 普通擊退不直接淘汰；致命擊飛每個敵人只計一次擊殺，演出中不再造成傷害，最終回收。
5. 玩家不死，受擊有回饋且計次節流；計時結束後停止戰鬥，重試歸零。
6. 手機開始後能聽到普通命中、金屬命中與致命揍飛的差異。是否夠爽以使用者真機試玩為準，headless 通過不代表手感驗收。
7. 主要 scene 可在編輯器改間距、靜態文字與代表物件位置；執行不覆寫編輯值，執行期數值不污染來源。

瀏覽器驗證要覆蓋真觸控事件、console、網頁匯出與重試；軟體 WebGL 不代表實機效能。外部公開發布另行處理；本規格的交付是可本機試玩的 Web build。
