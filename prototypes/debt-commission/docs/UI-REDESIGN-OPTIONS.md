# UI 改版候選方案

2026-09-25。狀態：供使用者選風格，尚未套入 Godot 遊戲。

[互動比較頁](ui-options/index.html)以相同現有場景與角色素材比較三款介面，包含閱讀、吐槽選項、選單與標題。示意文字只用於版面測試；預覽操作不會寫入遊戲存檔。

已完成 Chromium 檢查：1440、390、320 三種瀏覽器寬度 × 兩種手機預覽比例 × 四個畫面，共 24 組，未發現按鈕超出預覽邊界或小於 48px。三款的選單開關、前進及選項選取回饋均通過。已人工查看[對話比較](ui-options/comparison-dialogue.png)、[選項比較](ui-options/comparison-choices.png)與[窄版選項](ui-options/narrow-choices.png)；檢查紀錄見 [verification.json](ui-options/verification.json)。裝置按鈕切換的是預覽比例，頁面窄時外框會縮小；這不是原生裝置模擬。

## 現況與設計依據

依據 [TODO](../TODO.md)、其中三張參考圖、[目前實機匯出截圖](UI-TRIAL.md)及 `game-ui-design` 的 patterns、sharp_edges、validations。

目前四顆底部實心快捷鍵與兩顆懸浮圓鈕各自搶佔注意力；LOG／AUTO／SKIP 與中文內容的語言不一致。對話層高度隨視窗比例配置，短台詞留下大面積空區，對話、角色與操作缺乏清楚主次。照片解析度與人物素材品質也影響整體觀感，需與介面設計分別評估。

三款共通設計：保留舞台與人物的完整視線；閱讀時顯示說話者、台詞、下一句和輕量快捷列；存讀檔集中在選單；吐槽階段才展開計時與四個選項。取消預設雙懸浮鈕是候選互動變更，選定後需一併更新既有操作驗收。

## A｜月下映畫

墨藍、米白、低彩度青色。滿版場景搭配底部漸層遮罩，細上緣線分開對話層；名字用小色標標示。快捷列使用文字，保留足夠觸控範圍。選項是細線分隔的深色橫列；選單以低彩度實底承載。

最接近 TODO 參考圖，適合長時間閱讀與沉浸。對美術背景的依賴較高，照片和角色完成度不足時仍會顯得粗糙。轉場以短淡入淡出為主。

## B｜萬事屋委託簿

暖紙白、墨色、朱紅。底部像一張委託書，台詞採深字淺底；名字是欄位標籤，選項像帳簿條目，主要行動使用朱紅印章語彙。標題、選單與存讀檔可共用帳頁、頁碼與日期的視覺規則。

與討債、委託和萬事屋生活感最一致，也是目前推薦的完整風格。淺色面板可穩定閱讀對比，但會比 A 明顯占據畫面。紙感以簡單線條與色塊實作，避免繁複貼圖和過度仿舊。轉場用短促帳頁遮罩，不做反覆翻頁動畫。

## C｜吐槽分鏡

黑白、朱紅與少量黃。對話層使用漫畫分格與粗細有別的邊線；選項採編號與切角，吐槽主動作具有最強對比。普通閱讀保持安靜，爆點才使用短暫速度線或局部放大。

最強調喜劇節奏與吐槽玩法，也最容易搶走台詞注意力。長篇敘事需控制裝飾密度；縮小到窄螢幕時文字仍保持水平，不隨外框傾斜。轉場以短分格切換為主，降低動態模式使用淡入淡出。

## 選定後的 Godot 實作與驗收

- 以共用 Theme／StyleBox 和可複用 Control 元件統一 normal、hover、pressed、focus、disabled 狀態。現有 UI 多在 `main.gd` 執行時建立，不能只修改空白主場景的編輯器節點。
- 用 Container、錨點與內容高度管理對話、快捷列、四選項及選單；驗證 320×568、390×844、桌機直式舞台與較長手機。
- 預覽基準：台詞至少 18 CSS px、次要文字至少 14 CSS px、操作區至少 48×48 CSS px；Godot 需按實際匯出顯示尺寸換算。文字對比至少 4.5:1。背景滿版，重要文字與控制項保留安全邊距。
- 計時具備數字與進度雙重提示；開啟選單、歷史或存檔時暫停。停用與選取不僅依賴顏色。鍵盤焦點可見，覆蓋層關閉後返回原焦點。
- 每款正式落地後檢查標題、旁白、具名台詞、長台詞、調查、裝傻、四選項、對話紀錄、存讀檔與覆寫確認。HTML 樣稿檢查不等同於 Godot 或真人手機驗收。
- ASCII／駭客轉場仍是 TODO 的候選，不作為三款共同基底；故事氣質確認後另做短片段比較。

## Godot MCP 的定位

本次檢查：此 Codex session 沒有可呼叫的 Godot MCP 工具，`codex mcp list` 僅列出 Cowart。這只能說明本 session 的可用狀態，不能證明其他客戶端沒有安裝。

[Godot MCP Toolkit 官方倉庫](https://github.com/NPGameDev/godot-mcp-toolkit)提供 Godot 編輯器外掛及配套 `@npgamedev/godot-mcp-server` bridge，可處理場景、節點、腳本、執行及測試回讀。Godot MCP 另有多個同名專案，未指定網址時不能視為固定的一套工具。

建議正式改版時使用一套能讀取實際執行狀態的 MCP，協助檢查 Control 尺寸、節點樹、輸入與截圖；保留腳本測試和 Web 匯出瀏覽器驗證。預期收益是縮短修改與觀察的循環；視覺品質仍取決於設計方案、素材、字體與逐屏修正。實際效率需在本專案驗證，不預設工具安裝後就會變快。
