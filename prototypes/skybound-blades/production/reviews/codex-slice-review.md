# C2：RO 戰鬥切片交叉 review

2026-10-24。範圍：派工指定規格、tuning、8 支程式與 2 支測試，補讀實際 field／actor／HUD scene 與角色 sheet。僅靜態閱讀，未跑 Godot／測試、未修改實作。
結論：6 項可由程式路徑確認的缺陷（高 1／中 3／低 2），另列 2 項待實跑確認；不以候選美術差異或風格偏好列缺陷。

## 確定的缺陷（靜態路徑確定，尚無本輪執行證據）

### R1【高】同 tick 傷害沒有共同快照，先出手者可取消應有的致死反擊
- 位置：`domain/battle.gd:112`、`:125`、`:494`、`:563`、`:576`、`:589`、`:609`。
- 情境：雙方在射程內、普攻皆已就緒，隊長與怪物本 tick 原可互相致死（取雙方命中的 RNG 情況）；關閉自動藥、AI 已倒下。
- 結果：隊長 ID 較小，先 `_hit`→立即 `_down` 怪物並發獎；怪物輪到決策時已不 alive，致死反擊根本不產生。若這筆 EXP 升級，隊長還會在敵方同 tick 傷害前補滿血。
- 與 implementation-plan §5 的「同時傷害快照→死亡→回復→最後獎勵升級」相反；`_sustain()` 也排在普通攻擊傷害前。需統一普攻／技能命中結算相位，再判死、補血、發獎。

### R2【中】有鎖定但超出射程時，Q 會擅自換成另一隻近敵
- 位置：`domain/battle.gd:497`、`:502`、`:508`。
- 情境：鎖定距離 5 格的 A，B 在 1 格內，按 Q；cleave 已就緒。
- 結果：`manual` 分支因 A 超出射程而找 B，改寫 `target_id`、耗冷卻並攻擊 B；原追打目標也被改掉。
- ro-slice 操作規格只在「沒有鎖定」時允許選最近敵人。有鎖定但太遠應拒絕／保留追擊，不該換怪；目前測試只測無鎖定的近距離施法。

### R3【中】AI 寫入不可達紀錄後，下一 tick 仍會選同一隻怪
- 位置：`domain/battle.gd:305`、`:339`、`:346`、`:478`；對照僅隊長搜尋讀取紀錄的 `:287`。
- 情境：敵人隔著封閉障礙鎖定隊長，兩名 AI 在隊長 8 格內、無法到達敵人，怪物也未死。
- 結果：`_engage` 卡住後寫入 `u.unreachable` 並清 target；但 `_companion_target` 每 tick 直接回傳同一個 threat，完全不讀 AI 的 unreachable。於是反覆撞牆／報 blocked，無法遵守 5 秒避選期，也不回跟隨。
- 需在同伴的 threat／集火／自衛選擇都過濾不可達目標；目前障礙測試只覆蓋隊長 move。

### R4【中】暫停畫面仍接收戰鬥快捷鍵，恢復時才突然執行
- 位置：`game/field.gd:116`、`:132`、`:183`；`domain/battle.gd:115`。
- 情境：受傷且有藥時 Escape 暫停，在暫停選單按 E／R／Q／F／空白，再恢復。
- 結果：鍵盤分支與 `send()` 都未檢查 paused／portrait，命令留在佇列；畫面當下沒有結果，恢復後才消耗補給／放技能／領獎／切換自動，形成非預期操作。
- 應於凍結期間拒絕戰鬥命令（保留 Escape／選單操作），或明確設計並顯示排程；目前沒有暫停輸入測試。

### R5【低】死亡後重開，原本可見的名字牌持續隱藏
- 位置：`game/actor_view.gd:57`、`:63`、`:83`、`:103`；`game/field.gd:99`。
- 情境：隊長死亡並 sync 一次，名字牌已 hide；按開始新一輪。
- 結果：`bind()` 把 `_was_alive` 設 true，卻未還原 `nameplate.visible`；下一次 alive sync 又無法進「由死復生」分支。隊長名字牌不恢復，重開時仍倒下的怪也有同問題（直到之後再次死亡／重生）。
- `bind()` 應完整還原可見性與呈現狀態；現有 restart 測試只檢查 domain／結束面板，未檢查名字牌。

### R6【低】滿血按普通藥，提示「沒有回復藥水」，但庫存仍有 5 瓶
- 位置：`ui/hud.gd:98`、`domain/battle.gd:663`、`game/field.gd:376`。
- 情境：新局滿血、tonic_small=5，點藥水或按 E。
- 結果：按鈕未禁用，`hp >= max_hp` 被歸為 reason=none，顯示「沒有回復藥水」，與 HUD ×5 矛盾；未扣庫存。
- 應區分 full_hp／no_stock／hot，給正確提示或禁用滿血按鈕。

## 待實跑確認的風險（不是已重現缺陷）

- R7【中，推測】：`game/field.gd:87`、`:143`、`:173`。地面拖曳開始後，若在 HUD／暫停選單上放開左鍵，GUI 可能攔截 release，使 `_drag_moving` 殘留；restart 也不清此旗標。若成立，恢復／重開後每 0.15 秒會自動下 move，覆蓋攻擊／自動狩獵。需實測「拖到 HUD 放開、Escape 後重開」，並以實際按鍵狀態或全域 release 清旗標。
- R8【中，靜態尺寸推算】：`ui/hud.tscn:153`、`:169`、`:207`，`project.godot:10`。以 844×390 橫向、900 高設計畫布等比縮放估算，92 px 縮放／暫停鍵約 39.9 px，64 px 回報鍵約 27.7 px，低於 44 px 規格；未見手機尺寸的最小觸控區補償。需以 Web CSS viewport／實際 Control 尺寸確認，不能拿 design px 當觸控 px。
