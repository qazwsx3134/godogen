# 機制優先規劃 v0.2

2026-10-24。戰鬥畫面以外的機制規劃。建置順序：先完成 [RO 戰鬥切片](ro-slice.md)（M0），再依本文件做機制驗證與遠征閉環（M1 起）；遠征結算與切片共用同一個 `domain/` 戰鬥模擬。

仍然有效的決定：單機＋AI、角色永久死亡＋部分帳號傳承、Web 桌機與手機橫向。此次沒有改成真人 MMORPG，也沒有把研究到的所有常見 MMO 功能承諾納入首版。

研究依據與 20 系統盤點見 [EOA／MMORPG 研究](../../../docs/research/echoes-of-aincrad-mmorpg-systems-2026-10-24.md)。舊 tuning-draft.json 保留為尚未平衡的起始草案，不代表 EOA 的實際數值。

## 1. 先回答的五種成長

| 成長 | 玩家問題 | 資料歸屬 |
|---|---|---|
| 角色 Lv／能力 | 我現在能承受什麼？ | Run，死亡重練 |
| 武器與技能熟練 | 我用這一類武器練出了什麼？ | Character，符合條件後可回城登錄手記 |
| 裝備成長 | 我願意把哪些資源投在哪件物品？ | EquipmentInstance，穿身上有風險，存倉可傳承 |
| 冒險執照／探索 | 我證明了什麼、能去哪裡與使用哪些服務？ | Profile／World，依主線與探索里程碑提升 |
| 知識與收藏 | 下一代能少走哪些冤枉路？ | Profile，配方／來源／圖鑑／回顧 |

冒險執照先用首次開營地、完成重要調查、攻略守層者三類條件，不能只刷同一隻怪升階；舊區維持既定 tier。手動配點、複雜天賦樹及特效轉移仍是候選，不立即推翻現有固定成長草案。

## 2. 要形成的系統閉環

```text
任務／目標 → 區域情報 → 遠征配置 → 遠征結果
     ↑                                 ↓
     └── 新能力／新配方 ← 加工／存倉 ← 戰利品與進度
                            │
                            └→ 知識與傳承 → 下一代
```

遠征結果至少包含：傷亡、消耗、EXP、技能熟練、戰利品、任務事件、探索發現與停下原因。各系統依事件處理，不依賴角色是 3D、2.5D 還是文字圖示。

## 3. 優先序與範圍

| 階段 | 系統 | 交付內容 |
|---|---|---|
| A・基礎 | S01–S03、S08、S20 | Profile／Run、成長、技能、物品實例、倉庫、死亡日誌、資料表與存檔 |
| B・遠征閉環 | S04–S07、S10–S11、S19 | 區域／執照、任務、掉落／強化、商店、AI 配置、補給策略與遠征結算 |
| C・世界感候選 | S09、S13、S15、S17–S18 | 採集／製作、NPC 協會委託、區域事件、聲望／情報／收藏，逐項選最能支撐閉環的加入 |
| D・另案連線 | S12–S16 中的真人共享部分 | 好友聊天、組隊招募、公會管理、玩家交易、全服攻略；只有使用者改變單機方向後才規劃實作 |

住宅、婚姻、釣魚、PvP、領地戰不因被列入盤點就成為必做。先保留原 3 層／3 Boss 內容上限，不提前增加大量樓層。

## 4. 非戰鬥資料與必備規則

| 資料 | 必備欄位／行為 |
|---|---|
| Profile | 已登錄配方、手記、圖鑑、執照、營地、倉庫、紀念碑 |
| Character／Run | 等級、屬性、個人熟練、隨身資產、任務、隊伍、目前遠征 |
| RegionDefinition／RegionKnowledge | 解鎖條件、tier、資源來源、路線、營地、已發現資訊 |
| QuestDefinition／QuestInstance | 前置、目標、計數方式、回報地點、消耗、獎勵與 receipt |
| ItemDefinition／EquipmentInstance | 模板、tier、品質、能力、加工、綁定、鎖定與來源 |
| Recipe／CraftJob | 配方解鎖、材料、費用、時間、產物與結果 receipt |
| PartyRoster／Companion | AI 身份、裝備、分工、戰術、熟練與死亡／退役狀態 |
| OrganizationProgress | NPC 協會認可、委託與已提交工程；和個人好感分離 |
| ExpeditionRequest／Result | 區域、隊伍、配置、方針、結果事件與風險說明 |
| Journal／Commission | 已讀、冒險回顧、死亡原因、離線 job 與領取紀錄 |

重要邊界：角色等級、武器熟練、裝備強化、執照不是同一個值；普通材料、任務品與加工素材也不能只看名稱分類。組織認可／世界工程可以保留，當代個人關係及未領獎任務不自動傳給下一代。

原作沒有確認的規則，沿用本作 implementation-plan.md 的明確提案，例如強化失敗不毀裝、安全離線委託與庫存交易。未因參考 EOA 自動改成全存檔刪除、不可撤退 Boss 或全域隨階級增強。

## 5. 先做哪些玩家操作

不論日後戰鬥畫面如何呈現，玩家都應能完成：

1. 在任務上查到需求、來源、風險與下一步。
2. 查看角色、當代技能與跨代知識分別如何成長。
3. 比較裝備、鎖定重要物品、看懂加工的消耗與結果。
4. 配置 AI 職責、補血與撤退方針，知道哪些操作會自動進行。
5. 選擇區域並收到清楚的結算，知道為什麼回城或停下。
6. 把成果登錄／存倉，再決定是否挑戰下一個里程碑。
7. 死亡後理解失去了什麼、留下什麼，以及下一代可以如何開始。

初期的可編輯介面可以由角色、技能、任務、區域、背包、工坊、隊伍與傳承等面板構成，不先製作大批戰鬥原畫。主要風險操作仍需明確提示，普通整理不要堆疊確認視窗。

## 6. 世界感應該如何落地

### 生活與材料

先讓同一份普通材料可以投入藥品、強化或委託，形成選擇。採集／製作數量若擴充，以採集、鍛造、製藥為優先；配方來源可從主線、NPC 委託與探索取得。保留回頭找來源的圖鑑，不讓玩家靠外部 wiki 才知道哪裡農。

### NPC 協會

候選功能是執照、委託板、捐料工程、情報與服務解鎖。它不是提供真人權限管理與共享倉庫的玩家公會。NPC 攻略隊的活動明確標示為模擬世界事件。

### 長期目標

除樓層外，可提供流派手記、配方收集、伙伴個人事件、怪物資料與城鎮工程。聲望獎勵應增加路線或選擇，不全部變成必須刷滿的永久傷害加成。

### 放置化

自動補血、農點、停止條件、離線委託是本作的放置設計，不是 MMORPG 必備項，也未宣稱 EOA 具備離線掛機。重要任務選擇、稀有資源消耗與永久死亡不做無提示自動處理。

## 7. 第一個驗證物

**機制驗證版**：一個區域、少量模板、兩種任務、三人 AI 配置、一種加工、一個倉庫與一次死亡傳承；以決定性遠征結算搭配簡單介面呈現。

需通過：

- 同一遠征結果不會重複給 EXP、物品、任務計數與收藏。
- 任務回報與製作先重新確認材料，再一次扣除並產生結果。
- 等級、技能、裝備與執照能各自成長，來源可追溯。
- 倉庫和隨身資產在死亡時依規則分開；配發品不能刷成跨代資產。
- 新角色能使用知識與倉庫，但仍需養成當代技能與能力。
- 同樣一批材料至少有兩種合理用途；不能只剩全部賣掉或全部囤著。
- 遠征卡住時顯示可採取的下一步：換配置、換農點、補給、加工或推進任務。

此驗證只證明非戰鬥資料循環；不會拿自動結算結果宣稱已驗證動作戰鬥手感或最終 Boss 平衡。戰鬥手感由 RO 切片驗證。
