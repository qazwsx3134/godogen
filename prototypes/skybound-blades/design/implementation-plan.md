# 浮空劍域：玩法與實作規格 v0.1

2026-10-24。狀態：規劃交付，尚未實作或平衡驗證。暫名 Skybound Blades。

**建置順序：M0 是 [RO 戰鬥切片](ro-slice.md)（§10 的 HD 2.5D 呈現＋§5／§6 的戰鬥子集），M1 起依 [mechanism-plan.md](mechanism-plan.md) 接上機制閉環。數值與系統仍是可修訂的提案。**

**把每次出城設計成一段可持續農怪、也值得決定何時帶成果回家的遠征。** 角色會自動行動，玩家負責目標、流派、隊伍戰術、補給與撤退。下一層不是單純換背景，而是要求重新準備的一場守層者挑戰。

## 1. 已確認與本版設計決定

| 類別 | 定案 |
|---|---|
| 使用者確認 | 爬塔、主支線、農怪、角色等級與技能熟練度；單機＋AI 隊友；永久死亡＋部分傳承；Web 桌機與手機橫向；HD 2.5D RO 視覺方向；RO 式操作（點敵人追打、點地移動、自動狩獵為持續意圖）；先做戰鬥切片，切片中隊長倒下只結束本輪、不存檔 |
| 技術基準 | Godot 4.7；優先沿用 godot-kit 的 sprite3d、AtomicFile、TestKit、聲音及 Web 工具；畫面由可編輯 scene 組成 |
| 首版設計 | 3 層、隊長＋2 AI、3 種武器、原創世界與人物；一個城鎮主場景與分層營地；安全離線委託 |
| 尚待原型量測 | 刷怪節奏、Boss 難度、死亡接受度、技能成長速度、HD 採樣、手機效能；下文數字是可執行的起始調校值，並非原作數值或已達成的成績。節奏與離線收益的試算見 production/reviews/codex-pacing.md |

[一頁企劃](game-brief.md)控制範圍；[六項研究](../../../docs/research/snored-art-online-mechanisms-2026-10-24.md)保存證據與缺口。本文件明確定義自製版，不以未知原作規則當開發阻塞。

### 設計支柱

- **農得到的改變看得見**：等級、技能與裝備各自有進度，角色演出與數字都能確認。
- **準備能改變戰果**：同級不同武器、AI 戰術及補給，對同一守層者應有不同結果。
- **帶回家的成果有重量**：城鎮倉庫與知識延續，身上冒險資產會隨永久死亡失去。
- **放置過程可理解**：說明角色正在做什麼、為何停下、收益從哪來、風險在哪裡。

## 2. 玩家體驗與首版內容

### 三種節奏

| 尺度 | 玩家做什麼 | 應得到什麼 |
|---|---|---|
| 約 30 秒 | 看一場戰鬥、一次技能命中與掉落 | 明白配置如何運作，知道現在是否安全 |
| 約 5–10 分鐘 | 完成討伐、熟練度成長、補給回城 | 能換一件裝備或作一次配置決定 |
| 一次遠征 | 選路、存物、準備守層者、決定攻或退 | 解鎖新層或帶回能支援下一次的成果 |
| 多代角色 | 記下死因、傳承手記、使用倉庫 | 後代多一些選擇與知識，仍需練等練技能 |

時間是調校目標，不用自動計時跳關。首名守層者以新玩家約 20–30 分鐘能準備一次挑戰為起始假說，須用完整新手測試修正。

### 3 層內容預算

| 層 | 視覺與區域 | 守層者考題 | 主要學習 |
|---|---|---|---|
| 1・風庭遺跡 | 草地狩獵區、廢塔入口、石門戰場 | 蓄力橫掃與護衛分擔 | 補血門檻、守護與撤退 |
| 2・雨蝕回廊 | 苔石水道、蛛巢、潮濕祭壇 | 毒傷與召喚小怪 | 援護、目標優先與消耗管理 |
| 3・星爐中庭 | 晶石採掘區、鍛造廊、核心廣場 | 護甲階段與反擊窗口 | 破甲、技能順序與攻擊節奏 |

首版合計：1 城鎮＋2 營地配置、6 狩獵區、3 Boss 戰場、9 種一般怪物數據、3 種精英、3 Boss、12 件任務（主線 3、討伐 6、收集 3）、9 個武器技能、3 個 AI 工具技能。美術可共用地形件，數據變種要有明顯色彩／裝飾區別。這些是製作清單，並非現成資產。

第一層完成後才擴內容。百層是世界長期意象，首版不建 100 個空殼樓層。

## 3. 角色、死亡與帳號傳承

這裡的帳號是**本機玩家檔案**，首版不做登入伺服器。

| 資料 | 當代死亡後 | 原因 |
|---|---|---|
| 角色等級、EXP、技能熟練度、身上金幣／物品、穿戴裝備 | 失去 | 維持這次遠征的風險與養成價值 |
| 城鎮倉庫與已存入金幣 | 保留 | 讓回城及存放是有意義的選擇 |
| 地圖知識、怪物圖鑑、已解鎖營地／傳送點 | 保留 | 玩家與世界知識成長，不強迫重看所有介紹 |
| 傳承手記、已解鎖配方／流派與造型 | 保留 | 擴大後代選擇，不直接給滿級角色 |
| 主線閱讀紀錄 | 保留回顧；當代任務條件重新建立 | 不重播已知劇情，也不憑舊任務重領當代獎勵 |
| 紀念碑 | 永久記錄角色名、最高層、死因、關鍵戰鬥事件 | 使死亡有可回顧的故事 |

### 死亡的精確邊界

- 隊長 HP 歸零，立刻標記該 run 永久死亡；本次遠征結束，不提供同角色復活。
- AI 夥伴也是具名冒險者，HP 歸零即該人物死亡；隊長活著時可回城招募替代者。隊長死亡後，倖存夥伴退役，不把高等戰力直接帶進下一代。
- 三人共享「遠征等級／EXP」，各自保存武器與技能熟練度；替代 AI 依當代遠征等級加入，熟練度從 1 起。下一代整組重新培養。
- 傳承手記首版每代可選 **1 本**：解鎖一個已登錄技能的學習選項，仍需角色等級與前置條件，技能從 Lv1 起；不繼承原角色熟練度。技能達 Lv3 並回城時才登錄手記，不在野外自動把成果存成傳承。
- 城鎮才能存放／取出倉庫資產。沒有戰鬥中傳倉、屍體取回或死亡後結算背包裝備。
- 同一時點隊長與 Boss 都死亡，判定本次遠征失敗，不解鎖樓層；紀錄中保留雙方被擊倒的事件。

永久死亡前應能看到最近傷害、治療及撤退事件。新角色建立不要求重新走長篇新手閱讀。

## 4. 世界與行動狀態

```text
城鎮整備 → 移動 → 搜尋 → 戰鬥 → 掉落／任務進度
    ↑                   │  ↑             │
    ├──── 回城 ← 撤退 ←──┘  └─────────────┘
    │
    ├─ 安全委託 → 離線結算 → 城鎮整備
    └─ 守層者入口 → 確認風險 → Boss 戰 → 解鎖下一層
                                  │
                             隊長死亡
                                  ↓
                             紀念碑／新一代
```

- 行動狀態用明確 enum：Town、Moving、Searching、Fighting、Resting、Retreating、Boss、Story、Commission、Dead。HP 歸零的實體不能再選技。
- 「自動狩獵」是持續意圖，不是另一個戰鬥系統；補給中斷、劇情節點、手動停止及撤退都可終止此意圖，UI 要顯示原因。
- 3D 場景使用可通行網格與 waypoint；domain 保存 2D 地面座標，顯示層補地形高度。MVP 地面近乎平坦，避免把物理碰撞／高低差綁進離線系統。
- 自動尋找最近且路徑可達的有效目標；鎖定後持續至死亡、不可達或玩家改令。目標重算有間隔，避免逐幀跳怪。
- 主線演出只能在安全節點開始；清除戰鬥後停狩獵，再進 Story。退出閱讀後是否重新出發由玩家決定。

## 5. 戰鬥、等級與技能的起始規則

以下全部是**自製版調校提案**。存到資料檔，不能散落在演出腳本。

### 基礎公式

令 L 為遠征等級：

- 下一級 EXP：`ceil(200 × L^1.8)`，可連升多級，餘數保留。
- 隊長基礎 HP：`120 + 36 × (L−1)`；ATK：`14 + 3 × (L−1)`；DEF：`5 + 2 × (L−1)`；AGI：`10 + (L−1)`。
- 最終能力＝基礎能力＋裝備平值＋已生效 Buff；乘算依資料欄位另處理，保留來源明細。
- 普攻／技能先做命中判定，基準 95%；迴避扣除此機率，最終命中夾在 20%–99%。
- 命中傷害：`max(1, round(ATK × 倍率 × random(0.9,1.1) − DEF × 0.6))`；爆擊另乘 1.5。每一擊有事件 ID，同一擊只結算一次。有盾時另做格擋擲骰，成功將最終傷害乘 0.5；爆擊與格擋可同時成立，UI 同時記錄。三種流派都能在副手（`offhand`）裝盾；非槌流派裝盾後速度再乘 0.8。
- 普攻間隔：`max(350ms, 2000ms ÷ (1+AGI/100) ÷ 武器速度倍率)`。
- 升級將存活隊員 HP 補滿，死亡人物不受此效果。隊伍只增加一次遠征 EXP，不因三名角色而複製三份貨幣或任務計數。低等怪 EXP 乘 `max(0.1, 0.8^(max(0,L−怪物等級−3)))`，避免永久只刷第一區最有效率。

### 武器與技能

| 流派 | 首版定位 | 速度倍率 | 技能重點 |
|---|---|---:|---|
| 單手劍 | 穩定、守護與反擊 | 1.0 | 單擊、護架、破勢 |
| 細劍 | 快速、多次命中與標記 | 1.25 | 突刺、連刺、弱點標記 |
| 槌盾 | 抗傷、嘲諷與破甲 | 0.8 | 盾擊、堅守、震甲 |

- 裝備技能格於 L1／L10／L25 各開 1 格；首版內容主要驗證前兩格。初始單一技能已啟用。
- 技能資料包含流派、學習等級、前置技能等級、倍率、命中段數、距離、準備／命中時間、恢復時間、冷卻與效果。
- 角色空閒時，由技能格 cursor 循環找第一個已就緒且合法的技能；都不能用才普攻。多格重排不重設冷卻。
- 冷卻從施放開始計；每個角色同時只能有一個攻擊施放。多段命中以排程事件執行，不能靠動畫格數直接改 HP。
- 一次有效施放命中後給 5 熟練 EXP，整次施放只給一次；揮空及打不存在的目標不給。多目標不倍增。
- 技能熟練升級需求：`ceil(100 × 1.6^(技能級−1))`，最高 10；每級倍率＋5%，冷卻乘 `max(0.75, 1−0.02×(技能級−1))`。
- 第二、第三招分別以角色 Lv5／Lv15 及前招熟練 Lv3 解鎖。學會、已裝備、熟練度、施放中與冷卻必須是分開欄位。

### 同時事件的順序

模擬採固定 50 ms 步進（`simulation.step_ms`），攻擊與冷卻計時器保留餘數，不因步進量化吞掉 AGI 或速度加成；依 simulation time、優先序、事件 ID 排序，不以 render FPS 決定戰果。

1. 收集同時點已排程的傷害，從同一狀態快照計算後一併套用。
2. 處理死亡；隊長死亡則進死亡提交，當 tick 不再治療、升級救活或獎勵 Boss 解鎖。
3. 對存活者處理持續回復及效果到期；檢查自動用藥。
4. 處理撤退意圖與完成移動；可行動者依 AI／技能格選動作，排程後續命中。
5. 結算有效擊殺的 EXP／掉落／任務事件，處理升級與安全劇情入口。
6. 發出顯示事件與待儲存狀態。事件只能被消費一次。

## 6. AI 小隊與對話

玩家控制隊長的目標與方針，兩名 AI 真正參與傷害、受傷、冷卻與死亡。

| AI | 決策優先序 | 可調戰術 |
|---|---|---|
| 護衛 | 隊長或援護遭鎖定時嘲諷 → Boss 蓄力時護架 → 攻擊集火目標 | 保護隊長／優先精英 |
| 援護 | 最低血量存活隊員低於 45% 時治療 → 清除可解除的毒傷 → 攻擊 | 保留治療／積極進攻 |

- 工具技能不使用 LLM：資料驅動的條件與優先序即可。隊伍對話是由事件觸發、有冷卻的角色文案，清楚標示 AI 夥伴。
- AI 角色倍率只作用於基礎能力，再加裝備；替代 AI 招募費為 `30+10×遠征等級` 金，初始兩名 AI 免費。
- 三人各有 HP／技能狀態，共用背包補給。多人同時缺血時按 HP 比例、再按穩定 actor ID 排序扣庫存，不能出現負數。
- 嘲諷有持續時間與抗性；守護是減傷，不是永遠無敵。相同 Buff family 只取最強效果，重放刷新時間，不無限疊乘。護衛工具為嘲諷／護架，援護工具為消耗繃帶的治療並解除 1 層毒傷，細節在調校檔。
- 撤退為全隊命令，2 秒後離開；期間仍受傷，不重複點按延長／縮短結束時間。它不是免死按鈕。
- 隊伍可選保守／均衡／積極：保守遇反擊姿態暫停出手並保留治療，均衡遵守 Boss 危險標記，積極優先輸出。Boss 反擊窗口不是要求玩家每次手動點走位。
- 戰鬥紀錄分成我方、隊友、敵方、掉落、任務與系統；可篩選與回看死因。首版沒有假裝真人的世界聊天。

## 7. 補給與自動化

- 普通藥：起始每瓶回復 60 HP／6 秒，12 金；自然回復為每秒最大 HP 的 0.5%。同類 HOT 不疊加，生效中不自動再喝。
- 瞬補：立即回復 35% 最大 HP，個人冷卻 20 秒；數量有限，不作死亡後補血。
- 自動喝藥預設 60%；比較條件為 `HP/maxHP < threshold`。用藥後庫存、HOT 與紀錄一次更新。
- 自動撤退預設 25%；補給不足時若無可用回復品，停止開始新遭遇並回城。戰鬥內仍依撤退規則承擔風險。
- 自動購藥、存物、售物先只在城鎮處理；稀有／具名／任務／鎖定物品不能被批售。消費有預算上限，保留身上最低 30 金。
- 自動用藥：HP 低於門檻且沒有 HOT 時喝普通藥；HOT 生效中仍低於門檻的一半（預設 30%）時，自動使用瞬補（冷卻與數量允許的話）。
- 優先序為：判死 → 已有 HOT → 可用瞬補／普通藥 → 是否撤退 → 選攻擊。持續回復不會追溯抵銷已致死的傷害。
- UI 顯示已確認的門檻值；滑桿拖曳完成後一次提交，避免快速輸入產生部分成功的狀態。

## 8. 任務、戰利品、強化

### 任務

- 主線、討伐、收集使用資料定義；同時最多 10 件支線。
- 討伐只計接取後的有效 MonsterKilled；同一 kill ID 不重算。收集進度讀當前庫存，回報時扣所需數量。
- 收集品可同時顯示在多件任務，但同一份物品不能被兩次回報消耗；領獎時重新驗證。
- 回報在對應城鎮／營地進行。消耗物品、移除任務、發獎、更新圖鑑及寫 reward receipt 是同一提交。
- 一次性主線不可重領；日常討伐完成後 5 分鐘可重新接取，重新計數，不回溯過去擊殺。
- 追蹤會先給出目的地與風險，再開始移動／狩獵；第一次進入新危險區要確認一次。主線台詞與回顧可跳過已讀內容。

### 物品與經濟

ItemDefinition 保存模板；EquipmentInstance 保存唯一 ID、品質、強化與鎖定，不能修改共用模板。貨幣與堆疊物是整數。

新角色起始可存入金幣為 0。初始裝備與補給標為當代配發，不可賣、不可入帳號倉庫；同模板配發品與正常掉落分堆保存。避免反覆創角把免費物資轉成永久資產。

收益：怪物／任務／委託；支出：藥品、強化、裝備、補充 AI、委託物資。首版無拍賣、交易與付費加速。

首版不設背包容量上限；模板、品質、tier 與實例依調校檔生成，稀有裝備不以普通物品堆疊。

普通素材可賣，10 分鐘遊戲內時間（simulation time，離線與暫停時不計）內按原售出額買回；裝備售價為購入價 50%。任務物品不可賣。排序、比較及用途必須可見，不能只靠名稱判斷。

### 強化的自製版明確規則

- 城鎮工坊才可操作；每件普通／精製／稀有／具名裝備分別有 4／6／8／10 次初始嘗試。
- 每次至少 1、最多 3 顆同類材料。成功率：`clamp(0.90−0.08×plus+0.05×(材料數−1), 0.35, 0.95)`。
- 費用：`max(20, round(模板價格×0.3×(1+0.5×plus)))`。
- 成敗都消耗費用、材料及 1 次嘗試；失敗不毀損、不降級。這是本作規則，不是已實測的原作結論。
- 成功只增加選定方向：武器攻擊／速度／爆擊，防具防禦／HP／敏捷，飾品 HP／敏捷／爆傷。基礎量與每次成長留在資料中，首版以模板主屬性的 10% 為起點，整數至少＋1；速度每次＋3 顯示點、爆擊＋1 百分點、爆傷＋4 百分點，與百分比乘算分開。
- 確認畫面要列明前後能力、成功率、費用、材料與剩餘嘗試。一次 request ID 只可抽一次 RNG；重試回傳既有結果。

## 9. 安全離線委託與暫停

永久死亡與離線收益分開處理：**玩家無法操作時，不偷偷推進會死亡的實戰。**

- 實戰每 10 秒與每個重要事件（擊殺、升級、用藥、任務進度）寫入快照；切背景時凍結並盡力存檔。Web 關頁不保證寫完，所以以最近快照為準，不能依賴關頁事件。回來從相同戰況接續，HP、冷卻、敵人動作均不因離開而重置，也不發實戰離線收益。
- 要取得離線成長，先在城鎮派出安全委託；委託整隊與實戰互斥，不能同一角色同時領兩份收益。
- 只允許已淨化的普通區域；無 Boss、稀有裝備、主線推進或永久死亡。
- 上限先定 8 小時；區域資料的每分鐘 EXP／金幣／素材是基準值，三者都乘 `reward_ratio`（50%）；低等衰減取該區三種怪物等級各自衰減的平均；各區每分鐘收益由資料給定，不用玩家一次爆擊反推；逐分鐘重新計算低等區 EXP 衰減。
- 物資先扣：每預定小時 1 份口糧，未完成的分鐘按取消規則返還未使用的整小時份數；已開始的小時不退。取消也要先結算已完成分鐘。
- 每份委託包含 job ID、run ID、開始時間、區域、時長、預付物資、獎勵 seed 及 claim receipt。只有同一仍存活 run 可收經驗；開始新遠征前必須結清／作廢舊任務。
- 每次回歸最多結算一次；時間倒退算 0，超過上限只算上限。時間來源可注入以測試。

## 10. HD 2.5D 畫面與共用模組

### 視覺方向

3D 低多邊形地圖承接光照、地形與建築；角色使用 3～3.5 頭身 HD 插畫圖集，清楚輪廓與柔和分色。不是把整個遊戲套像素化濾鏡。城鎮暖色、野外清爽，Boss 戰保留明確的蓄力與地面預警。

固定約 35° 俯角與 45° 方位，首版無自由旋轉；方向仍用 kit 的鏡頭相對選列。角色面向優先序是攻擊目標 → 移動 → 保留最後方向。

### 已有與要補的能力

| 共用資源 | 本作用途 | 邊界 |
|---|---|---|
| sprite3d_actor／sheet／shader | billboard、方向、動作、受擊、溶解與描邊 | 支援的是顯示，不含任務、戰鬥、AI 或網路 |
| shadow／xray | 貼地影子與遮擋可讀性 | 仍需在本作樹木、人群、受擊時驗收 |
| sprite_atlas.py | 圖集、腳底線與尺寸驗證 | 不會自動產出一致的 8 方向 HD 原畫 |
| AtomicFile／TestKit | 存檔與自動驗證 | 死亡交易、schema、備份策略由本作負責 |
| 音效／音樂／載入／Web 工具 | 回饋與部署驗收 | 本作填自己的資產與事件表 |

來源：[kit README](../../godot-kit/README.md)、[sprite-actors-3d 規格](../../godot-kit/skills/sprite-actors-3d/SKILL.md)。同步時只跑 `sync.sh skybound-blades`，不改其他原型；`addons/proto_kit` 副本不可直接修改。

**HD 必做 spike：** kit 角色 sampler 目前固定 nearest。先在相同世界身高、鏡頭與手機尺寸比較高解析來源的 nearest／linear 呈現；需要 linear 時，在本作 `shaders/` 做引用共用 include 的薄 adapter，同步處理本體、剪影與殘影，不為單一新作改共用預設。

**紙娃娃邊界：** 身體／頭／頭飾分層換裝沒有現成 runtime。首版每種武器外觀用完整 actor 圖集切換，換護甲先反映圖示與能力。可見的逐件護甲／頭飾換裝是後續獨立功能，不假裝同步 kit 即已完成。

### 資產與記憶體起始預算

- 主角三種武器版本＋兩名 AI 各需圖集，實戰只常駐當前主角版本及兩名 AI。
- 起始驗證規格：192 px 格、8 個完整方向、idle 2／walk 4／attack 4／hit 2／death 6 格，共 144 格，RGBA8 約 20.25 MiB／角色。左右持武器不對稱時不鏡像。
- 三名常駐角色約 60.75 MiB；一般怪採較小圖集及 4 方向，Boss 視需求 4／8 方向。每區只載需要的集合。
- 起始目標：角色圖集常駐不超過 96 MiB、全場貼圖不超過 160 MiB、首包下載不超過 25 MiB。這是資產預算，須依實際圖與目標手機量測修正。
- 桌機目標 60 fps、手機至少穩定 30 fps；驗收包含 3 隊員、1 Boss、8 雜兵、技能與 UI，不拿空地圖 FPS 當成績。
- 角色圖先 import 成外部 Texture2D／sheet 資源，scene 只引用；`.tscn`／`.tres` 不內嵌 Image 資料。
- 不在本輪生成資產。製作前另列批次、用途與尺寸，再依專案規則選直接生成或提供 opt image 提示詞。

### 畫面配置

```text
┌─ 樓層／遠征狀態 ──────────────────────────── 設定 ─┐
│ 隊伍 HP     │                                      │
│ 隊長＋2 AI  │          2.5D 世界                    │
│ 戰術／補給  │     移動、狩獵、戰利品、Boss 預警      │
│             │                                      │
├─────────────┴──────────────────────────────────────┤
│ 任務摘要／收益 │ 技能狀態 │ 自動狩獵 │ 補給 │ 撤退 │
└────────────────────────────────────────────────────┘
```

桌機可展開右側任務／背包面板；手機橫向只保留短摘要，點開 drawer，不常駐整片文字遮擋戰場。主要觸控按鈕至少 44 px，危險與掉落不只靠顏色識別。

另有「遠征帳本」省電視圖：停止更新 3D viewport，顯示數據與事件；domain 仍以相同時鐘運作。它不改收益、難度或冷卻。手機直向顯示旋轉提示並暫停實戰。

## 11. 模組、資料與可編輯 scene

```text
命令／資料表 → 純模擬與 RNG → 遊戲狀態＋事件
                    │                │
                    ↓                ├→ 2.5D scene／UI／音效
               存檔與死亡日誌        └→ 戰鬥紀錄／任務
```

| 模組 | 責任 |
|---|---|
| domain/simulation | 狀態機、固定步進、事件排程與 RNG；不依賴 UI、相機或物理 FPS |
| domain/combat、skills、party_ai | 傷害、時間軸、Buff、目標與 AI 決策 |
| domain/inventory、quests、progression | 物品實例、原子命令、任務領取、升級與傳承 |
| domain/save_service、commission | schema、快照、死亡日誌、離線 job／receipt |
| presentation/world、actors | 事件映射到角色、導航呈現、鏡頭與特效；不自行給掉落 |
| ui | HUD、任務、背包、工坊、小隊、紀念碑、委託；只提交命令 |

必要 scene：`main.tscn`、`town.tscn`、每層狩獵／Boss 場景、`party_actor.tscn`、`monster_actor.tscn`、`drop_item.tscn`、`hud.tscn`、`inventory_panel.tscn`、`quest_panel.tscn`、`forge_panel.tscn`、`memorial_panel.tscn`、`commission_panel.tscn`。主要場景在編輯器即可看到代表性角色與版面，不靠 `_ready()` 建出整個畫面。

用 anchor／Container／scene offset 管版面；腳本只處理內容、訊號與必要安全區縮放。新建或大改場景用 Godot pack/save，驗證 owner、instance 引用及節點數；正常開啟不重跑產生器。

### 儲存最小形狀

```text
SaveEnvelope
├─ schema_version、revision、next_event_id、rng_state
├─ Profile：倉庫、圖鑑、營地、配方、手記、紀念碑
├─ Run：id、狀態、等級／EXP、隊員、物品、任務、戰鬥排程
└─ Commission：job id、run id、時間、物資、receipt
```

- 金幣、物品量、HP 與嘗試數永不為負；所有命令先驗證，再一次套用。
- reward、enhance、death、commission 各有 idempotency key。重試不能再擲一次強化或重給獎勵。
- 死亡先持久化含 run ID 與事件 ID 的 tombstone，再寫主快照。載入舊備份前先合併 tombstone，禁止把已死 run 當活人恢復；主檔寫失敗時保留死亡日誌供恢復完成。
- 若死亡日誌無法存入，鎖住後續遊戲操作並提供重試／完整匯出，不回到可繼續農的狀態。
- Web 版須確認 IndexedDB／IDBFS 持久化回調；不能只把記憶體檔案寫成功當磁碟成功。匯出包含 Profile、Run 及死亡日誌。

## 12. 建置順序與驗收

| 里程碑 | 可交付物 | 過關條件 |
|---|---|---|
| M0・RO 戰鬥切片 | 見 [ro-slice.md](ro-slice.md)：一個狩獵區、隊長＋2 AI、點敵人追打與自動狩獵、升級與補藥、HD 採樣比較 | ro-slice.md 的 7 條驗收；方向／腳底／遮擋正確；手機可讀 |
| M1・單層閉環 | 出城、狩獵、補血、撤退、回城、1 Boss、死亡 | 能靠準備改變勝負；死亡與回城資產邊界可預測 |
| M2・養成與內容 | 3 流派、技能格、換裝、強化、主支線、AI 戰術 | 任務不能重領、技能不錯流派、強化不改模板；AI 不是裝飾 |
| M3・長期循環 | 倉庫、手記、紀念碑、離線委託、復原 | 關頁再開保持死亡；離線不能重領；下一代有選擇但非滿級 |
| M4・3 層首版 | 內容清單與完整 Web 包 | 新手完整測試、目標裝置效能、缺字與橫向瀏覽器驗證 |

### 必須寫進測試的邊界

- 固定 seed 與命令序列，在不同 render FPS 下產生相同模擬結果。
- 0 HP、不足一擊、同時 Boss／隊長死亡、撤退結束同時受傷。
- 門檻上／下、無藥、HOT 存續、兩名隊員搶最後一瓶、庫存為零。
- 技能停用／重排不重設 CD；多段同事件不重複熟練；換武器清理非法技能格。
- 收集品被賣／被另一任務消耗；獎勵重試；一次 EXP 連升多級。
- 強化失敗也扣正確資源、重試不重抽、鎖定裝備不可批售。
- 死亡各持久化階段中斷、主檔壞、備份尚為活人、重複載入 tombstone。
- 離線 0／負時間／超 8 小時／重複領取／不同 run；凍結實戰不偷補 HP 或 CD。
- 相同 scene 兩個 actor 材質不互染；編輯器改 UI 靜態間距後執行仍保留。
