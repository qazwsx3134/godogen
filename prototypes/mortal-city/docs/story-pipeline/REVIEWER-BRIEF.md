# 審查員派工單：魔都傭兵（mortal-city）劇情委託草稿

你要審查一份 AI 寫的劇情委託草稿。專案根目錄：`/Users/peter/repo/godot/godogen/prototypes/mortal-city`。派工時會給你**草稿 id**。你沒看過寫作過程，也不需要：只依這份評分表判斷。

## 1. 目標

作者會在遊戲裡讀草稿全文，再參考你的報告決定收下、退回或改寫。你的工作是把**作者讀的時候會卡住的地方**先找出來，每一條都能讓作者直接對照原文。**只判定、不修改**：不要動草稿或任何其他檔案。

## 2. 先讀

- 草稿：`story-drafts/<id>.json`（寫手的設計說明 `story-drafts/<id>.writer.md` 可以看，但不能拿來替草稿辯護：玩家看不到它）。
- 規則與世界：`CONTEXT.md`、`docs/DICE-POOL-SPEC.md` 第 3、5 節、`src/content/cases.ts` 的型別註解、`src/content/data.ts` 的 `FIXERS`、`src/content/districts.ts`、`src/content/items.ts` 的 `ITEMS`。
- 對照的既有案子：`src/content/cases.ts`（01、02）、`src/content/cases_wangan.ts`（03、06）。寫手派工單 `docs/story-pipeline/WRITER-BRIEF.md` 是寫手被要求的標準，你用同一套標準審。

## 3. 評分表

每條給 **PASS** 或 **FAIL**；FAIL 要**引用原文**（欄位路徑＋文字），並寫一句建議改法。沒有問題的條目一行帶過。

**A. 機器檢查**：執行 `pnpm story:check story-drafts/<id>.json`，貼最後的統計與所有 ERROR。錯誤不是 0 就直接判「不通過」，其他條仍然審完。警告逐條判斷要不要修。

**B. 文字和欄位對得上**（遊戲照欄位結算，文字只是描述）
1. 每個 `danger.options[].text`：寫了拿到保單→有 `lifeline`；寫了縫傷口→有 `heal`；寫了被拍到、警察記住、通緝→有 `heat`；寫了拿到錢的多寡和 `reward` 相稱；撤離選項的文字真的不會死。
2. 限定做法的選項（`approach`）文字接得上那條路（例如只有駭入才看得到的選項，內容要用到你已經在系統裡）。
3. 器材選項的 `needs.label` 和文字用到的器材一致；屬性選項的屬性和文字的行為一致（沉著＝冷靜說服、體能＝硬扛）。
4. `danger.body` 寫的現場人物＝`threat` 或「打」選項的對手；沒有追兵時，現場真的沒有人。
5. 每個做法的 `beats`：`attr` 和場面的行為相符；`costs` 的文字和 `kind` 相符（寫被拍到卻是 `injury` 就 FAIL）；`fail` 的種類和 `out.fail` 描述的惡化相符。
6. `out` 四句的好壞順序正確：`crit` > `clean` > `cost` > `fail`。

**C. 邏輯**
1. 時間：`posted` 與 `replies[].at` 的先後、`body` 與危險節點講的時間點（例如「還要九十秒」）前後一致。
2. 地點與人物：中間人屬於那個街區；人物的身分、口吻和既有案子一致；沒有人知道他不該知道的事。
3. 因果：委託為什麼發、危險節點為什麼發生、每個選項的結果為什麼成立；`requires`／`variants` 的前因後果通順。
4. 每個做法的 `summary` → `autoLog` → 兩個場面 → 危險節點，接起來是同一件事、同一個地點。
5. 選項之間不矛盾（例如撤離選項說「箱子留下」，另一個選項卻預設你已經把箱子交出去）。

**D. 世界觀**：不引入遊戲沒有的系統（新貨幣、新道具類型、新屬性）；企業、組織、武裝醫療隊、救命保單、神經錯亂的用法符合 `CONTEXT.md` 與既有案子；科技程度一致。

**E. 用字**
1. 繁體中文、台灣用語，沒有簡體字、錯字、語病；標點用全形。
2. 標準用語：「防火牆」（不是黑冰／ICE）、「攻擊」（不是咬）、不用英文黑話、不寫百分比或 HP。
3. 句子長度與節奏符合既有案子；手機一屏讀得完（機器檢查的字數警告要看）。
4. 語氣：冷硬、短句；人物台詞有個性但不中二。

## 4. 輸出

寫到 `story-drafts/<id>.review.md`（**這個檔出現就代表你做完了**），格式：

```markdown
# 審查：<標題>（<id>）

結論：通過｜有條件通過｜不通過

## 給作者的三個重點
1. …（最影響閱讀或邏輯的三件事）

## A. 機器檢查
…

## B. 文字和欄位
- B1 PASS／FAIL：… 原文：`danger.options[2].text`「…」→ 建議：…
（B2～B6 同樣格式）

## C. 邏輯
…

## D. 世界觀
…

## E. 用字
…
```

- 「結論：」這一行照格式寫，遊戲的草稿分頁會讀它。
- 判準：機器檢查有錯誤、或 B／C 有會讓玩家結算或理解錯的 FAIL＝不通過；只有用字或小邏輯問題＝有條件通過；全部 PASS＝通過。
- 在對話裡只回：報告路徑＋結論＋3 行摘要。
