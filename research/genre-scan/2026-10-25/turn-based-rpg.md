# 回合制戰術 RPG（老鼠冒險者）分析與功能拆解

資料：`research/in-progress/trun-base-rpg/` 8 張截圖（1920×1080，2026-10-25 13:16–13:19，本機保留，不進 git）。標記同 `games.md`：**〔圖〕**實見／**〔推〕**推論／**〔未〕**未驗證。畫面沒有遊戲名稱，下稱「本作」；地名「前往拉塔福尼亞的路」、主角「拉姆斯」都是畫面上的字。

## 類型判斷

**方格戰術 RPG × 「先編排、後執行」的回合制**（同類參考：Into the Breach 的意圖顯示、FF12 Gambit 的指令串、Wildfrost 等遊戲的行動預告）。〔圖〕證據：
- 戰場是方格（131939 黃色移動範圍格），有部署階段（131823「戰鬥配置」）。
- 每個角色每回合排 **4 格技能的順序**，拖放或按箭頭調整（131926 教學字幕）；按右下紅色 ▶ 才執行。
- 左邊是依「先制」排序的行動順序（12／11／11／10），每個頭像旁邊顯示**這回合要用的技能圖示**：敵人的意圖是公開的。
- 左下 ▶ ◀◀ ▶▶ ×1 是**回放與速度控制**〔推〕：執行階段是自動演出，可以倒帶重看。

所以它不是傳統「輪到誰、選一個指令」的 JRPG，而是**每回合寫一段程式，然後看它跑**。

## 遊戲功能拆解

```
本作
├─ 敘事層
│   ├─ 書信開場（致母親）                       〔圖〕
│   └─ 戰鬥前對白泡泡（準備戰鬥！！）            〔圖〕
├─ 探索層（大地圖）
│   ├─ 地名標題、地圖、任務                     〔圖〕
│   ├─ 隊伍頭像列（隊長王冠）                   〔圖〕
│   └─ 共用背包＋負重上限 0/100                 〔圖〕 → 角色「負重上限」屬性
├─ 戰鬥層
│   ├─ ① 部署：可放置區、雙方棋子計數          〔圖〕
│   ├─ ② 回合準備（核心）
│   │   ├─ 行動順序條：依「先制」排序＋各自本回合技能（敵我都公開）
│   │   ├─ 每人 4 格技能串：拖放／箭頭排序、每格開關
│   │   ├─ 行動力 5 點（黃點）× 技能消耗          〔推：每個技能扣 AP〕
│   │   ├─ 移動力 4m、移動範圍格
│   │   ├─ 每回合道具 1 次 (0/1)
│   │   └─ 資訊查詢：點敵人看能力值／裝備／特性／戰術
│   ├─ ③ 執行：按 ▶ 後依先制順序自動跑完        〔推〕
│   └─ ④ 回放：▶ ◀◀ ▶▶ ×1                    〔推〕
└─ 角色養成
    ├─ 能力值 10 項（攻、AP、物防、魔防、移動、閃避、暴擊率、暴傷、負重、先制）
    ├─ LP（點數，推：學習／升級用）            〔未〕
    ├─ 裝備欄、特性 0/5
    └─ 註冊戰術 1/10：可存多套指令串            〔圖：敵人有；我方〔未〕〕
```

一回合的流程：

```
部署 ─→ 回合準備 ──────────────────→ 執行 ─→ 回放(可選)
         │ 看敵人意圖（行動順序條）       │
         │ 排自己的 4 格技能串、扣 AP      │ 依先制輪流跑每人的技能串
         │ 用道具（0/1）                  │ 敵人照「註冊戰術」跑
         └─ 按 ▶ ──────────────────────→ └─→ 下一回合（回到回合準備）
```

## 值得學習

1. **敵人的 AI 就是玩家看得懂的指令串**〔圖 131857〕。「基本戰術：攻擊 → 移動」既是 AI 的實作，也是 UI 的說明。玩家讀了就能預測敵人；設計者寫敵人時也只是在排列技能。**一套資料，同時是 AI 與教學**。
2. **意圖公開＋先制排序**〔圖〕：左側順序條直接畫出「誰先動、用什麼」。玩家的樂趣變成排順序來搶先手、躲攻擊，和 Into the Breach 同一路線。
3. **技能串的編輯手感**〔圖 131926／131939〕：拖放加箭頭鍵兩種操作；拖動時有插入線；格子之間的箭頭表示順序；教學是一個真實的小任務（「把這格移到移動前面」），不是一段說明文字。
4. **部署階段用棋子計數**〔圖 131823〕：藍 3、紅 2 一眼看出人數差。
5. **負重同時存在於背包（0/100）與角色屬性（負重上限）**〔圖〕：裝備重量會影響帶多少東西〔推〕。
6. **資訊卡分頁 Q／R**〔圖〕：能力值頁和戰術頁共用左半的角色圖與裝備，只換右半。和 Shardbreakers 的 Q／E 分頁同一種模式（見 `ui-style-catalog.md` 的 `tabbed_modal`）。

## 與本 repo 的關聯（〔推〕）

| 本作功能 | 可用在哪 | 現成的東西 |
|---|---|---|
| 指令串 AI（註冊戰術） | skybound-blades 的守層者招式、hero-horde-idle 王的預警 | skybound 已有 telegraph 預警，可改成「把王的招式串公開給玩家看」 |
| 先制排序＋意圖顯示 | 任何回合制原型 | 無；可做成 godot-kit 模組 |
| 技能串編輯 UI | 新原型 | `card_draft.tscn` 的牌列可改造；無拖放排序元件 |
| 回放 | 需要可重播的確定性模擬 | skybound 的 50 ms 固定步長、hero-horde-idle 的 `push_sim` 都是確定性的，具備回放的前提 |

## 可以抽成模組的候選（尚未實作）

1. **`action_queue.gd`**：每個單位一條長度 N 的技能串。介面包含：加入、移除、交換位置、依 AP 檢查合法性、每格的啟用開關；`resolve(units, rng)` 依先制排序後逐格執行，每步輸出一筆事件給回放用。
2. **`initiative_bar` scene**：依先制排序的頭像列，旁邊顯示本回合意圖圖示，平手時固定順序。
3. **技能串拖放元件 scene**：可拖放、有插入線、格間箭頭、左右箭頭鍵（手機與鍵盤都能用）。
4. **`tactics` 資料格式**：敵人與我方共用的「註冊戰術」JSON（多套指令串加啟用條件），讓 AI 和 UI 讀同一份資料。
