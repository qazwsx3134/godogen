## 主要判斷

這款遊戲的驅動力是「取得資源 → 投資防線 → 看到防線與輸出改變 → 挑戰新怪潮」。值得參考的不只是外觀，而是它把戰鬥、經濟、解鎖和收集串在同一個畫面：城堡直接長出塔架、單位直接站到配置位置、戰鬥時底欄改成傷害統計與技能列。

```
配置英雄／防禦塔／主炮
          ↓
自動普攻＋手動瞄準／英雄技能 → 波次推進
          ↓                       ↓
金幣／鑽石／EXP             任務與設施解鎖
          ↓                       ↓
升城／升級／招募 ← 礦洞被動收入與其他養成
          ↓
更多槽位／更強技能／更多組合 → 再次挑戰
```

圖是依實機入口整理的關係；裝備實際掉落率、離線公式及後期資源來源尚未驗證。

## 戰鬥與 build 的設計

### 三類輸出單位的操作分工

英雄和防禦塔承擔自動輸出，主炮讓玩家有直接介入的手段。這讓戰鬥可觀看，也可在關鍵時刻親手補強。六種尋敵優先權把「同一隊伍」變成可調整的策略，而不需要每個角色都由玩家微操。

尋敵策略值得獨立成系統：AOE 選高密度位置、單體爆發優先 Boss、對空單位優先飛行敵人，可能產生比純攻擊加成更大的差異。但本作目前選單只證明有六個選項，沒有證明其內部評分演算法。

### 實機技能樣本

| 單位／技能 | 面板描述的規則 | 證據 |
|---|---|---|
| 火焰炮手：焰矢射擊 | 普通攻擊為 100% 火屬性傷害 | 16 |
| 火焰炮手：砰砰砰！！ | 火箭雨，242% 火屬性傷害，使受擊敵人獲得燃燒；顯示 12 秒、60 MP | 15，當時英雄 Lv.5 |
| 火焰炮手：燃燒大師 | 攻擊命中使敵人獲得燃燒；提示 4 星解鎖 | 17 |
| 烈焰塔：豪火球 | 對範圍內敵人造成 258% 火屬性傷害，12 秒 | 21，塔 Lv.1 |
| 破城弩車：銀核弩射 | 130% 物理傷害 | 22，主炮 Lv.1 |

這些係數是當時 tooltip 的顯示值，不可當成所有等級固定值。火焰炮手與塔帶來火屬性、燃燒、範圍傷害等構築關鍵字；被動在 4 星開放，讓星級同時改變數值與行為。

**修正早期估算：**若以弩車面板攻擊 12、頻率 1.5 次／秒和技能 130% 計算，無其他修正的名目值應是 `12×1.5×1.3=23.4／秒`，而不是只乘攻擊與頻率的 18。這仍不是實測 DPS，會受命中、攻擊停止、瞄準、敵人抗性等影響。

燃燒的疊層、持續時間、傷害來源歸屬、對 Boss 的適用性與重複施加規則未取得。不能把關鍵字直接當成已知的持續傷害公式。

### 從傷害欄讀到的 UX 問題

戰鬥底欄會出現各單位的直柱與頭像，方便比較貢獻；但「DPS總量傷害」混用了速率與累積量名稱。自己的遊戲應明確標示統計時間窗與歸因，並納入控制、增傷、治療等非直接傷害貢獻，避免玩家只保留最高傷害角色。

## 成長、經濟與內容節奏

### 三個會互相推動的循環

```
短循環：瞄準／施法 → 擊殺 → 浮字與掉落
中循環：守住一波 → 升級／新槽位 → 更快清怪
長循環：招募 → 碎片升星 → 新被動／build → 後期設施
```

礦洞是循環之外的穩定收入來源，降低卡關時的資源斷流。實機可見未開戰時金幣仍逐步增加；因有人類勞工，不宜把這現象直接解釋為「離線收益」。

|---|---|---|
| 城堡 Lv.1～5 HP | 105／160／215／270／325 | 此區間每級 +55，不能外推後期。 |
| 城堡 Lv.1～5 MP | 60／70／80／90／100 | 此區間每級 +10。 |
| 城堡下一級費用 | 150／300／450／650／800 | 不符合全段固定加值，完整公式未知。 |

| 升星當前預覽 | 10 碎片、攻擊 +5% | 是當前階段預覽，不是所有星級一律相同。 |
| 礦洞人類線 Lv.1 | 2,400 金幣／h | 理論 40／min；未驗證關程式後收益。 |

| 第一個任務樣本 | 擊殺任意怪物 20，金幣 +500 | 下一項可見任意英雄 Lv.10、金幣 +1,000；非完整任務鏈。 |

### 招募與升星是同一條經濟鏈

招募設施在城堡 Lv.5、100 金幣可開。單抽 10 鑽石、十抽 100 鑽石：畫面沒有顯示十抽價格折扣。單抽後進度由 0/20 變成 1/20；招募說明明確表示卡池會隨次數升級並提高稀有機率，重複角色轉成碎片。

當時 Lv.1 卡池的機率表：

| 等級 | 該級總機率 | 池中數量 | 依均分文字換算的單一角色機率 |
|---|---:|---:|---:|
| 鑽石 | 0.8% | 5 | 0.16% |
| 黃金 | 6.4% | 8 | 0.8% |
| 白銀 | 92.8% | 10 | 9.28% |

總和 100%。上述單角值是算術換算，不是大量抽樣驗證；卡池升級後的完整機率表、保底與特殊獎勵規則未取得。願望單 +100 鑽石只是介面文字，這輪沒有提交願望單或驗證發獎。

**設計分析：**初次抽到新單位擴大配置選擇，重複抽到則推進星級；卡池自身等級又形成第二條長期進度。若借鑑，應讓玩家看得到當前機率與進度，並讓基礎陣容不依賴難以控制的隨機結果。

### 解鎖門檻如何安排內容

本版把不同成熟度的需求綁到不同系統：城堡等級開訓練／天賦、英雄等級開寶物、已有裝備數開鐵匠、波次開黑市。這比「所有系統都等主線等級」更能引導玩家接觸多條成長線。

問題是門檻只在點開剪影後才顯示。自己的 UI 可在鎖定入口直接顯示「城堡 20」「裝備 5 件」等短條件，並提供追蹤下一個解鎖的功能。

## UI layout：可直接轉成設計規格的部分

### 戰場主畫面

```
┌────────────┬───────────┬────────────┐
│ 城堡 HP    │ 波次／狀態 │ 城堡 MP    │
├────────────┴───────────┴────────────┤
│                  遠景／天空                     │
│       英雄、城堡、主炮        怪物從右側進場     │
│ 任務      防禦塔／地面作戰帶                     │
├────────────┬───────────┬────────────┤
│ 資源／養成 │ 開始戰鬥   │ 設施快捷入口│
│ 戰中傷害圖 │ 戰中控制   │ 戰中技能列  │
└────────────┴───────────┴────────────┘
```

實機 1080p 近似量測：頂部狀態高約 150px；下方控制列由 y≈855 起、約 225px；地面交戰集中 y≈740～850。中間空間容納建築擴張、高塔、遠程彈道與飛行敵人。比例只是截圖估算，不是原作 anchor 或原始解析度。

主要視線依序是波次／危險→戰場接敵→施法與投資。戰前戰中底欄替換，控制列的整體位置保持，能減少操作搜尋。美術上厚重石／金屬框架與陰影把可操作區與場景分開；大面積天空提供喘息，但初期角色少時顯得空。

### 單位雙頁面板

左頁：名稱／星級、角色展示、六格屬性、技能、裝備、等級與四個操作。右頁：類別 tab、單位卡片清單。底部：編隊預設與編隊操作。

這個模板把英雄、塔、主炮統一，方便橫向比較。可借用資訊結構，但建議修正三點：屬性 icon 永遠可查文字；升級前有明確成本和前後差；空列表／未取得隊長不要保留容易誤認的上一類資料。

### 彈窗與重用樣式

- 設施解鎖：標題、設施圖、名稱、成本、主按鈕、條件。訓練、天賦、寶物、鐵匠和黑市共用相同結構。
- 技能 tooltip：技能圖＋名稱＋冷卻／MP＋敘述；Alt 固定後可查看關鍵字。適合延伸成嵌套說明，但需要清楚焦點管理。
- 升星：目前階段、碎片進度、提升預覽、主要行動、一鍵選項。它是獨立投資確認畫面。
- 倉庫：類別 tab、內容網格／空狀態、批次管理。空狀態目前只說沒有物品，自己的遊戲可補充取得途徑。
- 招募：卡池等級進度、機率入口、角色視覺、跳過動畫、單抽／十抽、結果展示。機率說明可讀性值得保留。
- 礦洞：場景展示＋兩列工人／槽位＋各列升級成本；把純經濟進度視覺化為在工作的角色。

## 美術、Shader、渲染和效能

本機檔案結構可確認 Unity／IL2CPP，無法確認 Built-in／URP、材質名稱或 Shader 原始碼。請勿把下面的重建方案當成對方技術棧。

截圖 07 是代表性效果：亮黃光束核心、多條橘紅外緣、火焰噴發和命中區，集中在低對比背景上；這形成亮度與方向性對比。單幀不能判定它是拉伸 sprite、LineRenderer、mesh、粒子或自訂 shader，也不能證明用了 Bloom。

可以在 Godot 分層重建：背景低對比圖層；像素世界保持一致採樣；光束用 Line2D／帶 UV 的 mesh 或獨立 sprite；火焰使用 AnimatedSprite2D 或粒子；浮字獨立。先把形狀、時序、色彩做好，再決定是否需要 shader。

| 元素 | 可行方案 | 成本／驗證重點 |
|---|---|---|
| 角色普攻 | SpriteFrames／AnimatedSprite2D | 出手幀、命中時刻、腳底對齊，不只循環播放。 |
| 火焰／升級 | 序列幀＋GPUParticles2D／CPUParticles2D | 透明重疊、粒子上限、物件回收。 |
| 弩箭拖尾 | Line2D 或淡出 trail sprite | 尾跡別遮住敵人；按武器區分視覺。 |
| 光束 | 亮核心／外緣分層，必要時 UV 流動 shader | 亮度受控，確認低效能 renderer 的退化方案。 |
| 受擊閃色 | canvas_item shader 的 tint／flash 參數 | 這是建議，本輪沒有獨立確認原作受擊 shader。 |
| 輪廓與選取 | UI 外框／sprite outline | 卡片外框不等於原作使用 outline shader。 |
| UI 框體 | 自有九宮格圖片＋文字節點 | 保留四角；不能把整張面板連文字一起縮放。 |

本次 overlay 在不同畫面顯示約 22～60 FPS，但存在前景／背景、輸入操作與錄製工具干擾，沒有控制測試條件，不可拿來下效能優劣結論。也未執行 GPU capture 或 profiler。

開發自己的版本時，分別量測：尋敵／碰撞 CPU 時間、單位與投射物數、透明 overdraw、材質切換、浮字節點數、GC／配置、背景限幀和倍速穩定性。畫面可讀性與後台耗電，對放置遊戲和特效華麗程度一樣重要。
