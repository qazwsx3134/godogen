# 流浪仙境研究 → Godot 參考規格

這份文件是設計建議，**不是原作原始碼結構**。用於你後續討論 UI、component、遊戲機制與渲染的實作分工；本次沒有建立或修改 Godot 遊戲。證據與數值見[完整研究報告](完整研究報告.md)。

## 1. 最小可玩範圍

先做一個職業、一張地圖、兩種菁英、一個限時頭目、一個訓練假人。技能盤 6×6，但先開 8 格；3–5 主動、4–6 輔助足以驗證拼圖是否好玩。第一版不需要完整轉職樹、全卡片、排行、雲端或多角色副本。

成功條件：玩家能放入主動、正確連動輔助、讀懂換裝的輸出／生存差異、用假人驗證，並至少有兩種構築能過關。UI 除了顯示變強，也需解釋原因。

## 2. Scene 與元件分工

```text
GameRoot
├─ WorldRoot (Node2D)
│  ├─ MapVisual
│  ├─ Actors (Y-sort)
│  ├─ GroundWarnings
│  ├─ Projectiles
│  └─ CombatVFX
├─ Services
│  ├─ CombatResolver
│  ├─ BuildService
│  ├─ InventoryService
│  └─ SaveService
└─ Interface (CanvasLayer)
   ├─ CombatHUD
   ├─ ManagementShell
   │  ├─ MainTabs
   │  └─ FeaturePanel
   ├─ ItemDetailDrawer
   ├─ ModalHost
   └─ ToastHost
```

| 元件／scene | 責任 | 必須支援的狀態 |
|---|---|---|
| CombatHUD | 血量、等級、貨幣、藥水、頭目與效率 | 一般、挑戰、死亡、訓練；關鍵讀招不被聊天遮擋 |
| ManagementShell | 主頁籤、返回、面板與捲動位置 | 寬螢幕並排、窄螢幕上下；單一主要捲動層 |
| GemBoard | 顯示格子與配置，派發操作意圖 | 未開格、空格、佔用、可放、不可放、已連動 |
| GemPiece | 形狀、旋轉、類型與標籤 | 拿起、預覽、放下、交換、取消 |
| LinkPreview | 解釋連動結果 | 成功、未相鄰、標籤不符；多目標收益 |
| GemTray | 未放寶石、分類與搜尋 | 空、滿、缺圖示、重名、變異、跨職業 |
| BuildPresetBar | 配置儲存／複製／切換 | 當前、草稿、未儲存、挑戰中不可套用 |
| StatRow | 基礎、裝備、天賦、最終數值 | 增益、減益、達上限、被轉換、失效來源 |
| ItemSlot | 品質、孔、鎖、裝備建議 | 空、未達等級、雙手限制、其他構築使用中 |
| ItemComparison | 換裝前後差值與限制 | 輸出、生存、條件效果未計入 |
| InventoryFilters | 篩選、排序、保留規則 | 無結果、批次預覽、保護理由、規則衝突 |
| TalentGraph | 節點、路徑與成本 | 未連接、可投、已投、終極上限、模擬草稿 |
| TrainingPanel | 假人設定、時間窗與來源統計 | 重置、暖機、記錄中、可比較結果 |
| MapCard | 等級、擊殺、首領與獎勵 | 未解鎖、可刷、可挑戰、已通關、當前 |
| NPCDialog | 城鎮服務與門檻 | 可用、鎖定理由、資源不足、返回原頁 |
| GuidePanel | 短導覽與詳細查閱 | 首次提示、搜尋、規則來源、版本 |

Control 元件以 Container 管理佈局；標籤使用可換行文字，避免固定最小寬度。盤面格子維持正方形，必要時用獨立專注視圖。物品詳細窄螢幕採底部抽屜，桌面可改側欄；兩者共用同一資料模型。

## 3. 資料模型建議

| Resource／資料 | 關鍵欄位 |
|---|---|
| SkillDefinition | stable_id、技能標籤、元素、冷卻、基礎倍率、傷害類型、觸發限制 |
| GemDefinition | stable_id、格子相對座標、可旋轉、類別、支援標籤、技能引用 |
| GemInstance | instance_id、definition_id、變異資料、來源、鎖定 |
| BoardLayout | 版本、已開格 mask、寶石實例與原點／旋轉 |
| SupportModifier | 受益對象、加算／乘算／覆寫、條件、上限、來源 ID |
| BuildSnapshot | 裝備、盤面、共用天賦、職業天賦、版本 |
| ItemInstance | 品質、基底、固定額外素質、精煉、孔、卡片、保護狀態 |
| TalentDefinition | 節點、連線、成本、互斥、終極、效果、轉換順序 |
| StatusInstance | 狀態、來源寶石、施加者、快照傷害、層上限、剩餘時間、抗性 |
| CombatEvent | 施加者、目標、技能／寶石、傷害階段、觸發鏈、時間 |
| SaveEnvelope | schema_version、遊戲資料版本、角色、帳號共用資料、校驗資訊 |

Definition 與 Instance 分離，避免同一技能多顆寶石互相覆寫冷卻。天賦草稿與生效配置分離；UI 拖曳預覽不能直接修改戰鬥資料。

## 4. 關鍵機制契約

### 盤面與連動

以整數格座標運算旋轉與佔格，不以畫面像素判碰撞。先驗證邊界、已開格與衝突，再建立鄰接圖，最後依標籤解析支援。單顆寶石多條邊接觸同一主動時，應定義「算一次」或「依接觸數」；不要讓 UI 視覺偶然決定規則。

交換、移動與取消採原子操作：成功整筆提交，失敗保留原配置。輸出明確失敗原因。每次換盤重新推導有效技能，不累加舊 modifier。

### 戰鬥與觸發

集中處理命中→傷害→狀態→後續觸發。事件攜帶來源與鏈深度，明確禁止哪些觸發可再觸發自身。區分普攻、技能、持續傷害、反射、召喚與生命支付；生命支付不能自然被當受傷事件。

乘算、加算、轉換、覆寫與上限應有固定順序。保留 debug breakdown，讓 UI 與訓練場讀同一份結果。支援不影響戰鬥結果的文字／粒子上限。

### 狀態與召喚

毒層獨立計時，顯示可合併；控制抗性按來源記錄，不能因寶石顯示同名就誤合併。召喚需分自主輪次、共享命中計數、額外攻擊與來源快照，切換盤面／死亡／離戰如何清除要明確。

### 比較與模擬

裝備評分需註明敵人、攻擊頻率、觸發覆蓋率等假設。無法估計時列出未納入效果。模擬器先算合法性與差值，再讓玩家套用；挑戰中鎖定的是提交動作，而非禁止閱讀。

## 5. 渲染與品質分級

| 層級 | 保留內容 | 可降低內容 |
|---|---|---|
| 必要資訊 | 危險圈、單位、彈道、關鍵狀態、血量 | 不應因低畫質消失 |
| 戰鬥回饋 | 命中閃色、技能輪廓、暴擊提示 | 同屏數量、光暈大小、文字密度 |
| 氛圍裝飾 | 暗角、霧、餘燼、拖尾、背景粒子 | 低畫質可關或降低更新頻率 |

Godot 可用 AnimatedSprite2D、GPUParticles2D、CanvasItem shader 與 Control 組合完成類似視覺。先用貼圖動畫達成可讀效果，再決定是否需要 shader；不要為了「有 shader」增加全螢幕 pass。

像素精靈需統一縮放與取樣策略；字體 UI 可維持清晰，不必全部像素化。碰撞與傷害判定獨立於動畫粒子，關特效不能改變輸出。大量飄字、彈道、粒子應有池化或限額策略，並用實際幀時間驗證。

## 6. 有價值的驗證案例

- 相同輔助碰到同一主動兩個格邊，不應意外重複給加成。
- 旋轉四次回到原形；非法放置、交換取消不丟失寶石。
- 同名主動不同實例可獨立冷卻，持續光環依規則只生效一次。
- 暴擊觸發與反射不能無限遞迴；額外施放與召喚輪次不重複計算。
- 存檔讀回後，配置 ID、卡片、倉庫、冷卻恢復政策與模擬草稿不混用。
- 同一戰鬥在高／低畫質結果一致，危險訊息仍可辨識。
- 長名稱、無圖示、大量物品、文字放大與窄視窗不造成必讀句子橫向捲動。

這些測試對準實際系統風險；單純驗證 Label 顯示某常數的測試價值有限。

## 7. 開發順序

1. 自動戰鬥與可觀察的命中事件，先做假人統計。
2. 盤面合法性、主動／輔助與連動預覽。
3. 裝備、比較與可回復的配置切換。
4. 一個有預警的頭目與地圖解鎖。
5. 小型天賦分支與免費重配，驗證構築多樣性。
6. 存檔版本、規則資料共源與效能品質分級。
7. 核心已證實好玩後，才擴職業、收集與長期內容。
