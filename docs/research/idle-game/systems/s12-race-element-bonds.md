# S12 種族與屬性羈絆

狀態：研究完成／製作規格草案；本新案尚未審核或整合實作，repo既有基礎另計。優先級：Vertical Slice；主要里程碑：M3。

既有module／prototype、差距與程式位置見[30系統重用盤點](../reuse-audit.md)。

## 1. 原作證據與未知

O：E08按2名／3名同種族或同屬性給加成；精靈、神聖有不同效果，E03可顯示無羈絆。U：重複物種、死亡與門檻累計規則。 證據ID對照[素材分析](../00-reference-analysis.md)；未標O的實作與規則均為P提案。

## 2. 用途與玩家價值

讓單一高稀有角色與隊伍整體效益形成取捨；玩家有收集下一個角色的具體理由。

## 3. 要做的內容與規則

M3先做2個種族＋2個屬性，2／3人門檻；一種純數值效果、一種改變關鍵詞參數的效果。

P：只計有效上陣的不同物種，取最高門檻效果；種族與屬性各算，兩類可並存。開戰凍結計數，戰鬥中死亡先不失效；這些是新作候選規則，不是O。

## 4. 資料、數值與持久化

BondDefinition：tag_type、tag_id、thresholds、effect_ids；BondSnapshot：member_uids、unique_species、active_tier、modifier_sources；影響技能參數時有明確欄位。

數值與單位以本系統正式F／D文件為準；共通候選計算見[數值模型](../balance-model.md)。持久狀態經S23的快照介面保存，定義資源不承載玩家狀態；顯示用暫態不自動列入存檔。S23是儲存適配器，這項整合不是領域系統反向依賴它。

## 5. Godot分工與介面

BondEvaluator輸出Modifier及RuleParameterOverride，不在自身套用第二份屬性。bond_row.tscn列目前人數、下一門檻與有效成員，character_sheet顯示來源。

強制領域前置：**S06, S11**。直接使用本契約的下游：**無強制下游；由Application／UI整合**。此處列的是實作契約依賴；玩家循環中的獎勵回饋不形成程式循環引用。畫面檔名為預定交付，尚未建立。

## 6. 例外與失敗行為

同一物種多個UID不重複計數；轉換物種後下場重算；死亡政策不得和面板顯示不同；兩個效果改同一閾值時按指定加算與最低值護欄。

## 7. 調參與文件交付

門檻、人數計數政策、各層效果與參數上下限是F內容。用同總資源的混編高攻隊、純羈絆隊與治療反應隊比較，避免唯一正解。

**正式文件需求**：G／F／U／T／D／Q／C；計數矩陣、效果來源表與跨關鍵詞參數規範。 代號內容見[文件製作計畫](../documentation-plan.md)。本檔提供研究／規格草案，不代表這些正式文件已完成。

## 8. 驗收條件草案

- **AC-S12-01**：2個不同精靈啟用2人效果，第3個啟用3人並依選定政策取代；重複同物種不追加。
- **AC-S12-02**：移除成員後預覽立即失去羈絆，實戰在提交邊界更新，無殘留modifier。
