# S22 圖鑑、分類、閃光與收藏

狀態：研究完成／製作規格草案；本新案尚未審核或整合實作，repo既有基礎另計。優先級：Alpha；主要里程碑：M4。

既有module／prototype、差距與程式位置見[30系統重用盤點](../reuse-audit.md)。

## 1. 原作證據與未知

O：E08圖鑑含種族／屬性、職業篩選、閃光0/378與道具；角色說明有進化與關鍵詞。U：圖鑑是否給永久能力。 證據ID對照[素材分析](../00-reference-analysis.md)；未標O的實作與規則均為P提案。

## 2. 用途與玩家價值

讓玩家有收藏進度、查詢下一隻的理由與認識規則的入口；閃光提供外觀追求。

## 3. 要做的內容與規則

MVP僅角色列表與基本詳情；M4正式圖鑑、分類、未收集剪影、閃光旗標、進化路徑和取得來源。

P：曾獲得的species永久記錄，消耗最後一隻不抹去圖鑑；持有數與曾收集數分開。閃光只改外觀作首輪提案，不預設額外戰力或付費稀有；不以原圖378作內容承諾。

## 4. 資料、數值與持久化

CollectionState：discovered_species、ever_owned_species、shiny_species、discovered_items；CodexDefinition：分類、描述key、來源、進化連結；分母由目前正式內容包計算。

數值與單位以本系統正式F／D文件為準；共通候選計算見[數值模型](../balance-model.md)。持久狀態經S23的快照介面保存，定義資源不承載玩家狀態；顯示用暫態不自動列入存檔。S23是儲存適配器，這項整合不是領域系統反向依賴它。

## 5. Godot分工與介面

CollectionService消費取得／進化事件；codex_panel.tscn、codex_entry.tscn、species_detail.tscn。規則說明引用Skill／Bond定義，避免手抄另一份數字。

強制領域前置：**S05, S14, S15, S16**。直接使用本契約的下游：**無強制下游；由Application／UI整合**。此處列的是實作契約依賴；玩家循環中的獎勵回饋不形成程式循環引用。畫面檔名為預定交付，尚未建立。

## 6. 例外與失敗行為

內容下架時分母與舊收藏相容政策明確；搜尋空結果與未解鎖項目有說明；未發現內容是否暴雷可設定；閃光與普通收藏不能互相覆蓋。

## 7. 調參與文件交付

收集分母、展示條件、閃光權重／保底與外觀辨識需核定；原型先用指定fixture取得閃光，不開始調百萬分率。

**正式文件需求**：G／F／U／T／D／Q／C；收藏語意、分類表、進化路徑與來源文案表。 代號內容見[文件製作計畫](../documentation-plan.md)。本檔提供研究／規格草案，不代表這些正式文件已完成。

## 8. 驗收條件草案

- **AC-S22-01**：消耗最後一隻後持有數變0，曾收集與閃光紀錄保持；進化形態依政策解鎖新條目。
- **AC-S22-02**：種族／屬性／職業交叉篩選結果正確；更新技能係數後圖鑑描述與戰鬥使用同一來源。
