# S03 桌面視窗與工作區整合

狀態：**Deferred／使用者已於2026-10-27指定先不製作。** 本系統保留研究紀錄，不排入M1～M6、不阻擋玩法驗收；恢復製作需使用者另行指定。

既有module／prototype、差距與程式位置見[30系統重用盤點](../reuse-audit.md)。

## 1. 原作證據與未知

O：所有截圖顯示窄戰鬥帶覆在其他應用上，管理面板另展開；有釘選圖示。U：實際OS窗數、穿透與系統匣行為。 證據ID對照[素材分析](../00-reference-analysis.md)；未標O的實作與規則均為P提案。

## 2. 用途與玩家價值

原作的桌面陪伴體驗留作參考。本階段以一般Godot視窗呈現橫向戰鬥與管理面板，先驗證玩法循環。

## 3. 要做的內容與規則

目前製作範圍採單一一般視窗；戰鬥與管理功能使用同一視窗內的scene／Control。

延期內容包含桌面置頂、透明、特殊焦點管理，以及同屬桌面殼的穿透、多原生視窗、工作區吸附與多螢幕位置管理。它們不自動轉移成Beta或RC的必要工作。

## 4. 資料、數值與持久化

目前不建立DesktopSettings或桌面能力矩陣。一般UI縮放與文字偏好由S27管理；戰鬥時鐘與離線政策分別由S02／S24定義。

數值與單位以本系統正式F／D文件為準；共通候選計算見[數值模型](../balance-model.md)。持久狀態經S23的快照介面保存，定義資源不承載玩家狀態；顯示用暫態不自動列入存檔。S23是儲存適配器，這項整合不是領域系統反向依賴它。

## 5. Godot分工與介面

目前不建立DesktopHost或額外原生Window。battle_strip.tscn與management_panel.tscn作為同一遊戲畫面內的子scene，由Main協調；詳見[架構](../godot-architecture.md)。

強制領域前置：**無**。目前下游：**無**。S04、S25、S27、S29與S30皆可在一般視窗中獨立完成，不依賴S03。

## 6. 例外與失敗行為

一般管理面板開關與退出遊戲的行為仍需明確；關閉管理面板不停止核心模擬。桌面殼的焦點／穿透／多螢幕案例不列入本階段測試。

## 7. 調參與文件交付

目前不排此系統的調參或實作工時；一般畫面尺寸與字級由S04／S25／S27處理。

**文件政策**：本檔留存延期決策；桌面殼G／U／T／D／Q及ADR A01暫不展開。代號見[文件製作計畫](../documentation-plan.md)。

## 8. 驗收條件草案

- **AC-S03-01（延期）**：置頂、透明與特殊焦點管理的驗收待恢復本系統時另定，不作目前Gate。
- **AC-S03-02（延期）**：桌面穿透、原生多視窗與螢幕位置驗收待恢復時另定，不作目前Gate。
