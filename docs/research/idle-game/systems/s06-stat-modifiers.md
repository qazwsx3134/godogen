# S06 屬性計算與加成來源

狀態：研究完成／製作規格草案；本新案尚未審核或整合實作，repo既有基礎另計。優先級：MVP；主要里程碑：M1。

既有module／prototype、差距與程式位置見[30系統重用盤點](../reuse-audit.md)。

## 1. 原作證據與未知

O：E03區分基礎攻擊與攻擊傷害；E02性格有加減；E08羈絆會修改多種數值。U：精確疊加公式。 證據ID對照[素材分析](../00-reference-analysis.md)；未標O的實作與規則均為P提案。

## 2. 用途與玩家價值

角色面板能解釋為何變強；裝備、天賦、羈絆與暫時效果能穩定組合。

## 3. 要做的內容與規則

M1定基礎HP／ATK／間隔／移速／距離；M2接裝備；M3接羈絆、天賦、反應技能強度。

P：每個modifier有source_id、stat、operation、value、scope、duration；固定值、加算百分比、獨立倍率順序固定。永久build與戰鬥暫時buff分開；修改來源後重算，不在既有結果上反覆加乘。

## 4. 資料、數值與持久化

BaseStats、Modifier、DerivedStats、StatBreakdown；攻速存interval或haste時須明確統一。預覽回傳build_revision與來源列表，避免拿舊結果套新隊伍。

數值與單位以本系統正式F／D文件為準；共通候選計算見[數值模型](../balance-model.md)。持久狀態經S23的快照介面保存，定義資源不承載玩家狀態；顯示用暫態不自動列入存檔。S23是儲存適配器，這項整合不是領域系統反向依賴它。

## 5. Godot分工與介面

StatCalculator為無UI純邏輯；UI的stat_row.tscn顯示base、來源與最終值。Resource為不可變基礎表；執行時快取可失效重建。

強制領域前置：**S01, S05**。直接使用本契約的下游：**S07, S08, S09, S11, S12, S13, S16, S20**。此處列的是實作契約依賴；玩家循環中的獎勵回饋不形成程式循環引用。畫面檔名為預定交付，尚未建立。

## 6. 例外與失敗行為

拔裝備移除該source全部效果；最大HP下降時當前HP處理需定義，候選按比例保留；負間隔、NaN與無限值拒絕；乘區與同名來源不得重複套用。

## 7. 調參與文件交付

公式與範例見balance-model；每個stat定合法域。攻速下限、抗性上限與暴擊上限只作原型護欄，依測試再核定。

**正式文件需求**：G／F／U／T／D／Q；來源疊加表、HP重算政策、範例fixture。 代號內容見[文件製作計畫](../documentation-plan.md)。本檔提供研究／規格草案，不代表這些正式文件已完成。

## 8. 驗收條件草案

- **AC-S06-01**：裝備、卸裝重複100次後屬性回到原值，來源列表沒有殘留。
- **AC-S06-02**：固定輸入按指定運算序得唯一輸出；面板預覽與下一遭遇實際build使用相同數值與版號。
