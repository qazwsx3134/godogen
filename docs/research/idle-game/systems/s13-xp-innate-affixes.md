# S13 經驗、等級與天生詞綴

狀態：研究完成／製作規格草案；本新案尚未審核或整合實作，repo既有基礎另計。優先級：MVP；主要里程碑：M2。

既有module／prototype、差距與程式位置見[30系統重用盤點](../reuse-audit.md)。

## 1. 原作證據與未知

O：E03 Lv.1與168/1000EXP；E01／E03列天生詞綴及10／25／40／65／80／100等門檻。U：成長曲線、EXP分配方式。 證據ID對照[素材分析](../00-reference-analysis.md)；未標O的實作與規則均為P提案。

## 2. 用途與玩家價值

掛機每段時間都有可見進展；等級除了加數字，也逐步打開角色的能力。

## 3. 要做的內容與規則

MVP先做1～10級及1個詞綴門檻；M3做多詞綴門檻與隊伍分配；正式上限等內容測試後定。

P：經驗給上陣活躍隊伍，分配政策先採均分且不因死亡時刻追溯扣除；升級可一次跨多級並保留餘額。每個詞綴以stable id與解鎖level記錄，不在每次讀檔重抽。

## 4. 資料、數值與持久化

XpCurve、GrowthCurve、InnateAffixDefinition；UnitState保存level／xp、rolled_affix_ids、unlocked milestones。顯示所需EXP與累積EXP不可混存為同一欄。

數值與單位以本系統正式F／D文件為準；共通候選計算見[數值模型](../balance-model.md)。持久狀態經S23的快照介面保存，定義資源不承載玩家狀態；顯示用暫態不自動列入存檔。S23是儲存適配器，這項整合不是領域系統反向依賴它。

## 5. Godot分工與介面

ProgressionService產生LevelChanged／AffixUnlocked，再由S06重算。xp_bar.tscn、affix_row.tscn與解鎖提示；戰鬥中的屬性更新時點與BuildPolicy一致。

強制領域前置：**S05, S06**。直接使用本契約的下游：**S15**。此處列的是實作契約依賴；玩家循環中的獎勵回饋不形成程式循環引用。畫面檔名為預定交付，尚未建立。

## 6. 例外與失敗行為

滿級EXP停止或溢出用途要定，原型封頂不轉貨幣；大額EXP不得只升一級；曲線變版需遷移；多角色分配的整數餘數以固定順序處理。

## 7. 調參與文件交付

XP_next候選曲線見balance-model；詞綴效果／門檻、升級頻率與閒置一小時提升量要用F表與seed批次模擬校準。

**正式文件需求**：G／F／U／T／D／Q／C；EXP與成長曲線、詞綴池／門檻、隊伍分配規則。 代號內容見[文件製作計畫](../documentation-plan.md)。本檔提供研究／規格草案，不代表這些正式文件已完成。

## 8. 驗收條件草案

- **AC-S13-01**：一次給足3級以上EXP能逐級升到正確等級，餘額與各詞綴解鎖只發生一次。
- **AC-S13-02**：滿級、0EXP與不合法負EXP都符合政策；存讀後詞綴ID及剩餘EXP一致。
