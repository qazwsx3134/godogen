# S25 管理介面、提示與資訊層級

狀態：研究完成／製作規格草案；本新案尚未審核或整合實作，repo既有基礎另計。優先級：MVP；主要里程碑：M2。

既有module／prototype、差距與程式位置見[30系統重用盤點](../reuse-audit.md)。

## 1. 原作證據與未知

O：E01～E09有狀態、倉庫、夢靈／裝備背包、圖鑑、天賦、地圖、工坊頁籤；角色、技能、節點都有tooltip。 證據ID對照[素材分析](../00-reference-analysis.md)；未標O的實作與規則均為P提案。

## 2. 用途與玩家價值

短暫回到遊戲即可辨識收穫、做一次有效調整，再回工作；進階玩家仍查得到完整規則。

## 3. 要做的內容與規則

MVP先編成、背包、角色、地圖與簡版設定；M3加天賦、羈絆來源；M4加工坊／圖鑑與批次操作。

P：同一視窗內的管理面板保留選中UID與頁籤；概要顯示可行動資訊，詳情再展開來源。locked／empty／full／loading／error各有狀態。稀有事件用可回看的彙總，通知顯示在遊戲介面內。

## 4. 資料、數值與持久化

UiState：tab、selection_uid、filter、sort、scroll、pending_preview_revision；ViewModel含價格、是否可操作、缺條件、預覽值；顯示狀態與領域狀態分開。

數值與單位以本系統正式F／D文件為準；共通候選計算見[數值模型](../balance-model.md)。持久狀態經S23的快照介面保存，定義資源不承載玩家狀態；顯示用暫態不自動列入存檔。S23是儲存適配器，這項整合不是領域系統反向依賴它。

## 5. Godot分工與介面

management_panel.tscn＋各panel／item scene，Container與Theme保存版面。UI presenter連signal並送command，不處理傷害公式／掉率。下游功能按契約接入，不讓通用UI依賴所有domain細節。

強制領域前置：**S11, S17, S23**。直接使用本契約的下游：**S26**。此處列的是實作契約依賴；玩家循環中的獎勵回饋不形成程式循環引用。畫面檔名為預定交付，尚未建立。

## 6. 例外與失敗行為

選中角色被消耗後回安全選擇並提示；tooltip不超螢幕；連點／拖曳取消不送兩次交易；視窗縮小保留可達操作；搜尋空集合不顯示空白死頁。

## 7. 調參與文件交付

字級、行距、通知頻率、tooltip延遲與快捷鍵均可調。原型先在100%／150%／200%DPI及兩種視窗寬度驗收，不照搬截圖的小字。

**正式文件需求**：G／U／T／D／Q；IA、頁籤／詳情流程、全狀態矩陣、鍵鼠與高DPI規格。 代號內容見[文件製作計畫](../documentation-plan.md)。本檔提供研究／規格草案，不代表這些正式文件已完成。

## 8. 驗收條件草案

- **AC-S25-01**：由主要畫面可在少量清楚步驟內找到新物、比較／換裝並返回；完整路徑以UX case計時驗證。
- **AC-S25-02**：每個panel能單獨instantiate並透過node名稱測試；手改scene的靜態字與間距不被_ready覆寫。
