# S09 技能、冷卻與自動施放

狀態：研究完成／製作規格草案；本新案尚未審核或整合實作，repo既有基礎另計。優先級：MVP；主要里程碑：M2。

既有module／prototype、差距與程式位置見[30系統重用盤點](../reuse-audit.md)。

## 1. 原作證據與未知

O：E04有最低血量隊友治療、2.4倍攻擊與12秒冷卻；V有週期性技能視覺。U：完整施法條件。 證據ID對照[素材分析](../00-reference-analysis.md)；未標O的實作與規則均為P提案。

## 2. 用途與玩家價值

不同角色具有戰術功能，玩家透過搭配技能而非高頻點擊取得進展。

## 3. 要做的內容與規則

MVP做單體傷害與單體治療各一種；M3補範圍、增益、優先順序與冷卻縮減。

P：SkillDefinition描述目標、條件、效果與冷卻。冷卻完成仍須有合法目標才施放；原型補血挑HP比例最低的活隊友、平手UID，滿血時保留就緒。施放成功才開始冷卻，與原作是否相同未知。

## 4. 資料、數值與持久化

SkillDefinition：id、target_rule、effect_ids、base_cooldown、cast_ticks、priority；SkillRuntime：next_ready_tick、cast_target、cast_sequence。

數值與單位以本系統正式F／D文件為準；共通候選計算見[數值模型](../balance-model.md)。持久狀態經S23的快照介面保存，定義資源不承載玩家狀態；顯示用暫態不自動列入存檔。S23是儲存適配器，這項整合不是領域系統反向依賴它。

## 5. Godot分工與介面

SkillScheduler提出意圖→S08結算；skill_icon.tscn顯示冷卻。kit auto_caster先做隊友目標與反應契約適配試驗，不宣稱可直接用。

強制領域前置：**S02, S06, S07, S08**。直接使用本契約的下游：**無強制下游；由Application／UI整合**。此處列的是實作契約依賴；玩家循環中的獎勵回饋不形成程式循環引用。畫面檔名為預定交付，尚未建立。

## 6. 例外與失敗行為

施法期間目標死亡時取消或重選必須定死；原型取消且不扣完整冷卻。施法者死亡取消；技能CD重算不製造負數；無合法目標不每tick產空事件。

## 7. 調參與文件交付

治療係數／CD、技能優先級、HP閾值、施法時長都資料化；2.4與12秒可作原作對照fixture，不作全角色通用預設。

**正式文件需求**：G／F／U／T／D／Q／C；技能目標矩陣、施放／打斷規則與技能表。 代號內容見[文件製作計畫](../documentation-plan.md)。本檔提供研究／規格草案，不代表這些正式文件已完成。

## 8. 驗收條件草案

- **AC-S09-01**：兩名隊友HP比例不同時補到指定者；全滿血不空放，掉血後下個合法tick施放。
- **AC-S09-02**：同一cast_sequence只結算一次；減少動畫播放速度不改CD與有效治療量。
