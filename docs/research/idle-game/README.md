# 桌面橫向放置 RPG：系統研究與製作規劃

研究基準：2026-10-26 收到的 9 張截圖與 `game-play.mp4`；文件完成：2026-10-27。狀態：**研究分析完成，並已依使用者指示實作[《夢靈遠行》第一個可玩版本](../../../prototypes/dreamling-idle/README.md)。完整30系統仍是後續研究與規格提案，不代表全部完成。**

這款參考遊戲的主體是「桌面陪伴式自動戰鬥＋夢靈收集＋隊伍構築」。橫向戰鬥帶是持續產出的入口；真正的選擇在角色、裝備、關鍵詞、種族／屬性羈絆、天賦與重複角色的處理。從素材不能判定原作內部引擎、離線收益或完整終局。

```text
選擇獵場 → 自動作戰 → 金幣／經驗／收集物
    ↑                         │
    │          ┌──────────────┘
    │          ↓
    └─ 隊伍變強 ← 換裝／升級／進化／羈絆／天賦
                    │
                    └→ 圖鑑與稀有外觀 → 長期收藏目標
```

**目前製作基準（2026-10-27使用者決定）**：先用一般Godot視窗製作橫向戰鬥與養成；桌面置頂、透明、特殊焦點管理及桌面殼相關能力先不製作，不列入M1～M6的Gate。

## 四個職責的結論

- **Lead Game Designer**：先驗證「短暫回來調一次隊伍，就看得到差異」；控制打擾程度與資訊負擔。
- **Lead Systems Designer**：先定義數值來源、效果事件、獎勵流與資源消耗，再設計收集、進化與工坊。避免每個頁籤形成一套互不相容的規則。
- **Godot Specialist**：先以一般視窗驗證玩法，畫面與戰鬥模擬分離；所有主要畫面與重複物件保存成可編輯 `.tscn`。
- **Lead Programmer**：先定資料契約、交易邊界、存檔版本與決定性模擬；用小內容驗證，再量產內容。

這是 generator source 裡的一份獨立研究包，沒有把其他 prototypes 視為同一款遊戲。後續實作位於 `prototypes/dreamling-idle`，不變更全 repo 引擎設定，沒有生成 AI 美術或修改 kit。Studio `map-systems` 僅用作拆解方法。

## 規模與完成狀態

30 份逐系統文件是**研究與規格草案**，包含原作證據、建議規則、資料／場景責任、例外與驗收案例；不能當作已核定的實作 story。第一版已完成自動戰鬥、編隊、養成、裝備、天賦、6關卡與存檔的最小整合，功能測試證據見遊戲 README。尚未完成全系統、長時間效能或跨平台發行驗收。

目前範圍：MVP 17 個、Vertical Slice 6 個、Alpha 6 個；S03桌面整合為Deferred，共29個系統排入目前製作，另1個保留研究。MVP 中若干系統先做最小子集；具體範圍以 roadmap 為準，並不表示首版做完該系統全部規則。

本包共39份Markdown，保留30份系統文件及60個驗收ID；其中S03的2項已延期，目前有效58項。已檢查本地連結、ID、必要章節、依賴無環及錄影取樣索引，結果見[文件完整性紀錄](evidence/document-check.json)；這項PASS僅代表文件結構一致，不代表新案功能驗收。原始截圖尺寸與雜湊見[素材盤點](evidence/source-inventory.json)。

2026-10-27補做既有程式盤點，並重跑kit、Taskbar Hero、Skybound Blades共7個相關測試套件，均PASS，見[既有測試紀錄](evidence/reuse-test-results.json)。這些是既有基礎的驗證，未將新案的30個系統標為完成；也未把其他prototype的未實作規格當成程式。

```bash
python3 docs/research/idle-game/extract_evidence.py --ffmpeg /path/to/ffmpeg
```

另保留較疏的 `gameplay-01.png` 至 `gameplay-13.png` 及 `gameplay-contact-sheet.png` 作總覽：它們是 FFmpeg `fps=2` 重採樣結果，**不使用檔號推定精確時間**。精確時間引用一律使用 manifest 中的 sequence 合成圖。
