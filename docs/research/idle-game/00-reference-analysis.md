# 素材證據與玩法分析

製作範圍註記（2026-10-27）：本檔保留原作桌面呈現與研究觀察；新案目前使用一般Godot視窗，桌面置頂／透明／焦點與相關桌面殼整合為Deferred，不列入目前roadmap。

## 1. 方法與證據強度

| 標記 | 意義 | 使用方式 |
|---|---|---|
| O | 可直接看見的原作資訊 | 截圖文字、欄位、錄影中的事件；只能證明當次畫面 |
| I | 根據可見資訊推論 | 要解釋理由，不能寫成已測得的機制 |
| P | 自製遊戲的方案 | 可調整、需試玩與核定，與原作規則分開 |
| U | 素材不足 | 明確列出缺哪種觀察，不填造假的公式／機率 |

素材中可見 DAYDREAM 標誌與 Steam Demo 背景；本報告以「參考遊戲」稱呼，不以未核對的商店名稱或版本建立額外結論。瀏覽器、Steam、Windows 工作列與社群頁面都是桌面背景，不屬於遊戲功能。

## 4. 玩家循環與設計價值

| 層次 | 分析 I／提案 P | 玩家需要作的決定 |
|---|---|---|
| 秒級 | 作戰持續帶來命中、補血、死亡與金幣回饋 | 通常不必逐擊操作，透過表演辨識隊伍是否穩定 |
| 分鐘級 | 短暫展開管理視窗 | 換裝、換獵場、處理新角色與天賦 |
| 小時級 | 解鎖上陣格，利用種族／屬性與技能形成隊伍 | 犧牲單體高數值以湊羈絆，或保留治療／坦克位置 |
| 長期 | 角色收集、進化、閃光與區域目標 | 決定保留／消耗重複角色與追逐何種收藏 |

關鍵設計張力：打得動不代表收益最好；收集更多不代表都應上陣；高稀有度不應自動壓過隊伍功能；離開管理頁後仍能看出剛才決策的結果。

## 5. 適合借鑑與需要改進的地方

- **可借鑑**：小戰鬥帶與管理頁分開；資訊逐層展開；職業、種族、屬性、關鍵詞提供多維隊伍目標；天賦把自動化能力與上陣格納入成長。
- **需要自訂**：原圖的文字密度與偏暗鎖定項目很高；窄帶特效會遮血條；應有簡潔／詳細模式、效果來源說明、稀有掉落彙總和成本預覽。
- **先測風險**：桌面視窗搶焦點、透明區攔截工作點擊、持續高耗能、治療觸發連鎖失控、滿包後掛機停擺、背包與工坊搶用同一物品。
- **未有證據的功能**：轉生、每日任務、抽卡付費、公會、PvP、雲端帳號、連線服務。先不列為必做系統；離線收益以獨立P系統評估。

## 6. 分析如何轉成規格

每個O項目要能連回證據；每個I要有追加觀察方法；每個P要有可調參數和驗收；每個U要有解鎖實作所需的決策。原作範例只做回歸參考，不直接當作新作的平衡數值或美術素材。
