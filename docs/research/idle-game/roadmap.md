# 開發 Roadmap：先整合戰鬥循環，再擴養成深度

本文件保留完整P製作提案。2026-10-27已完成[《夢靈遠行》第一個可玩版本](../../../prototypes/dreamling-idle/README.md)，使用者指定於此段落暫停。包含6夢靈／6關卡、戰鬥、編隊、治療／羈絆、裝備、培養、天賦、首領與存檔；M1～M3的部分玩法已整合，但未宣告所有階段Gate通過。正式效能、真人試玩與完整系統驗收仍待後續。

**既有基線已補盤點**：[重用報告](reuse-audit.md)確認Taskbar Hero已有橫向波次／成長／裝備／存檔，Skybound Blades已有純戰鬥domain／隊友／治療／背包倉庫，kit已有多項獨立工具與玩法模組。本roadmap的工作包應從既有基礎選擇、移植／適配並補缺口，不把30個系統都當成重新從零寫。這輪重跑7個相關既有測試套件均通過；新案整合仍需各階段Gate。

**目前視窗基準**：2026-10-27使用者指定桌面置頂／透明／焦點先不製作。S03及相關桌面殼能力延期，採單一一般Godot視窗，戰鬥與管理介面使用同窗scene／Control；不列入M1～M6驗收門檻。

## 1. 製作順序

```text
M0 方向／範圍與關鍵規則
 ↓
M1 一般視窗內整合可重播的最小戰鬥
 ↓
M2 MVP：取得 → 養成 → 換裝／換人 → 刷圖 → 存檔
 ↓
M3 Vertical Slice：羈絆＋反應技能＋天賦＋首領
 ↓
M4 Alpha：進化＋工坊＋圖鑑＋完整管理功能
 ↓
M5 Beta：平衡、背景效能、長時間運作、內容驗收
 ↓
M6 Release Candidate：原生匯出與交付驗收
```

M1先驗證既有原型適配與模擬一致性，作為進入M2的基礎。一般視窗足以驗證目前玩法；S03不構成依賴或阻擋。

## 2. 階段總表與工作量

以1位資深Godot開發者兼設計、每人日約6小時有效製作時間估算；內容量取本文件的小規模提案，已有引擎／工具環境。不是實際工時紀錄，也未用未來AI效率作保證。

| 階段 | 主要增量 | 初估人日 | 出口 |
|---|---|---:|---|
| M0 | 核定遊戲簡報、平台、規則與MVP文件 | 3～5 | 可交工程的M1規格與風險清單 |
| M1 | 一般視窗、scene適配、時鐘、單場戰鬥 | 3～5 | 最小戰鬥結果可重播 |
| M2 | 17個MVP系統的最小子集 | 12～18 | 可玩30～60分鐘並保留進度 |
| M3 | 6個VS系統、完整一區循環 | 15～22 | 多種隊伍策略可比較的demo |
| M4 | 6個Alpha系統與既有系統擴充 | 18～28 | 預定玩法範圍齊備 |
| M5 | 平衡、效能、8小時soak與回歸 | 10～15 | 主要數值／技術品質達標 |
| M6 | 原生匯出、安裝／升級與交付證據 | 5～8 | 可供發行決策的RC |

按目前範圍粗估約66～101人日；加入25～40%未知與返工緩衝，約83～142人日。每週5個有效人日約17～29週，不能把它當承諾日期。M0～M2基礎估計18～28人日，M0～M3累計33～50人日。專屬像素角色／動作、音樂、翻譯、商店營運、跨OS與大量內容製作另估；先不承諾378個角色。

這是原先依範圍所作的粗估，尚未逐工作包量測既有程式的適配成本；不能解讀為每個既有模組都要重寫，也不能在未做M1接入測試前直接扣除固定比例。M1須記錄可直接引用、須抽離、須改規則與須新增的工時，再替換此粗估。

若只做玩法原型，M1～M2可刪掉正式視覺、完整倉庫與所有Meta頁；目前範圍仍須驗證一般視窗操作、存檔、滿包與soak。每個系統的詳細責任見[總表](systems-index.md)。

## 3. M0：把參考研究變成自己的遊戲

**要解決的問題**：主要樂趣是桌面陪伴、隊伍build還是大量收藏？首發平台是什麼？關閉後是否產出？這些決定技術和內容成本。

交付：Game Brief、MVP範圍、術語表、系統依賴、M1資料樣本、戰敗／換build／時間政策、ADR A02／A03草案；A01隨S03延期。正式文檔路徑見[文件計畫](documentation-plan.md)，不直接把研究提案標Approved。

可先採的P基線：單機本地存檔、一般Godot視窗、2D水平作戰線、同窗管理面板＋戰鬥帶、1區3短遭遇、3個夢靈、2類職能、2個可穿部位、最多3上陣位；MVP實際先開主位＋1支援位。離線收益MVP不開，只保存結算watermark並清楚說明。

出口：必要選擇在決策表有明確結果；M1的S01／S02／S06／S08無關鍵U；資料有合法及非法fixture。S03保留研究且不阻擋M1。

## 4. M1：既有基礎適配與戰鬥原型

主要系統：S01、S02、S04～S08；S03延期。S23／S27／S28／S30先做介面與最小安全功能，不提前擴完整系統。先測Taskbar saved scenes／橫向波次與Skybound domain的適配邊界，再選單一戰鬥權威；不得把兩套原型的模擬同時接上。

| 工作包 | 實作與文件 | 可驗收的結果 |
|---|---|---|
| WP1 一般視窗與底座 | 釘選Godot版本／renderer、選既有底座、同窗戰鬥／管理scene、正常退出 | 管理面板可開關，遊戲可正常執行與退出 |
| WP2 可編輯畫面 | battle_lane、actor、血條、簡版管理scene；代表性物件與Theme | 在編輯器能調位置／間距，執行保留 |
| WP3 模擬核心 | 時鐘、UID、屬性、水平選敵、攻擊、死亡、seed trace | 固定輸入與tick產生相同state |
| WP4 效能探針 | actor／事件上限、計時、初步記憶體與CPU／GPU基準 | 量測環境可重現，M5預算有依據 |

Gate：整個遊戲只有一個driver；15／30／60FPS同tick結果相同；關管理面板戰鬥持續；無目標不掛死；死亡只一次；無Parse／Script錯誤；一般視窗做互動驗證，headless驗邏輯。

桌面置頂／透明／焦點、穿透與原生多視窗沒有本階段工作包；先完成既有戰鬥與資料契約的適配。

## 5. M2：可持續遊玩的MVP

新增：S09、S11、S13、S14、S16、S17、S18、S19、S23、S25；累計17個MVP系統的最小子集。

| 工作包 | 實作與文件 | 可驗收的結果 |
|---|---|---|
| WP5 第一個收益閉環 | 擊殺→金幣／EXP→角色升級→重新作戰 | 不開管理窗仍有收益，重新開窗可查 |
| WP6 有意義的調整 | 3夢靈中的編成、單體治療、主武器／防具、屬性來源比較 | 改一項配置後，下一遭遇結果可辨識 |
| WP7 進度與保留 | 1區3短遭遇、循環刷關、角色／裝備取得、容量／待領 | 可取得新東西、處理滿包、持續刷圖 |
| WP8 存讀與中斷 | 原子快照、bak、schema、grant去重、交易錯誤提示 | 關閉後恢復同一合法進度，壞檔能退備份 |

文檔須補：MVP GDD／公式表、背包與編成UX、save schema、A04、合法資料包、關鍵路徑QA。內容量只需支撐30～60分鐘測試，未要求玩家必須手動在線一小時。

Gate：完整跑「開始→戰鬥→取得→升級→換裝／換人→換關→存檔→重啟」；滿包、戰敗、無治療目標、無資源、拖曳取消均有結果；改render模式不改收益；首次新增角色不是純粹垃圾數值。教學只需基本指示，完整流程在M3。

## 6. M3：一個完整區域的Vertical Slice

新增：S10、S12、S20、S24（若核定離線）、S26、S28。擴S11到3位上陣、S19加入1首領。

最小內容P：6～8夢靈、2種種族、2種屬性、8左右技能／效果定義、6～8天賦節點、1條可驗證的治療反應build。這些數量可共用效果，不等於8套昂貴獨立特效。

| 工作包 | 實作與文件 | 可驗收的結果 |
|---|---|---|
| WP9 Build深度 | 羈絆、關鍵詞、治療反應、slot天賦與預覽 | 純輸出／續航反應／羈絆隊有可解釋的取捨 |
| WP10 區域完成 | 首領入口／鑰匙、首通／重刷、明確進度量表 | 入口扣費去重，首通不重領，戰敗可恢復 |
| WP11 回來看收穫 | 若開離線：時間區間、凍結build、模型校準、summary | 不離線首通、不重複領、收益誤差可量 |
| WP12 學會並看懂 | 漸進引導、屬性來源、戰鬥／收益統計 | 玩家可說出改隊理由；設計師能重播死因 |

文檔須補：羈絆／關鍵詞規則、A05／A06、天賦價格表、首領資料、前30分鐘UX、模型誤差報告。離線若不採用，保留關閉政策，從M3刪該工作包並重估人日。

Gate：預先定義的3種build在至少2種敵方配置有不同優勢，而非其中一種所有指標都壓倒其他；效果連鎖有界；羈絆只套一次；新增格子確實帶來決策；首領可完成；離線案例若存在全部通過。

## 7. M4：養成與內容Alpha

新增：S15、S21、S22、S27、S29；S30已逐階實施，完整交付在M5。擴充現有S05／S09／S13／S16／S17／S19／S20／S25。

P內容上限先抓12～20夢靈、2區、2首領、1條完整進化線、6個裝備部位、3～5工坊配方。圖鑑顯示這個內容包的真實分母；不使用原圖378當虛構目標。

工作重點：重複角色有用途；進化欄位保留與退裝交易；倉庫與自動選料；工坊熟練／跨階規則；圖鑑查詢；設定與聲音；內容合法性批次檢查。仍不新增PvP、公會、轉生、付費抽卡、雲端或每日活動。

Gate：所有預定玩法有端到端路徑；每個資源有來源與去向；自動選料不消耗鎖定／裝備中物品；進化／製作重送不重扣；角色、裝備、技能與來源文案一致；缺素材、空列表、鎖定、失敗、滿包都有UI。

## 8. M5：Beta品質與平衡

完整交付S30，所有系統處理邊界。工作包括固定seed批次平衡、同資源build比較、各階段等待時間、滿包與通知頻率、長時間記憶體、背景耗能、睡眠喚醒、多DPI、存檔遷移與故障注入。

Gate：參考機與匯出版預算有實測；8小時soak沒有無界成長／不可恢復錯誤；關閉和喚醒不重領；重要操作可取消／預覽；玩家能在不查外部文件的情況下理解關鍵循環；未解決嚴重問題列為阻擋，不把「能打開」當通過。

## 9. M6：RC與交付

產物：釘選版本的原生export preset、安裝／解壓／首次啟動說明、主要scene可編輯清單、設定與存檔路徑、升級／回復說明、已知限制、素材來源／授權清單及整合證據。

Gate：乾淨環境啟動→管理→存檔→關閉→再啟動通過；更新既有profile不損資料；一般視窗的管理面板開關與退出路徑有效；打包內容包含必要素材與字型；所選匯出目標的基本玩法可正常執行。對外發布另依實際發行要求執行；本研究沒有進行發布。

## 10. 依賴、關鍵路徑與可延後項

```text
資料／時鐘／屬性 → 自動戰鬥 → 獎勵／背包 → 編成／裝備／地圖
        │                          │                  │
        └→ 事件契約 → 關鍵詞／羈絆 ┘                  ↓
              存檔／交易 ───────────────→ 離線／工坊／進化

一般視窗／UI縮放 ─→ 管理UX ─→ 全流程驗收
量測／trace ─────────────────→ 平衡／soak／RC
```

最不能延後：時鐘、效果結算權威、UID、交易／存檔與資料來源。可先縮減：角色數、裝備隨機詞綴、閃光、工坊、進化分支、音樂量與背景數。離線可作產品選擇，但關閉／睡眠行為不能未定。

## 11. 第一次開發迭代的具體任務

1. 建立獨立遊戲根目錄與Game Brief；核定首發OS、引擎版本、MVP邊界。
2. 改接battle_strip與management_panel兩個saved scenes，在同一一般視窗驗證開關、縮放與操作。
3. 定Unit／Skill／Effect／Item／Stage的ID與最小Resource樣本。
4. 實作單一SimulationDriver、固定tick、RNG、傷害事件與trace。
5. 以一友一敵跑選敵、射程、出手、死亡、重試，並輸出seed與結果。
6. 跑不同render FPS的一致性檢查及一般視窗互動測試，保留證據再進M2。

上述是未執行的待辦。每次迭代結束依實測工時與阻礙重估後續，不用這份初估掩蓋新的平台／內容風險。
