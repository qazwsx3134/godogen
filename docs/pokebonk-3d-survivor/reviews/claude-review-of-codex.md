# Claude 審查 Codex 的報告與資料表

審查對象：`codex-bundle-analysis.md`、`data/characters.md`、`data/weapons.md`、`data/enemies.md`、`data/upgrades.md`。
基準：pretty bundle 與實玩截圖。先前已另派 verifier 抽查數值（20 筆、各表筆數全 PASS），這份只審**事實錯誤與覆蓋缺口**。

## 總評

| 面向 | 評分 | 說明 |
|---|---|---|
| 機制（數值、規則） | 好 | 角色、招式、進化、敵人、Boss、升級權重、XP、生怪、Mega、存檔都有，行號可查 |
| 特效實作 | 只到系統層 | 有粒子池、後處理順序、傷害數字池、InstancedMesh；**沒有逐招的畫法**，也沒有 Boss 預告圈、天氣粒子、拾取物動畫、Mega 演出的參數 |
| 美術 | 幾乎沒有 | 只有模型路徑。UI 視覺語言、toon／描邊做法、光照、霧、草、水、天空、色調都沒記 |

## 事實錯誤

| 嚴重度 | 位置 | 問題 | 證據 |
|---|---|---|---|
| 高 | `data/weapons.md`「套裝連動」 | 把 `Tempestade Divina` 寫成「套裝連動」，但它其實是**防疊加的削弱**：同時持有龍之波動、龍捲風、制裁光礫時，傷害打折（2 招 85%、3 招 60%）。圖鑑裡的 16 組 Combo 是另一套系統，只跳橫幅、不改數值。兩者要分開寫，否則讀者會以為 Combo 會扣傷害 | `main:3601`（定義）、`main:27394`（addWeapon 檢查）、`main:17233` 的 `Dt`（16 組 Combo）、圖鑑原文：Combos 不改變任何數字 |
| 中 | 同上 | 行號 `main:3565、main:3567` 錯了；那兩行是 `statsPerCard`／`intGain` | `main:3601` |
| 低 | `data/upgrades.md` 能力表 | `static` 標 `main:3399`，`protein` 標 `main:2143`；兩處都指到容器宣告行，各差 1 行（verifier 回報） | `main:3400`、`main:2144` |

## 覆蓋缺口：機制

| 嚴重度 | 缺什麼 | bundle 哪裡有 | 建議 |
|---|---|---|---|
| 高 | **角色被動**：每隻都有，例如 Pikachu「每級 +2% 攻速」、Charizard「每級 +2% 傷害」。這是選角差異的主要來源，`characters.md` 沒有這一欄 | `main:133` 起每個角色的 `passive:` 欄位 | 角色表加一欄「被動」 |
| 高 | **16 組 Combo** 清單：名稱、所需組件（進化招、一般招、特性）、說明 | `main:17233` 起的 `Dt` | 新增一節，或另開 `data/combos.md` |
| 中 | **寶貝球價格**：底價 12，按已開數量指數成長加上定額；寶箱稀有度、付款方式 | `main:3875` 的 `he`、`main:7500` 的說明字串 | 寫出公式與前 5 次的價格 |
| 中 | **Pressure／Adaptive**：README 已補（`main:3722–3742`、`main:4075–4105`、`main:30151`），報告本身沒有 | 同左 | 報告加一節，或直接指向 README |
| 中 | **天氣**：6 種天氣，每種的屬性加成與削弱、色調、霧、粒子；時間設定為 first 50／duration 45／gap 20／warn 7 | `main:6382–6442` | 新增天氣表 |
| 中 | **狀態異常**：麻痺、凍結、燃燒、減速、暈眩的持續時間與數值，以及 Boss／菁英是否抗性減半 | 各招與能力描述散落；需找狀態處理函式 | 列一張狀態表 |
| 中 | **Bonk 模式物件**：神殿、商人、微波爐、傳送門的效果與價格 | `main:3058` 起 | 寫進模式節 |
| 中 | **評級（Rank C 等）與 PB 結算公式**、22 個任務清單與獎勵 | 結算與任務資料 | 列公式與任務表 |
| 低 | **平衡實驗室**：F2「Balanceamento」、F4「Laboratório」，每個係數一條滑桿並附公式說明，測試局不進排行榜 | `main:23967`、`main:7485`、`main:26081` | 一段介紹；這是值得照做的開發工具 |
| 低 | 合作人數修正 `fe`（每多一人 HP +60%、Boss HP +85%…） | `main:3602` | 報告只提了 `coopMult`，可列出係數 |

## 覆蓋缺口：特效實作

| 嚴重度 | 缺什麼 | 建議 |
|---|---|---|
| 高 | **逐招畫法**：每招用什麼幾何、材質、粒子。例如連鎖閃電是折線還是 beam、火焰射線、水浪環、龍捲風、光柱、斬擊弧（`/vfx/slash_*`、`trace_*`、`twirl_*` 貼在什麼上面）、進化後多出的演出 | 按招式類型分組（投射物、射線、環形擴散、落點、環繞、近戰弧）各寫一段，附代表招的行號 |
| 高 | **Boss 預告**：地面警示圈、衝刺線的形狀、顏色、時間；危險區殘留的畫法 | 寫出各行為類型的預告參數 |
| 中 | **Mega 演出**：時間軸（hit stop、FOV、閃白、光柱、圓環、模型替換），以及「+Ns Mega」浮字 | `main:30745–30765` |
| 中 | **拾取物**：XP 四級的顏色與尺寸、彈跳、旋轉、吸附曲線；寶貝球光柱 | `main:26912–27000` |
| 中 | **天氣粒子**：`fx: { n, shape, size, vel, sway }` 怎麼畫，例如 2,400 顆雨、1,500 顆雪 | `main:6395–6440` |
| 中 | **受擊與死亡**：敵人閃白的做法（材質 uniform 還是 instance color）、poof 的貼圖與尺寸、碎片 | `main:30390–30501` |
| 低 | **色差／衝擊扭曲**的實作，以及設定 key `impact distortion` 對應哪個 pass | `main:5407`、`main:5445` |

## 覆蓋缺口：美術

| 嚴重度 | 缺什麼 | bundle 哪裡有 |
|---|---|---|
| 高 | **UI 視覺語言** | CSS `:root`，以下各項見下方子表 |
| 高 | **3D 著色與描邊**：toon 材質或 gradientMap 怎麼用；描邊是後處理 pass 還是 inverted hull；描邊粗細與顏色；「永遠看得到自己」怎麼畫 | toon `main:5491`、`main:8037`、`main:8566`、`main:8645`；outline `main:5393`、`main:5647` |
| 高 | **場景光照與氣氛**：光源種類與方向、陰影 map 尺寸與品質分級、霧、天空與地平線、黃金時刻 `grade 0.4`、tilt-shift `0.1` 的預設值 | shadow `main:8805`、`main:32255–32268`；sky／fog `main:8379`、`main:8786–8860`；預設值 `main:5396` |
| 中 | **地形與植被**：高草的實例化數量與搖擺 shader、樹與石頭的低多邊形 prop、水面材質 | grass 共 38 處命中，從 `main:5400` 起；water 從 `main:8379` 附近起 |
| 中 | **模型規格**：各角色模型高度、`camDist`、貼圖替換、Gmax／Mega 模型怎麼切換 | `main:16250–16433` |
| 低 | 圖示素材：items 用像素風並設 `image-rendering: pixelated`；屬性圖示；卡片插圖的放射背景 | CSS `img[src*="/items/"]` |

UI 視覺語言的子項目，都在 CSS `:root`：

| 子項目 | 內容 |
|---|---|
| 色票 | `--yellow #ffcb05`、`--navy #0c1733`、`--red #e3350d`、`--paper #f4f0e6`、`--evo #ff4fd8` 等 |
| 字型 | `--disp` Chakra Petch、`--pix` Silkscreen，另有 Lilita One 與 Nunito |
| 斜切角 | `--cut`：16px 斜切多邊形 |
| 網點 | `--dots` |
| 斜紋 | `--stripes` |
| 晶片 | `.tchip` 的 `skew(-8deg)` |
| 立體感 | 偏移硬陰影 |
