# Boss 模型製作與檢查紀錄

此紀錄對應使用者指出造型差異過大的初版；分部位重建與新版檢查見 [rebuild/README.md](rebuild/README.md)。

日期：2026-11-14。目標為 40 m、通常遠距觀看的 Boss；參考為同目錄三視圖及 `../../boss.jpg`。以下是初版實際檢查，不代表已經過使用者造型驗收或行動裝置效能測試。

## 製作流程

1. 以槍尖到尾端約 40 m 為尺度，先確定環形砲座、前槍、側翼、放射狀底刺與雙尾的輪廓。參考圖的側視含透視，因此尾巴高度、主體厚度及俯視形狀採合理推定。
2. 使用封閉的裝甲、環、桿與分節零件建立造型；在主體、砲座、尖刺及兩條尾巴之間加入支撐，使零件有接合。來源保留命名與尾部編輯基點。
3. 檢查來源幾何及零件接合；修補三個開口，補上尾部、砲座、底刺等接頭，再檢查非流形、翻面、退化面、自相交與接觸組群。
4. 將副本合為遊戲用網格，展開 UV，烘焙 1024² 色彩圖與 512² 粗糙度／金屬度圖，輸出單材質 GLB；來源 `.blend` 仍保留程序材質與可編輯零件。
5. 將 GLB 重新匯入 Blender 檢視四個角度，檢查 UV；再用 Godot 4.7 的臨時專案匯入並驗證模型、尺寸和材質。可重跑的命令見 `README.md`。

## 檢查範圍與注意事項

- 每個來源零件皆為封閉網格；接合組群使用曲面相交或包容推定。零件之間刻意存在穿插，未做布林聯集或焊接，因此「一個接合組群」不保證整機是單一水密拓撲，也不保證動畫時關節不露縫。匯出將零件放進一個網格／surface，並沒有把零件頂點焊在一起。
- 自相交檢查針對同一零件內不共用頂點的三角面組；零件之間的相交是組裝方式，沒有被當作錯誤。接合檢查的容差、包容射線和自相交排除條件都不是對所有幾何情況的數學證明；仍應在近景、背面及將來動作中人工檢視接縫與穿插。
- 近共面檢查只列出 BVH 有交集、法線點積絕對值大於 0.99999、頂點到對方面平面距離小於 0.1 mm 的不同零件三角面候選；沒有候選不保證各種距離、深度精度與動畫下完全不閃爍。若有候選，工具列出警告，須人工確認。
- UV 檢查以三角形多邊形交集大於 `1e-10` 的正面積判定重疊，不把共邊當重疊；不到一個 texel 是按面積估算，不代表該面一定在畫面不可見。當前圖集留有大量間距且細小面多，不適合直接假定近景貼圖清晰。
- Godot 頂點數高於 Blender 來源，主要來自硬邊、法線與 UV 邊界拆分；單一 surface 並不等於實際場景必然只有一次繪製。陰影、額外 pass、視距、解析度與平台會影響效能。
- 預覽使用 Blender 燈光，還沒有在實際戰場視角、不同光線、陰影或手機上驗收。模型也沒有 LOD、碰撞、骨架或動畫，兩條尾巴的編輯基點不能直接當成 GLB 動畫。

## 未來優化順序

1. 先在目標遊戲鏡頭與設備上看輪廓、尖刺閃爍、貼圖混色與陰影成本；按量測決定是否增加近距細節或減少遠距幾何。
2. 若需要 LOD，優先刪減不影響外輪廓的短刺、尾部小肋及被遮蔽零件，再重新檢查接合與多視角，不要只依全局比例自動減面。
3. 若貼圖成為瓶頸，重新整理 UV：合併相同材質的小裝飾、提高大面板有效 texel 密度，並以 mipmap 與遠近斜角檢查邊緣；若需要近景，再評估升級貼圖解析度。
4. 製作骨架或可動尾部時，先決定關節分段及遮縫方式，檢查整個動作範圍的穿插、露縫與 bounds，再量測蒙皮、陰影和不同 LOD 的實際成本。
