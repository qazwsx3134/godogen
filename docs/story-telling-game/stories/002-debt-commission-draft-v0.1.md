# 《請幫我向你老闆討債》第一場

版本：draft-v0.1。狀態：可人工分支試讀；尚未取得作者改稿回饋與真人試讀結果，尚未接入 Godot。

作者已選定：使用銀魂角色，從新故事種子 B 展開，以新八為主要視角，先驗證人物對話與選擇回應。依據：[種子提案](001-story-seeds.md)、[產出與驗證流程](../STORY_WORKFLOW.md)。

**一句話故事：** 新八以為終於接到一件正經的討債委託，直到他發現欠款人就是剛把訂金花掉的老闆。

**本場目標：** 讓銀時答應一項具體的還款行動。玩家選擇先聽說明或先查明細，這種問話方式稍後會被銀時拿來回應新八自己的欠薪問題。

**場景：** 午後，萬事屋。一張矮桌、委託書、帳本、糰子袋。人物為新八、銀時、登勢。片段長度待試讀量測；此場是新故事的開場驗證，整篇長度依後續情節決定。

## 主持人如何試讀

從 `debt_intro` 開始，一次只給讀者目前節點的玩家文本。讀者扮演新八，到選項時自行選擇，主持人依文末路徑表繼續。內心文字屬於新八的視角，畫面仍可採俯視地圖加立繪。

方括號是可朗讀的演出註記。流程標記、狀態表與另一條分支保留給主持人。首輪不設閱讀時限。先完成一條路徑並收集回饋，之後再讓讀者選擇是否看另一條。

## 玩家文本

### debt_intro｜一張正經委託

[午後。銀時靠在桌邊吃糰子。新八把委託書攤平，指尖停在已簽收的訂金欄。]

**新八・心聲：** 有委託。有簽名。還有訂金。這張紙正經得讓我有點不敢碰。

**新八：**「阿銀，訂金呢？」

[銀時把糰子袋往桌子中央推了一點。]

**銀時：**「已經投入員工福利了。」

**新八：**「員工還沒吃到。」

**銀時：**「那就是福利還有成長空間。先看工作。」

**新八：**「委託人，登勢婆婆。委託事項，協助追討拖欠房租……」

[新八翻到第二頁。]

**新八：**「欠款人，坂田銀時。」

[停頓。銀時把最後一顆糰子送進嘴裡。]

**銀時：**「很好，雙方都熟，省掉交通費。」

[門被推開。登勢把一本帳本放在桌上。]

**登勢：**「我就住樓下。你本來打算報多少？」

**新八・心聲：** 訂金已經吞下去了。至少得讓他說出一件真的會做的事，不能又只有「下次一定」。

→ 主持人接 `debt_choose_method`。

### debt_choose_method｜先從哪一邊開始

**新八：**「先別吵。一個一個來。」

玩家選擇：

- **A｜先讓阿銀把理由說完。**
- **B｜請婆婆先把欠款明細攤開。**

→ A 接 `debt_hear_gintoki`；B 接 `debt_check_ledger`。這裡選的是問話方式。

### debt_hear_gintoki｜先聽說明

**新八：**「阿銀，你先把理由說完。我聽。」

[銀時坐直，像突然有了靠山。]

**銀時：**「新八，世上不是每件事，都能用數字衡量。」

**登勢：**「房租可以。」

**銀時：**「我是在等一個適合還錢的時機。」

**新八：**「什麼時候？」

**銀時：**「我有錢的時候。」

[新八提起筆，又放下。]

**新八：**「這句寫在日期欄會放不下。」

→ 主持人接 `debt_ask_salary`。

### debt_check_ledger｜先查明細

**新八：**「婆婆，先把明細攤開。我們一筆一筆看。」

[登勢抽出幾張紙，壓在委託書旁。]

**登勢：**「這是上次的。這是上上次的。最後這張是他自己寫的。」

**新八：**「『下次一定』……這不是日期。」

**銀時：**「寫得有彈性，雙方比較好安排。」

**新八：**「只有你一直在安排。」

**登勢：**「紙倒是都很準時。每個月多一張。」

[新八把「下次一定」圈起來。]

**新八：**「今天先把這個改成真的日期。」

→ 主持人接 `debt_ask_salary`。

### debt_ask_salary｜另一筆帳

[新八移到桌子另一側，把銀時面前的糰子袋挪開，讓帳本正對著他。]

**銀時：**「怎麼連你都坐到那邊去了？」

**新八：**「這邊有地方寫字。」

[他低頭看著帳本，停了一下。]

**新八：**「等一下。既然今天都在算帳……」

**新八：**「我的薪水呢？」

[銀時看向新八剛才坐的位置，再看回他。]

→ 主持人依先前選擇，接 `debt_recall_hearing` 或 `debt_recall_ledger`。

### debt_recall_hearing｜你的規矩

**銀時：**「新八，你剛才說什麼？」

**新八：**「我的薪水。」

**銀時：**「再前面。『先讓阿銀把理由說完。』」

[銀時伸手把茶杯拉近。]

**銀時：**「這次的理由比較長。先從我小時候說起——」

**新八：**「我給你說明的時間，不是把我的薪水換成連載！」

**登勢：**「那先說有結局的部分。」

→ 主持人接 `debt_agreement`。

### debt_recall_ledger｜你的明細

**銀時：**「照你剛才說的，一筆一筆來。領薪水的收據呢？」

**新八：**「我就是沒領到，才沒有收據啊！」

**銀時：**「所以明細還不完整。」

[新八把筆按在紙上。]

**新八：**「欠款人不能自己發明一種永遠交不出來的證明！」

**登勢：**「這句寫大一點。以後用得到。」

→ 主持人接 `debt_agreement`。

### debt_agreement｜本人出席

[登勢把茶杯移到一旁，在紙上空出一行。]

**登勢：**「明天下午三點，到樓下洗碗。工錢先抵一部分房租。」

**銀時：**「這不是討債，是介紹工作吧？」

**新八：**「做得完的那種。答不答應？」

[銀時看一眼空掉的糰子袋。]

**銀時：**「好。明天下午三點。」

[新八立刻寫下日期和時間。]

**銀時：**「新八，明天你記得——」

**新八：**「本人出席。」

[新八補上四個字，把紙轉向銀時。]

**登勢：**「開始像一件正經委託了。」

**新八：**「那我的薪水……」

[登勢抽出一張空白委託書，推到新八面前。]

**登勢：**「這個，委託萬事屋看看。」

[銀時恢復平常的坐姿。]

**銀時：**「歡迎。先收訂金。」

[新八看著空掉的糰子袋。停頓。]

**新八：**「我要先付錢，才能委託你把錢付給我？」

[場景收束。]

→ 主持人接 `debt_end`。

### debt_end｜第一場結束

銀時答應了具體的還款行動；新八的欠薪成為下一段可發展的問題。

## 作者與主持人備註

### 角色與節拍

| 角色 | 欲望與語氣 | 本場功能 |
| --- | --- | --- |
| 新八／玩家 | 想讓工作有結果；從具體問題指出對方的邏輯缺口 | 玩家選問話方式；把被拖欠的自身利益帶入事件 |
| 銀時 | 想逃掉眼前麻煩；把程序或措辭解釋成對自己有利的樣子 | 製造矛盾，記住玩家的問話方式，稍後反用 |
| 登勢 | 要一項能執行的還款行動；短句、具體、少解釋 | 用現實條件截斷繞圈，讓場景能收束 |

| 節拍 | 事件與因果 | 玩家參與／回扣 |
| --- | --- | --- |
| 1 正常期待 | 難得接到有訂金的委託 | 玩家知道新八想完成工作 |
| 2 發現矛盾 | 訂金已被銀時花掉，追討對象也是銀時 | 同桌形成委託人、受託人、欠款人的衝突 |
| 3 決定問法 | 先聽理由或先核對明細 | 記錄一個問話方式 |
| 4 事情牽涉自己 | 新八想起被拖欠的薪水，轉到桌子另一側 | 行動與站位呈現立場變化 |
| 5 先前選擇被反用 | 銀時要求繼續說明，或要求領薪收據 | 呼應玩家先前選項，兩條路有不同笑點 |
| 6 具體落地 | 明日下午三點，銀時本人洗碗抵部分房租 | 完成本場目標，並堵住委派給新八的藉口 |
| 7 喜劇收束 | 新八追討薪水，反而又被要求先付訂金 | 回扣開場的訂金與糰子，留下下一段問題 |

### 狀態與路徑

| 狀態 | 初始值 | 寫入點 | 讀取點與可見後果 |
| --- | --- | --- | --- |
| `question_method` | `unset` | `debt_choose_method`：A → `hear_first`；B → `ledger_first` | `debt_ask_salary` 後決定銀時引用哪一套程序 |
| `repayment_promised` | `false` | `debt_agreement`：銀時答應後為 `true` | 本場結束狀態；後續篇章可區分是否已有洗碗約定 |

主持人不要把「已答應」記成「已還清」。此場只承諾明日勞務抵一部分房租，新八的欠薪仍未解決。

| 路徑 | 節點順序 | 預期可見結果 |
| --- | --- | --- |
| A 先聽說明 | `debt_intro` → `debt_choose_method` → `debt_hear_gintoki` → `debt_ask_salary` → `debt_recall_hearing` → `debt_agreement` → `debt_end` | 銀時引用「把理由說完」，新八指出說明被無限延長；最後取得洗碗約定 |
| B 先查明細 | `debt_intro` → `debt_choose_method` → `debt_check_ledger` → `debt_ask_salary` → `debt_recall_ledger` → `debt_agreement` → `debt_end` | 銀時要求不可能存在的領薪收據，新八指出矛盾；最後取得同一項洗碗約定 |

`debt_end` 是終止節點，沒有額外台詞。若從中段預覽：`debt_ask_salary`、兩個 `debt_recall_*` 與 `debt_agreement` 都要明確帶入 A 或 B 的狀態。`question_method=unset` 只允許出現在選擇前；出現未設定狀態時應回到選擇節點。

### 演出與 Godot 交接

| 演出 | 最小呈現 | 規劃中的能力 |
| --- | --- | --- |
| 攤開委託書、看到欠款人 | 台詞加道具文字即可理解 | `say`、`wait` |
| 先聽說明／先查明細 | 兩個自定步調的選項，接局部分支 | `choice`、`set_flag`；此稿的 enum 可在資料規格階段對應到變數 |
| 新八走到桌子另一側 | 兩個命名站位，中間留可走動線 | `move`、`face` |
| 薪水問題後的不同反應 | 依先前狀態讀取相應節點 | M2 的 `condition`；M1 可先把兩條路展開成獨立的直接跳轉 |
| 發現欠款人與最後一句 | 短停頓、表情切換，可加鏡頭聚焦 | `wait`；M2 的 `expression`／`camera` |
| 糰子袋、茶杯與帳本 | 首輪用文字註記；之後可用靜態道具與表情 | 資產需求，在視覺階段確認 |

閱讀的停頓由玩家推進保留；演出用的短等待可調整，不把作者估計的喜劇節拍直接當成玩家必須遵守的閱讀速度。

### 本次作者自查

- 兩條路徑都有入口、一次選擇、即時回應、合流、狀態呼應與結尾。
- 新八是在宣讀委託後知道欠款人，登勢只用自己持有的帳本與當場聽到的話回應。
- `question_method` 在兩條路徑都先寫入，再於後文讀取；不同角色明確引用玩家先前的做法。
- 本場結束是得到還款承諾；沒有把同意抵租寫成房租已付清，也沒有讓新八突然拿到薪水。
- 改稿時保留「訂金／糰子」「說明／明細」「本人出席」三組前後呼應，再檢查相關路徑。

以上是文本與路徑的作者自查。笑點、角色辨識度及續讀意願仍待實際讀者回饋。
