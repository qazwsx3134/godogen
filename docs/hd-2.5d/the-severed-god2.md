一、美術：拆解它的 HD-2D 視覺






























1. 它的美術並不是單純的 Pixel Art
觀察遊戲畫面，可以拆解出幾個不同的視覺層次。









角色：2D Pixel Sprite

角色本身具有明確的像素邊緣與相對簡化的造型。動作主要靠 Sprite 動畫呈現，而非依賴複雜的 3D 骨骼。












環境：具有立體感的場景

地面、岩石、草叢和遠景有明顯的深度差異，使人物像是站在有空間感的世界，而不是平面的背景圖片上。












後製：非像素化的光影與特效

以光暈、發光粒子、霧氣及技能軌跡提升畫面表現，讓角色雖然是像素風，戰鬥卻不顯得僵硬。



2. 為什麼這樣搭配很有效？
這裡有一個重要的視覺概念：混合解析度（Mixed Resolution）。

例如角色可能在低解析度空間繪製，場景和粒子卻以較高解析度渲染。

這種做法的優勢是：
- 角色保留 Pixel Art 的辨識度。
- 背景可以呈現比較柔和的色彩與漸層。
- 光影與特效不受限於角色的像素尺寸。
- 巨型 BOSS 可以利用尺度差異營造壓迫感。
但要注意，這不是越多 Bloom、模糊和光暈就越好。

最容易失敗的地方是角色與背景的解析度語言完全不一致，最後看起來像把像素角色硬貼在一張 3D 背景圖片上。
3. Godot 要怎麼重現？
如果要研究這類視覺，我建議先比較三種製作方式，而不是直接選一種。
方案 A：純 2D 分層
容易驗證

利用 Sprite2D、Parallax2D、CanvasItem Shader 與粒子系統建立假景深。

優點：效能與製作成本較可控。缺點：相機角度和真實透視受到限制。












方案 B：2D 人物 + 3D 場景

角色使用 Sprite3D / AnimatedSprite3D，場景使用 MeshInstance3D、Camera3D 和 WorldEnvironment。

優點：真實透視、燈光與景深更自然。缺點：美術整合、陰影與移動平台效能要求較高。












方案 C：預渲染場景 + 2D 角色

在 Blender 製作場景後輸出背景與深度分層，遊戲主要使用 2D 素材呈現。

優點：容易取得高品質構圖與場景光影。缺點：場景難以自由旋轉，環境互動也需要額外處理。












如果只看還原效率，我會先測試 A 與 B。

尤其你使用 Godot，畫面呈現可以是 2D，但底層場景不一定要全部使用 2D 節點。 要不要使用真正的 3D，取決於你是否需要可移動的相機、空間遮擋、即時光影和透視變化。

2. Break 與 Sever 必須形成不同的獎勵層次

階段	預期回饋	玩家心理

建議使用 Godot 的 Resource 儲存技能、怪物、部位和遺物的定義，讓系統和內容解耦。

例如：
class_name BodyPartData
extends Resource

enum Height { LOW, MID, HIGH }

@export var id: StringName
@export var height: Height
@export var max_hp: int
@export var max_shield: int
@export var disabled_abilities: Array[StringName]


然後戰鬥時另外建立 BodyPartState，追蹤剩餘 HP、護盾和是否遭到切斷。

這裡需要特別區分：
- BodyPartData：靜態資料，所有同類敵人可以共用。
- BodyPartState：執行時狀態，每隻敵人分別持有。
- BattlePresentation：負責動畫、特效和 UI，不直接決定傷害。
如此才能避免修改一隻敵人的 HP 時，意外修改共用的 Resource 資產。

3. Godot 如何避免技能與遺物產生大量 if/else？
我會採取事件驅動的 Effect System。

例如每個遺物都有觸發條件：
class_name RelicEffect
extends Resource

func on_battle_event(
    event: BattleEvent,
    context: BattleContext
) -> void:
    pass


遺物本身可以覆寫事件處理。
class_name BreakRefundEffect
extends RelicEffect

func on_battle_event(
    event: BattleEvent,
    context: BattleContext
) -> void:
    if event.type != BattleEvent.Type.SHIELD_BROKEN:
        return

    context.queue_resource_gain(
        event.actor_id,
        1
    )


這是架構示意，BattleEvent、BattleContext 和資源回復方法都需要自行定義。

真正要解決的還包括：
- 事件觸發順序。
- 重複觸發與無限連鎖的防護。
- 同類效果能否堆疊。
- 角色死亡後是否繼續觸發。
- 同一效果在局內和局外的有效範圍。
這些規則需要集中管理，而不是讓每個遺物自由修改戰場。

四、三套系統如何真正整合？
這是最值得研究的部分。

假設玩家裝備了破防相關遺物，並在戰鬥中成功破壞巨型 BOSS 的手臂。
1. Roguelite：戰鬥前的決策

   玩家選擇了增加破防效率的遺物，形成自己的戰鬥策略。
2. 戰鬥：策略產生效果

   玩家集中攻擊 BOSS 的手臂，成功 Break，再完成 Sever，使 BOSS 失去一項技能。
3. 美術：成果被玩家感知

   護甲碎裂、手臂斷裂、敵人踉蹌、鏡頭震動、特效與音效共同放大這次成功。
4. Roguelite：創造下一次期待

   玩家拿到新獎勵，開始考慮是否強化同一個流派，或改成另一套構築。

同一個「部位破壞」事件，同時支撐三個系統。

這也解釋了為什麼我認為《The Severed Gods》的 Battle System 非常適合成為整個遊戲設計研究的中心。

《The Severed Gods》視覺融合技術拆解：從美術到戰鬥系統
你選擇的「整體融合效果」，其實是這種遊戲最值得研究、也最難複製的部分。

因為真正吸引人的並不是單一元素，而是：

像素角色確實站在這個世界裡，光影影響角色，角色的攻擊影響環境，而鏡頭又能讓玩家感受到攻擊的重量。

我想先提出一個設計觀點：
我們不應該先問「Godot 要怎麼做出 HD-2D」，而應該先研究「哪些視覺資訊，讓玩家相信 2D 角色真的存在於 3D 空間」。

這是兩個不同的問題。
一、先觀察《The Severed Gods》的實際畫面
野外戰鬥場景
角色、草地、遠方丘陵與大氣光線，形成具有前後距離的空間。
技能攻擊演出
角色仍維持像素造型，但技能光效跨越畫面，形成更具衝擊力的戰鬥演出。

從這兩張畫面，我認為至少可以辨識出五種視覺技巧：
1. 角色與環境的解析度差異：角色像素感明確，環境則有更細膩的紋理與光影。
2. 前景、中景、遠景的層次：近處草叢、戰鬥平面和遠景共同建立空間感。
3. 統一的光照方向：角色與環境處於相似的明暗氛圍。
4. 柔和環境與強烈技能特效的對比：平常畫面穩定，技能發動時才出現高亮度變化。
5. 戰鬥構圖：玩家、敵人和技能特效都有相對明確的視覺位置。
需要區分的是：這些是根據遊戲截圖做出的視覺分析，不能僅憑截圖斷定開發團隊實際採用 3D Mesh、預渲染背景或哪種 Shader。

如果其中一層沒有配合，玩家就會察覺不自然。

例如：
- 角色採用側視角，但地面透視接近俯視角。
- 角色腳底沒有陰影，看起來像漂浮。
- 背景有強烈暖光，角色卻完全不受光照影響。
- 角色的像素顆粒很大，技能特效卻過度銳利。
- 背景太細緻、對比過強，讓角色失去辨識度。
因此我會認為，Camera、角色接地與光影一致性，比單純添加 Bloom 更重要。

Godot 的 Sprite3D 和 AnimatedSprite3D 就是為了讓 2D 貼圖存在於 3D 場景而設計，支援 Billboard、像素比例、透明度與光照等設定。

但這些功能本身並不保證畫面好看。
關鍵一：Billboard 與角色朝向
Billboard 讓 Sprite 面向攝影機，但不一定要用全方向 Billboard。

例如固定側面戰鬥場景，可以讓角色保持固定角度。若攝影機會繞著角色移動，才需要考慮 Billboard 或不同方向的角色動畫。

否則很容易出現角色隨攝影機轉動，像一張紙片的問題。
關鍵二：Shadow 與 Ground Contact
角色通常要有一個接地陰影。

這個陰影不一定需要即時物理陰影，可以是貼在地上的透明橢圓形 Decal 或 Mesh。

角色跳躍時，陰影留在地面，角色本身向上移動，就能立即加強空間感。
關鍵三：像素尺寸
假設人物 Sprite 高度 96 pixels，而希望在場景中呈現約 1.8 個世界單位高：
\[
pixel\_size = 1.8 / 96 = 0.01875
\]

這是概念上的比例換算。真正的視覺尺寸還受 Sprite 的透明留白、相機投影和縮放影響。

如果每個角色都使用不同的 pixel_size，角色之間很容易出現不一致的像素密度。

因此應該定義統一的 Pixel Density 規範。

四、如何讓角色與環境看起來像同一個世界？
我會將融合技術分成三個層級。
Level 1：統一空間
首先是讓角色站得穩。

觀察畫面裡的人物和地面，可以發現角色腳部、地面陰影、草叢高度、遠景之間具有一定的視覺邏輯。

在 Godot 中，我會優先處理：
- 角色腳底的接地點（Ground Anchor）。
- 攻擊動畫中的位移與回位。
- 草叢、石塊與人物的遮擋關係。
- 近景、中景、遠景的相機透視。
- BOSS 與一般敵人的相對尺度。
最重要的是把遊戲座標與視覺偏移分開。

例如角色跳躍、遭受擊飛時，應該讓視覺節點相對於角色 Root 移動，而不是隨便改變角色的戰鬥座標。

這對回合制尤其有用，因為角色的站位和技能目標通常需要保持穩定。
Level 2：統一光影
這部分開始接近 HD-2D 的核心美感。

Godot 可使用：
技術	用途	注意事項
DirectionalLight3D	統一主要光源方向	避免影子與角色美術衝突
WorldEnvironment	環境亮度、色調、霧氣	控制整體氣氛
Sprite3D.shaded	讓 Sprite 接受 3D 光照	需測試像素美術的明暗
GPUParticles3D	草葉、灰塵、技能粒子	手機須控制透明重疊
ShaderMaterial	特殊的像素或光照效果	不宜將所有效果放進單一 Shader
Godot 官方文件也確認，SpriteBase3D 的 shaded 設定可讓 3D 光源影響 Sprite。

然而，這裡有一個重要的取捨。

如果你把光照完整作用到像素人物身上，角色原本手繪的明暗也會一起受到影響，有時反而失去 Pixel Art 的風格。

所以我會比較：

A. Unshaded Character：角色維持原始顏色，透過外部陰影與特效融入場景。

B. Shaded Character：角色受場景燈光影響，強化明暗與空間一致性。

C. Hybrid Character：角色保留基本顏色，只讓環境光與特殊攻擊光部分影響人物。

其中 C 是值得做實驗的方向，但需要自訂材質處理。
Level 3：統一最終畫面
這裡才輪到 Post-processing。

例如：
- Bloom：讓技能、火光、魔法能量更突出。
- Color Grading：統一環境與角色色彩。
- Depth of Field：讓背景產生柔和的空間距離感。
- Vignette：讓視線集中在戰場中心。
- Camera Shake：讓重擊和破防更有重量。
但我不會全部開到最大。

尤其《The Severed Gods》的戰鬥有部位辨識需求，畫面漂亮與戰鬥資訊清楚之間存在衝突。

如果 BOSS 的手臂被紫色光效完全遮住，玩家就無法判斷哪個部位已經破壞。

因此視覺效果必須服從戰鬥可讀性，而不是相反。

五、視覺與 Break／Sever 的整合：最值得研究的地方
如果把戰鬥系統和美術系統分開開發，常常會變成：

戰鬥系統已經計算完傷害，然後美術系統單純播放一段攻擊動畫。

但我認為要做到你喜歡的那種整體融合，應該讓戰鬥狀態主導整個場景的演出。

我們用同一隻 BOSS，設計三個不同的戰鬥事件。









第一階段：Hit — 命中

角色突進、揮劍、命中閃光、敵人短暫後仰，搭配乾淨的打擊音。

設計目的：讓玩家知道哪一招命中了哪個部位。












第二階段：Break — 破防

護甲裂開、碎片飛出、敵人失衡、鏡頭短暫震動，破防特效明顯高於一般命中。

設計目的：玩家意識到自己成功創造戰術優勢。












第三階段：Sever — 部位破壞

部位破裂或脫落、敵人姿態改變、原本的攻擊動作被封鎖，留下持續可見的損壞痕跡。

設計目的：讓玩家看到戰鬥狀態發生永久改變。



這裡有一個值得留意的設計細節：

破壞結果應該持續留在畫面上。

例如破壞了 BOSS 的右臂，下一回合就不應該只是顯示「右臂已破壞」的文字，而是 BOSS 真正少了一隻手，或手臂呈現殘破狀態。

這樣玩家就不需要一直看 UI，也能從敵人外觀理解戰場狀態。

這裡 Disable Ability 是戰鬥邏輯造成的結果，不能只是動畫播放後才隨意觸發。

我會把戰鬥運算和視覺演出分開，再讓 Presentation Controller 控制整段演出時間。

例如命中後的順序可以是：

前搖 → 攻擊 → 命中停頓 → 傷害視覺 → 破防效果 → 敵人反應 → 回到待命

這就涉及遊戲設計中的 Hit Stop（命中停頓）。

不需要讓整個遊戲暫停很久，只要在重要命中瞬間短暫停住角色動畫，再搭配聲音、閃光與位移，就能增加衝擊感。

以原型實驗來說，可以先測試一般命中約 30–60 ms、Break 約 70–110 ms 的停頓；這些是試驗起點，不是《The Severed Gods》的實際數值，也需要依動畫節奏調整。

六、Godot 還有一個關鍵問題：不同解析度如何融合？
你之前的作品大多以手機為目標，所以這點尤其重要。

如果把整個場景都渲染成低解析度，放大時會得到一致的像素效果，但背景的細膩光影可能也會一起失去。

如果整個場景都以手機原生解析度渲染，背景很漂亮，角色像素邊緣卻可能出現不一致的縮放效果。

因此需要比較兩種渲染策略。
策略 A：單一渲染解析度

角色、地形和特效共同渲染，由同一個相機輸出畫面。

Visual Prototype：同一場景做兩種渲染方式









版本 A：2D 場景
用 Sprite2D、Parallax2D 和 Shader 模擬景深。

用 Mesh 地形、AnimatedSprite3D、3D 光源及 Camera3D。

測試時保持相同條件：
- 同一名像素角色和相同動畫。
- 同一個草地與岩石場景構圖。
- 同一個 BOSS 和一次 Break 動畫。
- 相同的目標解析度和手機硬體。
最後比較畫面整體感、角色接地、光影、相機自由度、開發時間以及 GPU Frame Time。

這樣比較的結果才有價值，不會因為其中一種方案用了更精緻的素材，就誤以為它的渲染架構更優秀。

八、我想接著和你討論戰鬥畫面的相機
目前我們聚焦的是整體融合效果，但我認為在決定 Godot 的渲染架構前，還有一個會直接影響美術製程的問題：

你最喜歡《The Severed Gods》這種具有舞台感的橫向戰鬥構圖，還是想要保留 2.5D 美術，但讓相機可以呈現更多角度？
A. 固定橫向戰鬥
以構圖、角色演出、BOSS 尺度和特效為主，戰鬥像是一個精緻舞台。









B. 電影式戰鬥鏡頭
基本戰鬥構圖穩定，但大招、破防、BOSS 演出時相機可以移動與轉換角度。










C. 斜俯視探索與戰鬥
有更強的場景移動感，角色可以在地圖中走動，探索與戰鬥保持同一空間。









D. 混合式鏡頭
探索時自由移動，進入戰鬥後轉為固定舞台，大招使用電影式鏡頭。
