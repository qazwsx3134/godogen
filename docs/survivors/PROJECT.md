# 宇智波斑 Survivors（暫名）

手機優先的 2D Survivors-like。玩家操控宇智波斑，在忍者軍團中從「本來就很強」一路長成「戰場級天災」。

> Vampire Survivors 的成長成癮 ＋ 無雙的軍團破壞感 ＋ 宇智波斑的戰場支配感。三者少一個就不成立。

來源：[conversation.md](conversation.md)（設計討論原文，不再修改）。本檔是整理後的決策版，數字與範圍以本檔為準；和原文不同的地方列在文末「裁定」。

狀態：規劃中。預定位置 `prototypes/survivors/`。取得版權前，先用與 IP 無關的替身原型 [安](../../../sugarcane-tanks/README.md)（弓箭傳說式房間射擊）驗證自動攻擊、升級三選一疊加與打擊回饋；那個原型不驗證敵海密度。

## 待決事項（開工前要使用者決定）

| 項目 | 預設（未決定前照這個做） | 影響 |
|---|---|---|
| IP | 原型階段以斑為設計基準，只在本機與私下試玩使用，不公開發佈。要商業化時改成原創角色，或取得《火影忍者》授權 | 角色名、招式名、台詞、五影等敵人名稱，以及 AI 生成素材能不能像原作角色。改成原創角色就要換掉整套素材，越晚改越貴 |
| 平台 | iOS 優先，沿用 pixel-monster 的 iOS 匯出流程。Android 另外評估 | repo 目前沒有 Android preset，要做 Android 是新工作 |

## 設計支柱

1. **戰場支配**：不是求生，是支配。曲線是「強 → 離譜 → 軍團殺手 → 天災」，Lv1 不能五下才打死一個小兵。
2. **大規模破壞**：每個核心技能都要回答「這招怎麼一次殺更多人」，不是「DPS 多少」。
3. **亂中可讀**：畫面可以亂，資訊不能亂。玩家永遠看得懂：自己在哪、Boss 在哪、危險區在哪、技能好了沒、什麼殺了我。
4. **短局**：MVP 一局約 11–12 分鐘（見「一局流程」），正式版 15–20 分鐘。

優先序：**手感 → 效能 → 系統 → 內容 → 打磨**。

## 核心循環

```
 殺敵 → 查克拉/EXP → 升級三選一 → 技能進化/合成
   ↑                                    ↓
 玩家覺得自己很強                 招式更誇張、一次殺更多
   ↑                                    ↓
 敵人恐慌/逃跑 ← 支配值上升 ← 擊殺數與連殺上升
        （同時推高音樂層數與畫面特效）
```

## 核心系統

### 支配值（Dominance）

玩家這一側的單一數值，驅動音樂、畫面、敵人恐慌與奧義。

- **來源**：擊殺、多殺、菁英擊殺、Boss 擊殺、完美閃避、奧義擊殺。
- **衰減**：一段時間沒擊殺就緩慢下降，讓它反映「現在有沒有在支配」，而不是第二條 XP 條。衰減速度與延遲時間在 M3 試玩時調整。
- **階段與效果**：

| 支配值 | 階段 | 音樂層（同步播放，按階段開啟） | 敵人 |
|---|---|---|---|
| 0–25% | Normal | 打擊（鼓＋太鼓） | 正常進攻 |
| 25–50% | Pressure | ＋低音 | 正常進攻 |
| 50–75% | Dominating | ＋弦樂，畫面特效變化 | 靠近斑的敵人會猶豫 |
| 75–100% | Overwhelming | ＋合唱 | 部分敵人後退、逃跑 |
| 100% | 覺醒 | 完整主題 | 天礙震星解鎖一次；使用後支配值降到 50% |

**恐慌**在 MVP 直接由支配值階段與大招事件（隕石、須佐能乎出現）推導，不做每隻敵人各自的士氣值。完整的 Morale 系統等 MVP 驗證過再做。

### 操作

自動攻擊，加上玩家決定關鍵技能。手機直式，雙手拇指操作：除了搖桿只有 3 個按鈕，全部放在畫面下半部。

| 手機 | PC | 功能 |
|---|---|---|
| 下半部左側浮動搖桿（手指按下處出現） | WASD | 移動 |
| — | — | 團扇、豪火滅卻：自動施放 |
| 右下 Dash（最大顆） | Space | 瞬身閃避。敵人攻擊前一刻閃避＝寫輪眼完美閃避 |
| Dash 左上方 須佐能乎 | Q | 短時間強化，有冷卻 |
| Dash 正上方 天礙震星 | R | 奧義，只在支配值覺醒後可用 |

HUD 放上方（HP、EXP、計時、擊殺數、支配值），下半部留給操作，中段是戰場。上下都要避開 Safe Area。

### MVP 技能

| 技能 | 施放 | 定位 | 成長 |
|---|---|---|---|
| 團扇 | 自動 | 前方 120° 近戰、擊退、撞飛後排 | 數值升級為主 |
| 豪火滅卻 | 自動 | 錐形火焰、燃燒 | Lv1 錐形火 → Lv2 加寬 → Lv3 燃燒 → Lv4 燃燒地面 → Lv5 著火敵人死亡爆炸；合成「炎獄」：爆炸再點燃周圍 |
| 寫輪眼 | 被動 | 暴擊、完美閃避 | 完美閃避 → 0.15 秒慢動作 → 殘影反擊 |
| 須佐能乎 | 主動 | 短時間強化、近戰大範圍 | 骨架手臂 → 肋骨 → 半身 → 鎧甲 → 完全體。外型進化本身就是獎勵 |
| 天礙震星 | 主動（奧義） | 全畫面級 AOE | 固定演出，見下 |

**升級選項分三類**：數值（傷害、冷卻、範圍）、機制（燃燒、爆炸、貫穿、分身、連鎖）、進化（滿足條件後出現，例如豪火滅卻 Lv5 ＋ 燃燒強化 → 炎獄）。MVP 共 15–20 個升級、3 個進化。

**天礙震星演出**：啟動 → 音樂壓低 → 鏡頭拉遠 → 敵人停下抬頭 → 天空變暗 → 隕石影子擴大 → 撞擊、短暫白屏 → 爆炸 → 擊殺數跳出 → 斑的一句台詞。第一次使用演完整版，之後可縮短。傷害判定只有一次圓形範圍查詢，跟演出分開。

### 打擊回饋

大招同時疊五層：

1. **Hit Stop**：大攻擊 0.04–0.08 秒。上一次停頓後 0.25 秒內不再觸發，免得割草時畫面一直卡。
2. **震屏**：小招 1–2 px、大招 5–10 px，天礙震星加鏡頭拉遠。設定裡可調 0–100%。
3. **音效分層**：Impact ＋ Bass ＋ Debris ＋ Enemy Hit ＋ Whoosh，不用單一 boom.wav。
4. **敵人反應**：受擊閃白 → 擊退 → 飛出（假物理弧線，不做真 ragdoll）→ 撞到的敵人也被推開。
5. **地面痕跡**：火遁留焦痕、須佐劍留劍痕、隕石留坑，用 decal／sprite，不做真實破壞。M4 之後再做。

傷害數字只突出 CRIT、MULTI KILL、ELITE BREAK、BOSS DAMAGE，一般傷害淡化或關閉。一擊的擊殺數搭配稱號：50 SHINOBI HUNTER、100 UNSTOPPABLE、300 BATTLEFIELD DEMON、500 GOD OF SHINOBI。

## 一局流程（MVP）

```
00:00 普通忍者 ── 02:00 遠程忍者 ── 04:00 菁英 ── 05:00 密度暴增
 ── 06:30 小Boss ── 08:00 軍團突擊 ── 09:00 最大密度 ── 10:00 Boss
 ── Boss 倒下後 30–60 秒 Reward Phase（完全體須佐、無限查克拉、大量生成）
 ── 結算
```

**敵人密度目標**（同時在場）：0:00 約 20 → 2:00 約 60 → 4:00 約 120 → 6:00 約 200 → 8:00 300 以上。

**生成用預算制**：普通忍者 1 點、遠程 2 點、菁英 10 點；每秒 `budget += difficulty_rate`，生成器依預算與時間軸挑敵人。時間軸寫成資料檔，方便調整。

**威脅來源**：斑很強，壓力來自三處。遠程與菁英逼玩家走位；Boss 的機制讓玩家從屠殺切換成「真的戰鬥」（至少 3 種攻擊、1 種位移、1 次轉階段）；敵海包圍時仍會扣血。M2 要一起驗證「斑很強」與「有死亡風險」能不能同時成立。

## MVP 範圍

| 類別 | 內容 |
|---|---|
| 角色 | 斑 1 名 |
| 地圖 | 1 張 |
| 敵人 | 普通 3 種（例如一般、快速、厚血）、遠程 1、菁英 2、Boss 1 |
| 技能 | 上表 5 個 |
| 成長 | 15–20 升級、3 進化 |
| 系統 | 移動、Dash、自動攻擊、EXP、三選一、敵海、擊退、擊殺計數、支配值、打擊回饋、結算畫面 |
| 手機 | 虛擬搖桿與 3 顆按鈕、Safe Area、切到背景時自動暫停 |
| 設定 | 特效高/低、敵人密度高/低、傷害數字開/關、震屏 0–100% |

不在 MVP：局外成長、其他角色、Endless／Boss Rush 等模式、完整 Morale、地形破壞、存檔續玩（只存設定）。

「敵人密度」的低檔會減少敵人數量，但提高單隻 HP（例如 300 隻 × 100 HP 改成 150 隻 × 200 HP），玩家感受到的壓力相近，效能負擔約減半。

## 里程碑

每個里程碑用實機錄影或試玩收尾，不以「程式寫完」算完成。

```
M1 Can I Kill?      移動、團扇、敵人、傷害、死亡
                    ＋ 從第一天就有：敵群資料陣列、空間格、物件池、效能上限
        ↓
M2 Is It Fun?       敵海 100+、擊退連鎖、打擊回饋、EXP、三選一
  ★ 關卡：「斑＋團扇＋100 忍者＋擊退＋Hit Stop＋擊殺數」這 30 秒
          不好玩，就不做須佐能乎，先修基礎戰鬥
        ↓
M3 Feels Like Madara?  豪火滅卻、寫輪眼、須佐能乎、天礙震星、支配值與音樂分層
        ↓
M4 Can It Ship?     Boss、菁英、UI、音效、實機效能、完整 10 分鐘流程、結算
```

MVP 要回答三個問題，答案是「否」就停下來修，不往下做：

| 問題 | 在哪個里程碑判定 |
|---|---|
| 100–500 個敵人同時被掃飛爽不爽 | M2 |
| 從普通斑進化到須佐能乎爽不爽 | M3 |
| 天礙震星會不會是玩家想錄影分享的時刻 | M3 試玩、M4 定案：試玩者看完錄影後，是否主動想存或轉傳那一段 |

**成功指標**

| 指標 | 怎麼量 |
|---|---|
| 30 秒內攻擊有重量 | 試玩問卷；錄影回看 |
| 3 分鐘內形成第一個 Build、8 分鐘內至少一次明顯進化 | 遊戲內記錄時間點 |
| 5 分鐘時感到「敵人變成海」 | 當下在場敵人數 ≥ 200 |
| 10 分鐘結束想再開一局 | 試玩者是否主動再開 |
| 中高階手機接近 60 FPS | 參考機實測（最低支援機沿用 pixel-monster 的 iPhone 12） |
| 300 敵＋天礙震星＋粒子＋掉落同時出現，至少 30 FPS | 參考機實測；天礙震星就是壓力測試 |

**工期**：原文總表寫 12–15 週，但各 Phase 標的工期加總約 13.5–16 週，而且還不含沒標工期的 Phase（技能資料化、Build 合成、流程、Reward Phase、音樂、優化、物件池、打磨等）。以 Solo Dev 來說，**實際抓 16–20 週**比較可信。

## 技術方向

- **Godot 4.7、GDScript、Compatibility renderer**，與 `prototypes/` 其他原型一致，才能直接用 godot-kit，也能出 Web 預覽版。`engines/godot.md` 寫的 C# 是 publish 出去的 runtime 用的，不適用 `prototypes/`。之後實機 profile 真的證明 GDScript 跑不動敵群，再只把熱路徑換成 C# 或 GDExtension。
- **解析度**：直式，設計解析度 1080×1920，stretch `canvas_items`、aspect `expand`、`window/handheld/orientation=1`，與 debt-commission 相同。
- **直式視野**：左右可視範圍比上下窄，敵人從左右進入畫面的距離較短。生成點依 viewport 矩形外擴一圈來算，不用固定半徑的圓；左右兩側的生成距離要另外調。鏡頭可以讓斑略偏畫面下方，但要避開手指蓋住的區域。
- **粒子**：先在 Compatibility 實測 GPUParticles2D；低階機不穩就換 CPUParticles2D（官方文件定位為舊裝置的備援）。

### 敵群架構

大量單位是假象，昂貴的運算只集中在玩家附近。

```
EnemySwarm（node，存在 main.tscn）
 ├─ 資料：Packed*Array 存每隻的位置、速度、HP、類型、狀態、LOD 層
 ├─ 更新：一個 _physics_process 批次跑完
 │     近（800px 內）60 Hz ／ 中 15 Hz ／ 遠 5 Hz
 ├─ 空間格 SpatialGrid：AOE 查詢、敵人互推、擊退連鎖都查這裡
 └─ 繪製：MultiMeshInstance2D（依類型分組），不為每隻敵人建 node
菁英／Boss：CharacterBody2D ＋ 狀態機，各自是 .tscn
```

- **AOE 判定查自己的空間格，不用物理引擎的 Shape Query**。普通敵人不是 PhysicsBody，`intersect_shape` 查不到它們；原文「普通兵不做完整物理」和「用 Shape Query 找範圍內敵人」不能同時成立。空間格也讓擊退撞飛後排的成本可控：連鎖只在近距離層計算，並限制傳遞層數。
- **視覺與傷害分開**：特效只負責好看，傷害是一次範圍查詢加上 `apply_damage()`。
- **效能上限**：同時模擬的敵人 400、畫面上最多 800（超過 400 的部分只在遠層低頻更新）、粒子 500、傷害文字 30、地上掉落 100。超過時重用、合併（例如 EXP 球合併）、剔除。
- **物件池**：敵人資料槽、投射物、特效、EXP、傷害數字全部重用，不要每秒數百次 `instantiate`／`queue_free`。M1 就做。
- **敵人移動**：直線朝玩家加上鄰居分離，不用 NavigationAgent2D。
- **前後遮擋（假 2.5D）**：MultiMesh 依緩衝區順序一次畫完，不會和斑、菁英、Boss 做 Y-Sort。做法是每幀把近距離層依 y 排序後寫回緩衝區，斑固定畫在敵群之上；遠層不排序。受擊閃白與 Run／Death 影格用 MultiMesh 的 per-instance color／custom data，交給 canvas shader 讀取。
- **時間控制集中**：Hit Stop、寫輪眼 0.15 秒慢動作、升級暫停都經過同一個時間控制器，不各自改 `Engine.time_scale`，避免互相覆蓋。

### Scene 與資料（對齊 AGENTS.md 的 scene 規則）

敵群用資料陣列跑，但畫面與可調的東西仍然放在 scene／resource，編輯器打開就看得到版面：

| 放在 scene／resource | 留在程式 |
|---|---|
| `main.tscn`：World、EnemySwarm、各類型的 MultiMeshInstance2D、Camera2D、HUD | 每隻敵人的位置、HP、狀態 |
| `player.tscn`、每隻菁英與 Boss 的 `.tscn` | 生成時機、LOD 分層 |
| HUD：搖桿、3 顆按鈕、HP／EXP／支配值／擊殺數／計時 | 支配值、音樂層開關 |
| 升級面板＋升級卡片 item scene、結算畫面 | 依資料 `instantiate()` 卡片 |
| `EnemyDef`、`SkillDef`、`UpgradeDef`、波次時間軸：`.tres` Resource | 特效與演出動畫 |

資料 Resource 的寫法可參考 taskbar-hero 的 `data/unit_data.gd`（`extends Resource` ＋ `@export_range`）。

**資料夾依功能分**，素材放在使用它的 scene 旁邊（見 [GODOT_BEST_PRACTICES.md](../../prototypes/godot-kit/GODOT_BEST_PRACTICES.md)），不用原文「scenes／scripts／assets 各一包」的分法：

```
prototypes/survivors/
├── main.tscn, main.gd
├── player/        player.tscn、斑的 sprite、技能控制
├── swarm/         enemy_swarm.gd、spatial_grid.gd、enemy_def.gd、各敵人 .tres 與 sprite
├── bosses/        每隻 Boss／菁英一個資料夾
├── skills/        每個技能一個資料夾：skill_def .tres、shader、特效 scene
├── progression/   升級、進化、三選一面板
├── dominance/     支配值、音樂分層
├── ui/            HUD、搖桿、結算
├── data/          波次時間軸
├── addons/proto_kit/   godot-kit 副本（sync.sh 產生，不要直接改）
└── tests/
```

### 素材

- 角色原圖約 512×512，遊戲中顯示 80–140 px；普通敵人剪影要粗、要好認。asset-gen 最小生成 1K，縮到 64 px 會糊，所以小兵用「一張圖多個物件再 `grid_slice.py` 切」或粗平面造型。
- 動畫：斑做 Idle／Run／Attack／Skill／Hit；普通兵只做 Run／Death。用 asset-gen 的「參考圖 → 姿勢 → 影片 → 抽幀 → 找循環點 → 去背」流程，或 Scenario 的 `scenario-sprite-animation`。每次生成都花錢，第一次付費前先確認。
- 同類素材打包成 atlas，不要散成一堆單張圖。
- 忍術特效不畫逐格動畫：主體 sprite ＋ shader ＋ 粒子 ＋ 閃光。須佐能乎用分層的大型半透明 sprite。
- 美術順序：斑 → 技能 → Boss → 敵人 → 環境。

- **震屏**：debt-commission `scripts/stage_effects.gd` 是移動 Control 圖層的 Tween，做 VN 演出用，這裡要改寫成 Camera2D 的 offset。
- **資料 Resource**：taskbar-hero `data/unit_data.gd`。
- **iOS 匯出**：pixel-monster 的 [MOBILE.md](../../prototypes/pixel-monster/docs/MOBILE.md) 與 [IOS-CICD.md](../../prototypes/pixel-monster/docs/IOS-CICD.md)（Godot 4.7、iOS 16、Simulator smoke、簽署流程）。
- **音樂分層**：Godot 4.7 內建 `AudioStreamSynchronized`（最多 32 軌同步播放，`set_sync_stream_volume` 逐軌調音量），不用自己寫。注意 synth README 提到 Web 匯出的 Sample 模式執行中調音量幾乎沒作用，Web 預覽版可能聽不出分層；iOS 原生版不受影響。

### 沒有，要在原型裡新寫

虛擬搖桿、物件池、EnemySwarm ＋ SpatialGrid ＋ MultiMesh 繪製、預算生成器與波次時間軸、Hit Stop、傷害數字池、EXP 掉落與吸收、三選一抽選、支配值、Android 匯出。

這些先放在 `prototypes/survivors/`。godot-kit 的收錄門檻是「至少兩個原型在用」，等第二個原型也需要（例如搖桿、Hit Stop、物件池）時再抽進 kit。要用外部套件（例如現成的虛擬搖桿 addon）前，先記錄來源、版本、授權與匯出限制。
