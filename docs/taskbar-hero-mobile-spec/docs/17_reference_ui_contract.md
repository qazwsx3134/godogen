## 圖稿還原與編輯

- 按原圖的頂欄、戰場、羊皮紙面板與底部導覽比例製作。六頁的面板起點不同，不統一成相同高度。
- 原始設計座標 941 × 1672；在相同比例驗證外觀，也在 390 × 844 和 320 × 568 驗證導覽、可讀性與邊界。高螢幕的整體等比呈現不得把人物或字體非等比拉伸。
- 文字、數值、進度条、按鈕與卡片為獨立 Godot Control node。各頁 `.tscn` 在編輯器即可預覽，重複元件另存 scene；禁止整張截圖加透明點擊區。
- 直接引用使用者圖稿中的插画、圖示區域，AtlasTexture 記錄來源與 region，不修改原始 PNG。這些圖稿尚無角色透明分層與動畫素材；驗收需明列因此造成的差異，不能把「重用圖片」當作角色素材已完成。
- 新增或大改場景使用 Godot PackedScene／ResourceSaver 製作；產生器只手動執行。正常啟動、匯入及測試不重建來源場景。
- 視覺驗收用明確的 reference fixture 固定 Lv.12、12,480 金幣、320 寶石等圖稿資料；正常遊戲金幣則呈現已載入的存檔和即時戰鬥結果。兩者不可互相寫回污染。

## 本輪功能邊界

六頁的導覽與可見操作要有對應回饋，戰鬥持續使用既有單位與事件。訓練、怪獸選取、背包資料等可先為會話內的互動示範，必須在說明文件和相關回饋中說清楚保存範圍。

商店的 `NT$ 170` 和廣告樣式保留圖稿視覺；本輪沒有真實付款、看廣告或外部 SDK，點擊時說明本機示範。原規格排除廣告 SDK 與後端的界線維持不變。

使用者於 2026-09-28 選擇「提供 opt image 提示詞，我自行製作」。已整理 `../art-prompts/`，本輪不直接生圖。透明人物／乾淨背景尚待提供；動畫另列後续工作。

## 驗收證據

1. 真正啟動主 scene，截取六頁，與對應 PNG 比較；記錄未達 1:1 的區域。
2. 以實際輸入驗證導航、返回、頁內操作、彈窗、暫停／保存，不能只測直接呼叫 signal。
3. 修改 scene 的靜態文字和布局，另存、載入並執行後應保留。
4. 驗證存檔損壞／未來版本保護、战斗奖励一次性、切頁持續戰鬥。
5. 啟動前後來源 scene/resource 雜湊一致。截圖 fixture 和測試使用獨立 user://。

既有 Checkpoint A 的截圖僅是歷史基線，不能作為這一輪六頁圖稿還原的證據。
