## 2. 已看見的元件類別

| 素材特徵 | React用途提案 | 整理方式 |
|---|---|---|
| Use／Hack／Buy／Sell／Decline／Accept按鈕 | 一般動作、方案與接案 | 保留框線造型，中文標籤用HTML文字 |
| 紅色、淺灰與低明度按鈕列 | 預設、選中、停用等互動變體 | 原SVG未提供互動語意，狀態對應由本作制定，不能把明暗直接當hover規格 |
| 勾／叉 | 成功、取消或狀態 | 小型SVG圖示，仍需可讀標籤 |
| 條紋Danger／Accept／Hack／Denied／Warning標籤 | 系統狀態與重大警告 | 條紋裝飾＋HTML標籤，不把Accept也一律做成致命提示 |
| 警告三角、框線與微型字標 | RiskDecisionPanel、結果警告 | 圖示可保留；原微型字不承擔必要資訊 |
| 小型輸入／文字框與數值框 | 裝備、數值與狀態 | 用CSS可伸縮邊框，避免文字擴大後破框 |
| 三角、菱形、十字與多重箭頭 | 任務類別、方向、選中提示 | 篩選必要圖示；不預設所有裝飾都有互動 |
| 角標與進度／數值樣式 | 狀態列與次要讀數 | 配合真實數值和語意標籤，不照原示意小尺寸使用 |

主要視覺語言是紅黑與淺灰、角標／切角、細線、斜紋警告與小型科技字標。本作會保留造型，為直式中文閱讀加大文字與觸控區。

## 3. 色彩與對比量測

實際fill包含 `#AF3931`、`#98231B`、`#3A2321`、`#232323`、`#EAEAEA`與white；大量元素另使用opacity，因此path出現次數不等於畫面面積比例。stroke主要為`#AF3931`。

以下按不透明sRGB色值計算相對亮度比，不涵蓋半透明疊色、模糊效果或所有元件狀態：

| 前景／背景 | 對比比值 | 本作處理 |
|---|---:|---|
| `#AF3931`／`#232323` | 約2.58:1 | 不採作長文或一般小字組合 |
| `#AF3931`／`#101318` | 約3.06:1 | 用於裝飾／較醒目邊框，不作正文色 |
| `#EAEAEA`／`#AF3931` | 約5.06:1 | 可作實色紅按鈕的文字起點，仍需驗證實際狀態 |
| `#EAEAEA`／`#232323` | 約13.06:1 | 適合作為穩定閱讀區的起點 |

整體主題由原先「警示黃主操作」提案調整為「紅色元件骨架、淺灰正文」。高危險用較亮的警示色、圖示、明確用語與區塊層級一起區分；不能所有紅色元件都表示永久死亡。

## 4. 接入React的製作順序

```text
原始SVG保留 → 挑元件類別 → 框線／圖示與路徑字樣分開
      ↓
小型裝飾SVG／CSS → shadcn互動元件 → 中文標籤與狀態
      ↓
360／390／430px直式展示 → 觸控／焦點／長文／高危險驗收
```

不把1.9MB整張總覽inline到每個頁面。先挑ButtonFrame、WarningMark、HazardStripe、Chevron四類裝飾，使用小SVG或CSS；避免新增前就拆出上百個沒用途的資產。

文字、狀態、ARIA、焦點與點擊區都由React元件管理。裝飾層設pointer-events:none，必要時aria-hidden；狀態切換由variant控制。內嵌示意PNG保留在原始參考，不當作本作場景或介面背景。

切角可保留固定角尺寸，中段依內容伸縮；需要SVG defs時ID須避免多次實例化互撞。先用少量元件證明手機外觀，再決定是否拆出更多原圖裝飾。此處是接入計畫，尚未產生衍生元件。
