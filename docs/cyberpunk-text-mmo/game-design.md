# 玩法與世界設計 v0.2

日期：2026-10-29。東京原型城市、每角色一次性委託、聊天／系統訊息、永久死亡、危險節點等待玩家、警方、Trauma Team及升級提高神機錯亂免疫力均已確認。具體名稱、公式與內容量仍為提案。細則見 [風險系統](risk-systems.md) 與 [文本計畫](content-plan.md)。

## 1. 玩家想成為什麼人

玩家是剛抵達城市的無名傭兵。最初只能幫人送貨、找人、處理街頭麻煩；逐漸得到中間人信任，接觸企業機密與地區權力。長期追求是「這座城市開始記得我的名字」。

三個設計原則：每次接案都要能選擇值得做的事；名聲要帶來新人物與新機會；城市的共同變化要可見，個人的故事選擇仍由自己保有。

## 2. 城市提案：東京原型的未來都市

同一時空、以東京為原型的城市，正式名稱未定。高密度鐵道與商業區之間存在地下診所、企業監控與非法義體市場；灣岸物流區由企業與警方控制。城市對原型的改編不作官方2077東京設定宣稱。

### 區域與進程

| 區域 | 氛圍與玩法差異 | 首版狀態 |
|---|---|---|
| 新宿／歌舞伎町原型街區 | 站前商圈、夜生活、地下診所與中間人 | 起始可玩 |
| 灣岸／新木場原型物流帶 | 冷鏈、倉儲、無人機與封鎖線 | 可解鎖、少量可玩 |
| 秋葉原原型電子街 | 義體維修、假貨、資料黑市 | 遠期方向 |
| 丸之內原型企業核心 | 身份權限、企業高樓與武裝保全 | 遠期方向 |

首版只製作前兩區。區域入口會顯示「需要的名聲、介紹任務、城市路線狀態」，並直接連到欠缺條件。後兩區不作首版承諾或可點的空頁。

### 首版人物與勢力

- 中間人A：新宿原型街區的修理店經營者，提供入門工作；姓名待定。
- 中間人B：經營灣岸情報與走私管道，關心消息是否有價值；姓名待定。
- 企業港務部門：用封鎖保護商業利益；名字待定。
- 地下診所與街區互助網：需要物資，也藏有不願公開的交易。
- 碼頭走私圈：能提供捷徑，但每條消息都有價格。
- 本地警方與MaxTac型單位：調查犯罪、追緝與處理失控威脅。
- Trauma Team：提供有條件的武裝醫療與撤離；死亡前能搶救，死亡後不能復活。

首版用少量「人物信任／故事旗標」表達關係，不先做多套可重複刷滿的勢力聲望條。

## 3. 核心循環與遊玩節奏

```text
查看委託 → 選擇解法／配裝 → 自動執行 → 閱讀結算
    ↑                                      ↓
新案子與新人物 ← 名聲／關係 ← 報酬 → 裝備改善
    │
    └→ 關鍵劇情手動選擇 → 改變後續案源與人物態度

一般委託的有效成果 → 城市事件目標 → 全服開通新路線
```

短次遊玩目標是查看戰報、調整裝備、選下一份案子；較長次遊玩則推進一段重要劇情。使用者已明確指定手機直式為主要介面，電腦作相容延伸。

### 自動執行的邊界

- 首個可玩切片同時執行一份委託，按下執行後自動跑完整段；離線也計時。這是最小驗證範圍，不等同最後放置深度。
- 任務完成後停止接新案；同角色不重接已結案委託，新角色可重玩。離線只推進已接受案件的安全流程，不自動創造新委託或重複收益。
- 建議初始耗時：教學 30～60 秒，一般委託 2～8 分鐘；屬待調校假設，測試可快轉。
- 正在執行的任務使用出發時的裝備與內容版本；途中換裝只影響下一案。
- 重要劇情與重大危險節點都停下等待玩家，離線不代選、不偷偷進入致命段。自動紀錄可加速或略過，重要資訊保留在結算頁。
- 永久死亡是核心規則。玩家確認可致命行動後，由伺服器一次結算生還、救援或死亡；不因重整重抽，也不讓已死角色復活。撤離代價在選擇前明示，詳見風險系統。

## 4. 角色與配裝：三種解題方向

首版不鎖死職業；角色等級提升基礎能力及神機錯亂抗性，裝備調整「火力、入侵、潛行」三種解題能力。先不加入永久配點與洗點成本。義體另帶固定負荷，任務可能累積神經壓力，見風險系統。

| 方向 | 解題感受 | 任務用途 |
|---|---|---|
| 火力 | 壓制敵人，突破危險路線 | 護送、設施破壞、救援 |
| 入侵 | 控制設備，竊取與解讀資料 | 金鑰、無人機、監控 |
| 潛行 | 避開接觸，在不驚動目標下完成 | 跟蹤、取件、秘密撤離 |

首版三個裝備欄：武器、作業設備、義體。每件裝備有固定能力與用途標籤；建議先做 9 件、無隨機詞綴、無強化失敗。談判解法初期由情報與人物關係解鎖，不再加第四條培養樹。

不以單一總戰力判斷所有任務。同一份委託可提供兩種可行方案，介面指出各自需求與預估評級；提高某個能力會實際改變可選路線或結果。

## 5. 任務規格與結果

每個委託需有獨立事件與後果，同角色不重複。資料含委託人、前置、方案、能力需求、耗時、危險節點、報酬／經驗／名聲、警方暴露、神經壓力、醫療條件、事件貢獻與後續旗標。

玩家先看到報酬與風險，再選解法。首版採可解釋的條件判定；若加入隨機風險，須先定義可理解的資訊與伺服器固定結果，不能重整重抽。

案件結果包括完整達成、勉強完成、撤離、失敗或死亡；救援成功是角色生還狀態，不自動算任務成功。結算指出準備與決策如何影響結果。危險節點先明示可能永久死亡，不把死亡藏在一般評級裡。道德選擇不貼上單一最佳評級，也不直接計入競技分數。

### 範例：取回失竊晶片

```text
接案 → 調查失竊貨物 → 自動執行選定方案 → 取得晶片
                                                  ↓
                                      發現非法實驗證據
                                                  ↓
                      ┌───────────────┼──────────────┐
                   交還委託人       提供給診所       私下出售
                      ↓               ↓              ↓
                   企業後續案      街區後續案       黑市後續案
```

首版讓分支改變一段後續對話、一個委託入口與人物態度，再匯回共同主線，避免每次選擇都使內容量倍增。選擇頁說明可預見的利害關係，不預告所有故事。

## 6. 經濟與名聲

- 一種主要貨幣，暫稱信用點；從不同的一次性委託取得，用於裝備、任務準備與醫療。不能假設玩家可重刷補足成本。
- 等級／經驗、街頭名聲與關係分開。名聲開放案源與區域；等級提高能力與神機錯亂抗性。以各條可達案件路線試算資源與門檻，避免有限內容造成軟鎖。
- 進入新區不要求同時消費名聲；名聲是資格，不是門票貨幣。
- 第一筆報酬應能買到一件真正改變解法的裝備。跨區成長避免舊裝備立刻全無用途。
- 第一輪平衡用「完成幾案能換裝／跨區」推算，不先做指數膨脹的貨幣與等級曲線。
- 首版無抽卡、玩家交易、拍賣、公會稅與付費加速；這些另列後續，不構成商業模式定案。

## 7. 非同步共同事件：封鎖線

事件目標三條：民生補給、情報、設施破壞。由多份不同的一次性委託貢獻，全部完成便永久開通灣岸路線。事件門檻需符合每角色有限案源；新角色重玩不能無限制刷帳號事件獎勵，細則見文本計畫。

事件面板顯示城市現況、三項進度、可貢獻委託、個人有效貢獻與重大里程碑；城市公共聊天與獨立系統廣播列入首版。真人即時組隊與全服劇情投票仍不列入。

個人任務獎勵與事件貢獻分開記帳；一份任務不能因重連重複加進度。事件結束後仍可做相關個人案子，面板明示不再增加本事件的有效進度。

後進玩家保有個人故事與進入資格；共同路線維持已開放，不重演首殺才能跨區。首個事件不設倒數失敗。小規模測試採獨立測試世界、低門檻與明示的管理操作，不用假玩家自動灌進度；正式門檻依封測參與量調整，事件開始後不偷偷改目標。

## 8. 排行榜

| 榜 | 目的 | 初版規則 |
|---|---|---|
| 街頭名聲榜 | 生涯資歷與傳奇紀錄 | 總名聲；同分同名次，標示存活／死亡 |
| 每週委託榜 | 當期案件成果 | 一次性案子計分；進度分組與計分規則待模擬 |

週榜不能以重刷同一委託支撐。需比較新進與章末角色的案源／評分機會，才固定分組與公式；不承諾重置週榜就自然公平。死亡角色保留歷史成績，新角不能把前角分數合併到自己。累積名聲與生涯紀錄先於週榜完成。

週界線建議採週一 UTC 00:00（台灣 08:00），畫面顯示下次結算時間；伺服器固定規則。計分以任務的既定完成時間歸屬，延遲結算不得把分數搬到新週。週榜先標示結算中，補完截止前到期工作再封榜；詳細流程見開發計畫。

排行先提供稱號／展示方向，不發強力裝備，避免領先者獎勵擴大差距。首版不做跨服、段位或多季歷史頁。

## 9. 介面與視覺方向

React／shadcn／Tailwind的具體元件對應、手機版面、色彩與參考取得情況見 [UI系統](ui-system.md)。使用者已提供cyberpunk元件參考，視覺tokens與尺寸尚待實作試看。

採傭兵工作終端的感覺：深色背景、高可讀文字、少量警示色、城市新聞與中間人訊息。敘事有生活感與黑色幽默；具體文風待試讀。不用大量閃爍、故障字或小字營造科技感。

手機直式採單一主閱讀區、底部五入口（委託、角色、城市、排行、紀錄），另有可收合通訊抽屜。頂部只常駐最必要的生命／任務／通緝提示，其餘狀態點開查看。玩家聊天、官方系統廣播、個人任務紀錄具不同來源標示。角色頁包含等級、抗性、負荷、壓力與醫療保障；危險節點在主區集中呈現風險、保障與選項，不被聊天或底部導覽遮擋。電腦可延伸側欄，但閱讀順序與手機一致。

```text
手機直式                    電腦
┌────────────────┐          ┌────────┬────────────────┬──────────┐
│ 生命／通緝提示 │          │ 導覽   │ 任務／劇情主區 │ 通訊側欄 │
├────────────────┤          │        │                │ 執行紀錄 │
│ 任務或劇情主區 │          └────────┴────────────────┴──────────┘
│ 危險風險與選項 │
├────────────────┤
│ 案件狀態／通訊 │
├────────────────┤
│ 五個主要入口   │
└────────────────┘
```

選項不能只靠顏色區分；觸控區建議至少44px，支援鍵盤操作與減少動態效果。先驗證360～430px直式寬度、Safe Area、長文字及軟鍵盤開啟的聊天輸入，不能水平溢出或遮住送出／生死選項。切回分頁重新同步。首版用文字、CSS與必要圖示即可成立；AI圖片另依作者選擇直接生成或opt image prompts。

## 10. 首版內容清單與體驗驗收

| 內容 | 建議數量／範圍 |
|---|---|
| 區域 | 2 區；新宿原型起始區＋灣岸原型解鎖區 |
| 中間人 | 2 人 |
| 一次性委託 | 先6案可玩切片，再擴為24案小型封測；教學融入案件 |
| 故事線 | 一組連貫人物與案件，具選擇、失敗後續與章末收束 |
| 裝備 | 9 件固定裝備、3 個欄位 |
| 共同事件 | 1 件、3 類目標 |
| 排行 | 累積名聲／生涯紀錄，之後接每週案件榜 |
| 生存與治安 | 永久死亡、危險節點、通緝0～5、條件式醫療撤離 |
| 神經負荷 | 等級提升抗性、義體負荷與任務壓力 |
| 通訊 | 公共聊天、系統廣播、個人紀錄 |
| 帳號 | 一帳號一個活躍角色；死亡留檔後可建新角，跨裝置使用 |

首輪30分鐘目標：接觸第一案 → 報酬換裝 → 在下一份獨立案件選方案 → 遇到重要故事／危險選擇 → 了解醫療與通緝 → 看見共同事件與第二區條件。實際六案不要求30分鐘全跑完，也不保證當時全服已開通第二區。

真人驗收需回答：玩家能否自行找到下一步？能否說明換裝為何影響結果？是否在乎故事選擇？能否分辨自己的名聲與全服貢獻？是否想接下一份案子？
