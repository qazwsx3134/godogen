# 手機直式 Cyberpunk 元件設計規範 v0.3

日期：2026-10-29。使用者指定本機`ui/`圖片作為元件設計參考、規範與目標。已逐一檢視16張JPG及先前example.svg；來源對應見 [圖片索引](ui/README.md) 與 [SVG盤點](svg-reference.md)。本文件是後續實作與review的設計基線；精確尺寸、語意色與互動細節是依手機需求制定，尚未經真人或runtime驗收。這輪未建立元件程式。

## Design Context

### Users

喜歡Cyberpunk世界與文字RPG的玩家，主要用手機直式接案、閱讀劇情、決定生死風險與聊天。短次回訪要看懂進度，長次閱讀要能舒適看完獨立案件。永久死亡使操作清晰與結果可信成為主要需求。

### Brand Personality

工業、緊張、有生活感。介面像東京街頭傭兵的工作終端；人物語氣、任務與城市廣播形成世界感。安全流程可自動跑，重大危險則由玩家親自決定。

### Aesthetic Direction

設計目標是一台能讀長篇委託、辨識生死風險的傭兵工作終端。依本機圖片的HUD、資料檔案、直式電梯／對講機與設備面板，採深底、紅色元件骨架、淺灰正文、青色資訊提示、局部黃色警戒；以切角、角標、細線、編號與斜紋建立共同語法。

同一套元件用固定語意色表達狀態，不每頁換一套設備主題。作品集的黃色展示底、四角FPS佈局、極細小字與曲面硬體框不作本作常態版面。原SVG色碼可確認，JPG只作視覺語法與狀態參考；未從圖片辨識出原字體名稱。

### Design Principles

1. 主要閱讀區與下一步選項優先，手機不縮成桌面HUD。
2. 框線與標籤帶出cyberpunk風格，正文保持高對比與足夠行距。
3. 生死風險、醫療保障與行動後果在同一個主畫面看懂。
4. 玩家聊天、系統廣播、私人紀錄明確標來源；不靠顏色獨力區分。
5. 效果不得干擾觸控、焦點或閱讀；斷線不虛報成功。

此背景只適用本作。建立遊戲專案後可存為該遊戲的`.impeccable.md`，不寫入generator source根目錄以影響其他作品。

## 2. 元件的三層

```text
shadcn/ui 互動元件來源
        ↓ CSS tokens＋Tailwind variants
遊戲元件：TerminalPanel／ChoiceAction／RiskPanel／MessageRow
        ↓
手機頁面：委託／角色／城市／排行／紀錄＋通訊抽屜
```

shadcn/ui元件加入本專案後可調整來源，統一用Tailwind與CSS變數換造型，不每頁另寫一套樣式。使用單一primitive家族，建議選Radix版相關元件並在初始化記錄preset，避免不同元件混用不相容props／樣式API。具體版本建專案時驗證。

斜切框用CSS／裝飾性SVG與pseudo-elements實作，按鈕保留真實button語意與完整觸控區。不要對整個可互動容器直接裁切，導致focus ring、popover、文字或點擊區缺角；裝飾層不可攔截指標。

| Collapsible／Accordion | EquipmentDetails／RiskDetails | 展開次要數值；關鍵死亡風險不藏起來 |
| Dialog／AlertDialog | RareConfirmation | 只用在必要不可逆操作，具標題、描述與明確取消 |
| Sheet／Drawer | CommsPanel | 手機通訊，能收合、處理焦點、Safe Area與軟鍵盤 |
| Tabs | CommsTabs／RankingTabs | 頻道與資料內切換；五個主入口用路由，不全塞Tabs state |

| Separator／Skeleton／Alert | TerminalSection／Loading／ConnectionNotice | 結構、載入與持續連線提示 |

任務列表以案件編號、人物、簡短衝突及狀態形成閱讀節奏；不要每個資訊項都包相同卡片。正文使用自然段落；選項各自有清楚動詞，避免只寫「確認」。

## 4. 色彩、字體與尺寸基線

| token | 初始值 | 依據與用途 |
|---|---|---|
| background | `#101318` | 本作提案，深色頁底 |
| surface | `#232323` | SVG實際色，穩定閱讀平面 |
| foreground | `#EAEAEA` | SVG實際色，正文與按鈕文字 |
| muted-foreground | `#AAB3BE` | 本作提案，次要資訊 |
| primary | `#AF3931` | SVG實際色，主按鈕底與元件骨架 |
| primary-foreground | `#EAEAEA` | SVG實際色，紅底上的文字 |
| primary-pressed | `#98231B` | SVG實際色；用於按壓狀態是本作提案 |
| surface-accent | `#3A2321` | SVG實際色，紅調次要平面 |
| destructive | `#F06A72` | 本作提案，高危險前景或按鈕底，搭配明確文字 |
| destructive-foreground | `#101318` | 高危險實色底上的深色文字；不能沿用淺字而降低對比 |
| warning | `#E7D34A` | 本作提案，警戒／限制；不用作整頁背景 |
| warning-foreground | `#101318` | 黃色實色底上的深字 |
| signal | `#6FCAC3` | 本作提案，資訊／通訊與焦點提示，不等於保障有效 |
| positive | `#82D8AB` | 本作提案，已完成／有效等狀態，仍附圖示與文字 |
| border | `#39424E` | 本作提案，低干擾結構線；選中時可用主色 |

映射到shadcn的background／foreground／primary／destructive／border等語意token，另外加wanted、neural、medical用途token。CSS變數集中維護，可改色不用逐頁找Tailwind色碼。實作可轉OKLCH；色彩對比須實測，不把提案色票當無障礙已通過。

本次已計算不透明色值：原磚紅對深灰約2.58:1，不用作一般小字；淺灰對實色磚紅約5.06:1，作主按鈕文字的起點。半透明、hover、focus、disabled與整體無障礙仍待實測。不能只因原圖有小字就照尺寸縮進手機。

繁中正文預設17px、行高1.8，可調16～20px；介面標籤14～16px、區段標題18～20px，頁面標題24～28px。案件ID與時間可用少量等寬拉丁字體；可讀中繼資料至少12px，會影響決策的標籤至少14px。裝飾性微型字不承擔必要資訊。字體建議Noto Sans TC等適合長文的字體，來源與載入預算在實作固定。

間距以4px基準，手機側邊16px（寬螢幕可20px）、面板內距16px、區段間距24px。主要選項高度至少48px、次要控制至少44px；多行選項高度自適應，padding至少12px。普通線框1px、選中／focus用2px並預留空間避免跳動。可按項之間至少8px。

主面板固定右上切角8px、按鈕切角6px作起點；其他角保持直角，避免每個元件都有不同輪廓。改變尺寸時切角不等比例放大。普通正文區不需要完整發光描邊，每區至多一個主操作採實色強調；其他選項以outline／低干擾狀態呈現。

色彩、間距、字級與切角都由同一組tokens／variants定義。新增元件不得自行發明色碼與切角尺寸；有新需求先更新本規範。必要文字對比的本作目標至少4.5:1，關鍵互動輪廓／焦點至少3:1；只量過少數色值不代表整套通過。

## 5. 手機直式版面

```text
┌──────────────────────────┐
│ 存活   LV.04      通緝 ★★ │  精簡狀態列
├──────────────────────────┤
│ CASE 004  高架橋下的槍聲  │
│ 委託／劇情正文            │
│                          │
│ 【重大危險】              │  RiskDecisionPanel
│ 生存風險、義體壓力、保障  │
│                          │
│ [從地下維修道撤離]        │  動詞明確的選項
│ [攜帶證據穿越路障]        │
├──────────────────────────┤
│ 通訊  3則未讀        展開 │  收合的通訊入口
├──────────────────────────┤
│ 委託 角色 城市 排行 紀錄  │  底部路由導覽
└──────────────────────────┘
```

360／390／430px直式先設計，再延伸平板／桌面。正文單一垂直捲動；避免整頁、故事框、選項與聊天各自捲動造成手勢衝突。

外殼使用動態viewport高度與Safe Area；底部導覽的實際高度留在內容padding中。軟鍵盤開啟時聊天輸入保持可見，必要時導覽暫隱；必須以真機驗證，不只靠固定100vh。輸入框至少16px，避免行動瀏覽器不必要的輸入縮放。

通訊展開成接近全高的Sheet／Drawer，與任務主畫面互斥操作；有新訊息只增加未讀，不在故事中間強制捲動或彈窗。危險頁仍可讀通訊，但返回後保留選項與閱讀位置；未送出的致命選擇不自動送出。

## 6. 不同結果如何呈現

- 等待危險選擇：顯示暫停、沒有倒數；關閉網頁不會替玩家選。
- 送出選擇：鎖定重複點擊，顯示處理中；失聯時顯示結果尚待同步，不能讓玩家隨意選另一條重抽。
- 救援成功：報告標示角色生還、任務結果、傷勢與帳單，不顯示死亡後復活。
- 永久死亡：完整生涯結尾頁，清楚標示角色已死亡與唯讀紀錄，提供建立新角入口；不只一個短toast。
- 系統廣播：具可信來源欄位與獨立造型；玩家輸入同樣字句也只是玩家訊息。
- 離線：顯示上次同步時間，停用不能確定有效的遊戲操作；不假裝能離線下注生死。

## 7. 動態與驗收

動態主要用在狀態切換、展開通訊與結算抵達，約120～200ms作初始提案。常態正文無閃爍，prefers-reduced-motion下移除非必要動態。警示不靠紅色閃爍、假倒數或強制打字動畫製造壓力。

第一批展示頁先實作SVG對應的紅黑按鈕、條紋狀態標籤、警告面板與通訊列，再涵蓋長任務名、長中文選項、五級通緝、神經負荷、醫療保障、聊天斷線、死亡生涯、新角、空列表與伺服器錯誤。展示資料明示為測試，不當作真實多人證據。

手機驗收看：一隻手能否讀與操作、文字放大不溢出、鍵盤不蓋輸入、通訊不蓋生死選項、焦點可見且順序正確、最長案件正文能否舒服看完。L2元件互動／瀏覽器冒煙以實際行為驗證，不測每個Tailwind class是否存在。

## 9. 元件合約與參考目標

下表是實作清單；不是額外增加遊戲功能。shadcn基礎互動之外，遊戲元件須滿足自己的文字、風險與狀態責任。使用來源圖的編號對應 [本機圖片索引](ui/README.md)。

| 元件 | 視覺／結構依據 | 必要內容與狀態 | 完成目標 |
|---|---|---|---|
| TerminalPanel | SVG、17、32 | 標題、編號、內容、可選狀態列 | 固定切角、中段可伸縮；長內容不截斷 |
| ActionButton | SVG、29、32 | 動詞、pending、disabled原因、必要圖示 | 預設／按下／選中／鍵盤focus皆可辨識；點擊區至少44px |
| ChoiceAction | 29、SVG | 方案、風險摘要、條件與選中狀態 | 48px以上自適應高，三行中文仍完整；選中與正式送出分開 |
| MissionListRow | 03、05、29 | 案件編號、人物、衝突摘要、可接／等待／已結案 | 一眼找到當前案；已結案不偽裝成可重接 |
| StoryReader | 17的資料分組、本作閱讀需求 | 說話者、正文、重要情報、合法選項 | 17px基準長文，放大仍可讀；通訊返回後保留閱讀位置 |
| StatusStrip | 04 | 生命狀態、等級、通緝摘要；其餘展開 | 頂部精簡，0～5星與死亡文字不被省略；不塞全角色數值 |
| NeuralLoadMeter | 04、08、09 | 抗性容量、義體負荷、壓力、安全餘裕與階段 | 負荷與剩餘容量方向明確；警戒／臨界有文字，不只變色 |
| MedicalCoveragePanel | 17 | 保單是否有效、覆蓋、救援條件、自付額 | 青色邊框不等於保證能救；無保障與無法到達可區分 |
| RiskDecisionPanel | SVG警告、05、29 | 可致命說明、傷勢／通緝／神經壓力、保障與合法行動 | 危險頁完整呈現關鍵資訊；沒有虛構機率／倒數；送出只判定一次 |
| EquipmentSlot／ItemRow | 11、12 | 欄位、名稱、能力變化、義體負荷、已裝備 | 三個欄位清楚，選中不等於已穿戴；不照搬多格密集背包 |
| RegionAccess | 04、05、14、29 | 地點、名聲、任務前置、共同路線狀態 | 選中／可進入／受限／未解鎖分開；欠缺條件可閱讀 |
| CityGoal | 05、08 | 目標名、目前／需求、有效貢獻、完成狀態 | 同步有時間依據；不把等待選擇的案件加為已完成 |
| CommsPanel | 30、29 | 公共聊天／系統頁籤、未讀、連線狀態、輸入 | 近全高抽屜，鍵盤不蓋送出；新訊息不奪取故事閱讀位置 |
| ChatMessage／SystemBroadcast | 05、17、30 | 來源、時間、正文、pending／已送／失敗 | 玩家、官方與私人紀錄用結構／文字辨識，玩家不能偽裝官方 |
| ServerStatePanel | 29、30 | 等待／同步中／失聯／拒絕／可重試原因 | 每種狀態有不同文案與下一步；不能以一直轉圈掩蓋錯誤 |
| ResultReport | 05、17 | 任務結果、經驗／名聲／貨幣、傷勢、帳單、後續 | 重要後果持續可回看；只有伺服器確認後顯示已完成 |
| CareerRecord | 17、05 | 生涯身份、成績、存活／死亡、最終事件、新角入口 | 死亡為唯讀終點，有完整頁面；不出現正常復活操作 |

圖示初始採同一筆畫／幾何家族，20～24px為一般尺寸；裝備輪廓可較大。每個關鍵圖示附可見文字或明確名稱，圖示按鈕有可辨識的輔助名稱。對原圖概念、未採用替代稿只借語法，不複製成首版需求。

## 10. 狀態、互動與生死決策規範

### 共用狀態語法

- idle：低干擾框線，主要操作與次要操作可分辨。
- pressed：短暫底色／框線變化，不移動版面；手機無hover也能看懂。
- selected：形狀／勾記＋文字或框線強調；與已提交狀態不同。
- focus-visible：持續可見的2px外框或等效高對比指示，切角不得裁掉。
- pending：保留原動詞與處理中提示，停用重複送出；圖示可動但文字不消失。
- disabled：不可操作且說明原因；不得把hover當成唯一說明入口。
- error：顯示可恢復與不可恢復原因，提供正確下一步，錯誤正文不自動消失。

選中、焦點與連線狀態是不同維度，不共用同一個布林值。無法確定結果時顯示「正在確認結果」，不能一律顯示「失敗，重新選」而允許重抽。視覺variant不承擔權限或生命判定。

### 高風險決策的內容順序

```text
案件／目前節點
    ↓
可致命結果與主要威脅
    ↓
傷勢、警方、神經負荷、醫療保障
    ↓
行動方案與代價 → 選定方案 → 明確送出
    ↓
等待伺服器確認 → 結果／同步提示
```

確認區可以在同頁展開，不要求每個故事選擇都再彈一層Dialog。關閉通訊、切頁或按返回只關介面／導覽，不視為已選撤離或同意冒險。若選項高於一屏，危險摘要仍在前方閱讀順序；不得為了「所有按鈕同屏」縮小字體。

角色生還、救出與死亡是資料結果；外框顏色／動畫不自行宣告。死亡報告與新角建立以不同步驟呈現，避免誤觸抹掉生涯紀錄。沒有保單時清楚寫出狀態，不用誤導性的青色醫療勾記。

禁止只替一般後台卡片加紅框就稱為完成：元件至少要在標題／編號、切角／角標、資訊層級、互動狀態中形成一致語法。也不以每項全加斜紋、故障效果或發光來提高辨識度。

使用原圖作對照與來源，不直接把整張JPG／SVG鋪成介面。正式畫面每一個文字、讀數與按鈕都可由資料與元件調整；公開bundle不含整份參考圖集。原始參考不覆寫、不用AI改圖替代。

## 12. 製作順序與可驗收目標

先用明示測試資料做同一套元件展示，不先做完整遊戲，也不把展示狀態當真實連線成果。

| 批次 | 交付 | 需要看見的證據 |
|---|---|---|
| A：元件語法 | tokens、TerminalPanel、ActionButton、標籤／圖示、ServerStatePanel | 同頁比較idle／pressed／selected／focus／pending／disabled／error；長標籤完整 |
| B：任務閱讀 | 委託列、StoryReader、ChoiceAction、RiskDecisionPanel、醫療摘要 | 一段真實長文與3行中文選項；明確指出可能死亡與當前保障 |
