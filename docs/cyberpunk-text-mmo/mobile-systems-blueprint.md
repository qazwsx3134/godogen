# 手機優先文字冒險：系統藍圖 v0.1

日期：2026-10-29。本作仍保留共享城市、非同步合作與排行，沒有改成純單機。本文把既有需求與Lead評估轉成手機玩法提案；新規則、節奏與效果需試玩，未把全部提案標成已驗收。

> 2026-11-04：使用者確認改為雙層任務（劇情委託一次性＋可重複的街頭工作）。本檔中「每角色委託不重複」「有限經濟」「週榜不能靠重刷」等敘述，以 [quest-layers.md](quest-layers.md) 為準，受影響段落列在該檔 §9。

## 1. 產品骨架與時間規則

核心體驗是用手機扮演一名傭兵，讀懂局勢、準備、選擇值得承擔的風險，讓人物與城市對自己的做法作出回應。

```text
中間人訊息 → 委託簡報 → 情報與配裝 → 自動執行安全段
                                          ↓
                           重要劇情／重大危險等待玩家
                                          ↓
                             行動選擇 → 確認 → 結果
                                          ↓
                     報酬／人物後果／成長／城市貢獻
                                          ↓
                            返回安全地點或開啟下一案
```

手機主畫面一次只處理一件當前任務。底部沿用委託、角色、城市、排行、紀錄五入口，通訊抽屜隨時可收合。詳情按需展開，危險摘要與合法行動在同一閱讀流程中。

時間分成三種，資料與文案不能混用：

| 時間 | 什麼會推進 | 手機離開時 |
|---|---|---|
| 一般執行時間 | 已選方案的安全段，伺服器due_at | 繼續至結果或等待節點 |
| 案件內情境時間 | 玩家選擇調查、繞路等明示耗時行動 | 等待選擇時凍結，不因讀得慢扣時 |
| 城市公共時間 | 其他玩家貢獻、排行與公告 | 世界繼續，但不改寫已開始案件的危險條件 |

重大危險／故事節點沒有現實死亡倒數。準備、傷勢與保障鎖在案件／遭遇快照；返回應用不重抽結果、不清通緝。沒有額外加入未授權的即時搶救或反應QTE。

## 2. 各系統如何玩

### S01 角色與生涯

- **手機呈現**：姓名、當前生涯、等級、名聲、生命狀態；詳情在角色頁，首頁只留摘要。
- **玩家決定**：選擇起始配裝方向（火力／入侵／潛行）與之後的裝備，首版不鎖死職業。
- **規則**：帳號與生涯分開；每帳號一個活躍角色，死亡生涯保存唯讀紀錄。新角可重玩案件，不繼承前角戰力的既有提案維持。
- **好玩目標**：玩家能說出「我這次準備怎麼做事」，而不只是選一張頭像。起始配裝是本輪提案，不另加三套出身長篇。

### S02 委託與案源

- **手機呈現**：像工作訊息的案件列表；卡列有委託人、衝突、報酬、所在地與風險摘要，點開才讀完整簡報。
- **玩家決定**：接哪件案、為誰辦事、想保住什麼；有並行案源時先顯示少量當前最相關案件。
- **規則**：同角色同案只結一次；完成、失敗、撤離都留下紀錄，新角獨立進度。接案前查看與取消準備不耗掉案件。
- **好玩目標**：下一案帶來人物或局勢的新問題。互斥案源須事前提示會失去的機會，不能在無提醒下斷掉整條生涯。

### S03 情報與調查

- **手機呈現**：簡報分「已知事實／來源說法／尚未確認」，關鍵線索點開可回看；不靠玩家記住數十頁小字。
- **玩家決定**：是否查監控、問熟人、實地觀察；每案先設少量有差異的情報行動。
- **規則提案**：情報開啟方案、指出風險來源或更正委託人說法；不是統一加成功率。花信用點、欠人情或耗案件內時間的成本先明示。
- **好玩目標**：仔細讀的人能提出更好的計畫。必要生死風險不能只藏在可漏掉的支線句子裡；同時不把所有人物真相提前揭底。

### S04 劇情與人物關係

- **手機呈現**：說話者＋自然段落＋少量選項。每段約80～180字元作起點，依語意分段；完整案件可長，不強迫每句按繼續。
- **玩家決定**：說出哪些情報、答應誰、守約或背棄；重要選項用明確意圖描述。
- **規則提案**：用少量人物記憶旗標保存具體事實，如「保住病患」「出賣消息」，後案回收。先兩名重要人物與一條祕密，再擴展勢力。
- **好玩目標**：關係改變會帶來可指出的反應與機會，不只出現一條好感加減。個人NPC後果不直接改成全服共同事實。

### S05 行動、戰鬥與撤離

- **手機呈現**：出發前選方案；執行中顯示精簡行動紀錄。普通流程自動跑，重要策略變更或致命關口停下。
- **玩家決定**：目標優先順序、路線、使用的設備；交火時可選本案允許的壓制、過載、掩護撤離等行動，不逐次點普攻。
- **規則提案**：火力／入侵／潛行能力、裝備用途標籤、情報與當前狀態共同決定結果；不存在每案固定都有的三個按鈕或通吃姿態。
- **好玩目標**：保人、保資料、壓低暴露、完整拿報酬之間有值得取捨的結果。成功、勉強、撤離、失敗與死亡分開；重整不重抽。

### S06 等級與裝備

- **手機呈現**：三個裝備欄（武器、作業設備、義體）＋可讀物品列，選物品顯示下一案的能力與負荷變化。
- **玩家決定**：買哪件工具、保留哪種打法、是否承擔更高義體負荷。先做固定物品，無強化失敗與隨機詞綴。
- **規則提案**：經驗來自有限的一次性案件；升級增加基礎能力與抗性容量。裝備可提供少量跨案用途，如遮蔽監控／短時過載／緊急穩定；初期不先加大型技能樹。
- **好玩目標**：升級後曾經危險的準備變得可行；物品用途能改變方案。不得用全敵人同步升級抹掉成長感，也不得要求刷已結案任務練等。

### S07 神機錯亂抗性與壓力

- **手機呈現**：一個餘裕摘要，展開看抗性容量、固定義體負荷與神經壓力。穩定、警戒、臨界均有文字。
- **玩家決定**：動用高負荷能力、先治療、在下一案前降低改造負擔，或在合法節點撤離。
- **規則**：沿用risk-systems的容量減負荷減壓力提案；治療處理壓力，固定負荷需改裝。等級提高免疫力，仍需配合裝備與壓力；係數未定。
- **好玩目標**：玩家能理解為何接近失控，選擇是否為眼前目標冒險。失控不是自動死亡／五星，也不在離線等待時偷偷引發致命結果。

### S08 警方與通緝

- **手機呈現**：0～5星及「追蹤／路障／重裝單位介入」文字，案內顯示哪些路線受影響。
- **玩家決定**：處理監控、帶走或銷毀證據、走繞路、承擔高星撤離；不是每次只等清星。
- **規則**：依被發現的行為、辨識證據與升級事件變化；普通巡警到MaxTac型單位維持既有方向。名聲、通緝與神機錯亂分開。
- **好玩目標**：改變可行動作，而不只是提高敵方傷害。離開網頁不清星；等待玩家時警方也不繼續造成傷害。

### S09 傷勢、治療與Trauma Team

- **手機呈現**：生命狀態、傷勢影響、保障摘要。危險頁直接顯示目前保障、覆蓋與已知限制，完整條款再展開。
- **玩家決定**：出發前投保、在安全地點治療、安排其他撤離方案，或接受沒有保障的風險。
- **規則**：先一種保障服務；使用遊戲內貨幣。可救傷勢、訊號／位置、到達時間與生存窗口共同判斷。成功救出仍有任務後果與帳單；死後無法靠保單復活。
- **好玩目標**：保障讓特定冒險值得考慮，未投保也有合理保守路線。費制與有限案源一起試算，首版不做離線自動扣保費。

### S10 經濟、商店與恢復

- **手機呈現**：信用點、真正會用到的裝備／服務、購買後變化與剩餘資金；不做巨大商城頁。
- **玩家決定**：錢用在工具、情報、恢復或保障，並理解它們如何影響下一案。
- **規則提案**：單一主要貨幣、固定商品；不加入抽卡、拍賣或玩家交易。每條主要路線盤點淨收入與必要成本，確保失敗後仍有可玩的後案。
- **好玩目標**：消費是在選策略。欠款可改變可用消費與案源，但不能形成活著卻永遠無案可接的軟鎖；不靠無限補助或原案重刷補洞。

### S11 名聲、人脈與區域資格

- **手機呈現**：名聲階段與下一個明確機會；人物頁顯示最近的重要往來，而非滿屏關係條。
- **玩家決定**：建立怎樣的辦事紀錄、維持哪些信任、願意犧牲哪些機會。
- **規則提案**：名聲代表資歷，人物記憶決定特定入口；高名聲不自動抵銷背叛。城市路線與個人介紹資格分開；名聲不作可消費門票。
- **好玩目標**：成長開新案源、新解法與新人物；不只是讓同類任務數字變大。角色標籤／稱號先由真實經歷產生，不再加一套可刷人格值。

### S12 城市、移動與區域解鎖

- **手機呈現**：區域路線圖／列表，點地點展開氣氛、人物、案源與限制。起始新宿原型街區、後續灣岸原型區。
- **玩家決定**：去哪個當前可達地點、先見誰，案內採哪條路線。
- **規則提案**：城市頁選地點；有風險的移動屬具體案件／撤離節點。首版不加漫遊中隨機離線死亡，也不加每走一步就重複抽事件的收益循環。
- **好玩目標**：新區帶來不同問題與人脈。地圖服務方向與資格理解，不先製作3D城市；新玩家可補個人條件進入已被全服開放的區域。

### S13 共享城市事件

- **手機呈現**：一張事件簡報、三條有名字的共同目標、目前可參與的獨立案件與已開啟援助。
- **玩家決定**：透過哪件自己的案子貢獻補給／情報／設施破壞，選擇想參與的城市目標。
- **規則提案**：同角色不重刷；首版建議同帳號對同事件的同一案只計一次有效貢獻，避免重建角色刷進度。別人達標可替未來案件開路線／援助，已開始案件保留原快照。
- **好玩目標**：能指出另一人的成果如何改變自己的選項。共同事件不替玩家做私人故事選擇；獨自遊玩仍有可用替代路線，首個事件無失敗倒數。

### S14 聊天、廣播與通知

- **手機呈現**：可收合通訊抽屜，公共聊天與系統分頁，個人後果進入紀錄；回主畫面保留閱讀位置。
- **玩家決定**：交流路線／城市狀態、閱讀公告、封鎖與檢舉；聊天不是通關必填步驟。
- **規則**：官方來源由伺服器認定，訊息可補讀；輸入與傳送狀態清楚。首版公共文字頻道，無私訊／語音。死亡後聊天身份政策仍待決定。
- **好玩目標**：聊天幫助形成傭兵社群，新訊息不蓋住危險選項。通知先用站內未讀，Web Push非目前首版承諾；不以通知逼迫玩家回來避免離線死亡。

### S15 排行與傳奇身份

- **手機呈現**：自己的位置、相鄰名次、角色稱號／代表紀錄，點開看公開生涯摘要。
- **玩家決定**：追求名聲、完成特定案件的表現，或以自己想要的方式留下紀錄。
- **規則提案**：先累積名聲／生涯榜，標示存活與死亡；已死成績保留，新角不能合併繼承。私人故事與敏感選擇不直接公開；無劇透的展示範圍另定。
- **好玩目標**：看得到自己是怎樣的傭兵，不只有總數。週榜仍在需求中，但須先處理有限案源、進度分組與新角重玩的機會差異；不以每日重刷填補。

### S16 永久死亡與新生涯

- **手機呈現**：完整的生涯結尾：最後事件、已知死因、曾做的事、唯讀紀錄與建立新角入口。
- **玩家決定**：明知重大風險仍執行時承擔生死結果；死亡後選擇新角的新準備方向。
- **規則**：DEAD是終態；救援發生在此前。死亡確認由伺服器保存，重連不回到選擇前，新角獨立進度。可加速已讀文本，但選擇與結算仍需完成。
- **好玩目標**：玩家能理解這段生涯如何結束。普通失敗先有多種後果，永久死亡不作固定週期的內容重置工具；也不靠暗中取消死亡降低風險。

### S17 紀錄、恢復與手機中斷

- **手機呈現**：重新開啟後顯示「上次完成什麼／現在停在哪／接下來可做什麼」，提供返回當前案件與短摘要。
- **玩家決定**：繼續閱讀、查看前情、回看線索；已確認選擇不可透過回顧改寫。
- **規則**：伺服器保存正式結果，手機只保存閱讀位置與偏好。斷線中的選擇顯示尚待確認，使用同一指令識別查回；無網路不排隊替玩家稍後送出致命選擇。
- **好玩目標**：短次登入也能安心停下，長時間後回來不需重讀全部內容。離線執行只跑安全段，不因手機收訊、睡眠或忘記開網頁而自動死亡。

## 3. 案件如何把系統串起來

範例提案：帶一名證人離開企業診所。

1. 中間人訊息交代目標與報酬；玩家另知道這名證人與先前救過的人有關。
2. 選擇查監控或問診所熟人；情報分別揭露監控盲點或轉診門路。
3. 檢查裝備與義體負荷，選突入、入侵或交涉；每種代價不同，不必每案都有三種。
4. 安全段自動執行；到路障時停下，顯示傷勢、通緝、壓力與保障。
5. 玩家選擇保住完整資料冒險，或付出資料／報酬代價撤離。若選高危險，伺服器一次判定結果與救援。
6. 生還、救出或死亡分別記錄。任務是否成功與角色是否生還分開；人物態度、名聲與城市情報貢獻按有效成果結算。
7. 下一份案子回收這次人物與資料後果；不能重接本案洗掉結果。

這份範例的NPC、解法與代價尚未定稿，用於驗證系統是否真有相互影響，非新增正式章節。

## 4. 首版應做多深

| 階段 | 需要完整的系統互動 | 暫不擴大 |
|---|---|---|
| 兩案風險切片 | 角色／委託／情報／選擇／自動段／基本配裝／壓力／警方／救援／死亡／恢復 | 三套起始配裝、兩名人物即可，不先寫滿所有高星遭遇 |
| 六案連線切片 | 前述持久化、聊天、名聲與區域、一個共享援助效果、基本生涯榜 | 不假裝六案已足以長期營運 |
| 24案小型封測 | 各路線資源與失敗後續、共同事件、成長曲線、週榜可行規則 | 不同時加入公會、PVP、拍賣、抽卡與大型地圖 |

規格先固定前兩案的具體資料，再寫程式；大部分系統可用少量內容驗證規則，不代表要先為每個系統製作獨立大型頁面。此深度安排是本輪建議，不直接改寫既有M0～M5里程碑。

## 5. 驗證與未定事項

最低充分證據：規劃層本輪不跑遊戲測試。後續L1驗證方案、負荷、傷勢與解鎖；L2驗證選擇重送、死亡終態、安全段離線、通訊與共同事件；真人走讀確認人物、取捨與下一案動機。手機視覺／操作依ui-system的G01～G10。

仍待試算／試玩的項目：案件耗時、戰鬥判定與是否採隨機、抗性係數、治療／保障費、名聲／跨區門檻、週榜分組、共享援助強度與死亡後聊天身份。不要把這些未定項目用假百分比或假條件顯示成正式遊戲數值。
